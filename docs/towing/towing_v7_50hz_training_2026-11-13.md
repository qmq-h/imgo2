# v7 速度残差 50 Hz 训练结果（2026-11-13）

> Run：`2026-11-12_23-12-28_v7_50hz_vx_oldppo_70col_20261112`
> 配置：v7/13 维（1 vx +12 关节）、50 Hz、老 PPO、70 列/1400 env、5–30 kg、
> `max_iterations=3000`、**fall 权重 −50、无 roll 惩罚**（该 run 启动早于这两项改动）。
> 已完成 3000 轮，最后 checkpoint `model_3000.pt`。

| `decoder_reconstruction` | 0.0280 | 0.0318 |

v7 在最终轮：

- tracking **+0.018**；
- fall **−0.31 个百分点**；
- timeout/回合长度略增；
- 但总 reward 低 0.36，动作更大幅、更频繁，横向拉力惩罚更差。

说明速度残差带来的是**小幅速度/存活改善**，不是数量级变化。

## 2. 训练曲线（v7）

| 轮次 | reward | tracking | fall |
|---:|---:|---:|---:|
| 1000 | 13.06 | 0.800 | 2.49% |
| 1500 | 13.43 | **0.894** | 3.91% |
| 2000 | 12.03 | 0.798 | 2.49% |
| 2500 | 13.36 | 0.842 | **2.99%** |
| 3000 | 13.20 | 0.851 | 3.18% |

- **1500** tracking 最高，但 fall 也最高；
- **2500** fall 最低，tracking 中等；
- **3000** 最均衡，建议作为主评测点；2500 作为安全对照。
- 训练 fall 是采样 rollout 的终止比例，不是评测 FALL；不能直接与测试台数字比。

## 3. 结论

- v7 速度残差**有效但幅度有限**：最终 tracking +0.018、fall −0.31pp。
- 这轮没有验证 fall −500 或 roll 惩罚；两项都在 run 启动后才加入，`params/env.yaml`
  仍是 `fall weight -50`，没有 `roll` 奖励。
- 要判断新 fall/roll 是否解决侧翻，必须用新代码从零重训；本 run 只能作为
  “v7 + 旧 fall + 无 roll” 基线。
- 重要：v7 的 offset 可能通过降速换取稳定；评测时需看 `upper_offset_vx` 的
  tow/coast 分布，不能只看 tracking。

## 4. 下一步

1. 用当前 v7 `model_3000` 跑一次有载/无载评测，和 v6 `model_3000` 同口径对比；
2. 再用新代码（fall −500 + roll −10）从零训练一版 v7，比较 15°/25–30 kg FALL；
3. 如果新惩罚导致 tracking 明显下降或停滞，优先下调 roll 权重/提高 deadband，
   而不是继续加大 fall。
