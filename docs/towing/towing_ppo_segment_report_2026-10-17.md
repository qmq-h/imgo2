> 「小车速度稳定性 / 启停冲击 / 重车不翻车」（见 [验收口径收束记录](towing_eval_criteria_2026-10-19.md)）；
> 下面第 5 节的「停车是否撞到机器人」只作诊断，**接触/间隙本身不是失败判据**，只看
> 关节/力矩冲击量；「停车后机器人是否往前走」也不再要求。

用户口径：「给 PPO 那个策略来一次 towing 的测试，用这个训练地形。统计平地的速度跟踪效果，
对于障碍场地，主要统计障碍段落的速度跟踪效果，下坡和上坡也分开。统计下坡机器人是否受到小车

交付两块：

1. **跑法**：测试台用 PPO 权重（`--policy ppo --policy-checkpoint`）+ 覆盖障碍段的时长；
2. **工具**：`imgo2_rl/scripts/tools/towing_segment_report.py`（纯标准库）把 run 读成
   「地形段 × 连接类型」的表。

本机（无 CUDA）**没有跑仿真**；下面 §4 是待训练机执行的命令与待确认项。

## 1. 工具算的六块

| 块 | 口径 |
|---|---|
| **1 平地速度跟踪** | 每个 case 先把所有 `平地*` 段（出生/带前/带后/出口）平均，再跨 case 取中位数 [p10,p90]；指标 = `\|vx_b − cmd\|`、跟速比 `vx_b/cmd`、带符号误差（正 = 超速）、关节跟踪误差 |
| **1b 平地 × 速度档** | 同上，按 `--velocities` 的档分开（0.5 / 1.0 / 1.5） |
| **2 障碍段速度跟踪** | 只取障碍段内的行：`5°坡 / 10°坡 / 减速带 / 波浪` × `上坡 / 坡顶 / 带顶 / 下坡`，绳与刚体各一列（`\|vx_b−cmd\|` / 跟速比）。**平地段的「带前/带后」不计入** |
| **2b 障碍段 × 速度** | 与旧 `stats.txt` 的「段 × 速度」矩阵同形：行 = 地形·段，列 = 每个速度档，绳/刚体各一张 |
| **3b 下坡 × 速度** | 下坡带符号速度误差按速度档分开（正 = 被小车推着超速），绳/刚体各一张 |
| **3 下坡：小车影响与步态** | 下坡段内：绳张力均值/ p90、**松弛占比**（`rope_taut ≤ 0.5` 的行比例，绳松 = 小车在下坡推着走）、带符号速度误差（正 = 被推得超速）、**步态周期**（FL 大腿角自相关，0.20–0.90 s 第一个峰）、**周期强度**（峰值自相关，越低越不像稳定步态）、**周期相对平地的变化** |
| **4 启动** | 关节 RMS / 峰值超阈 case 数（0.1 / 0.3 rad，测试台 JNT 口径）、关节峰值与 RMS 分位、力矩饱和占比、**起拖 0.2 s 窗口内的绳张力峰值 / 冲量峰值 / 速度偏差**、到 90% 指令用时 |
| **5 停车** | 是否发生接触（测试台三路见证）、滑行段最小几何间隙、到接触用时、车斗接触峰值力、**停车 0.2 s 内车斗力与机器人自身仍在动的速度**、停车关节峰值、小车滑行距离、机器人停稳用时 |
| **5 停车** | 另含 **coast 末已停住（n/N）** 与 **coast 末机器人速度**（§2.1 的校验） |
| **6 判定码分布** | 仅供参考（OK / LOW / LAT / SPD / COL / FALL / JNT / INV） |

所有表都是**两列：绳（compliant + inextensible） / 刚体（rigid）**；每格是「跨 case 中位数
[p10, p90]」，先按 case 在段内取平均再跨 case 取分位（不把同一 case 的几百行当几百个样本）。

输出：`<run>/segment_report.md` + `.json`（JSON 里带逐 case 的分段/事件明细，可按速度/质量再切）。

## 2. 测评方案：按地形拆开跑 + 按里程停车（训练侧不动）

用户口径（2026-10-17）：「每个地形分开跑，**平地需要的路程最短**、只要包含完整的启停就行；
障碍段只要包含障碍部分」，随后明确「**最后停止也按 10 m 给即可**，训练侧设置合理、不要动，
只改测评侧、平地不需要那么长」。

所以：**训练侧保持原样**（`STOP_DISTANCE_M = 10 m`、减速带仍在 5.625 m、timeout 24.232088 s /
485 步），测评侧用测试台新加的两个开关表达：

| 地形 | `--columns` | `--stop-progress` | `--tow-duration`（最慢 0.5 m/s + 余量） | 依据 |
|---|---|---|---|---|
| 平地 | `0-19` | **4.5 m** | **10 s** | 只要「起步 1 s + 稳态 + 停车」，不跑到 STOP |
| 5° 坡 | `20-29` | **10 m** | **21 s** | 与训练 STOP 对齐（越过 9.0 m 的坡出口） |
| 10° 坡 | `30-39` | **10 m** | **21 s** | 同上 |
| 减速带 | `40-49` | **10 m** | **21 s** | 同上（凸条在 5.475–5.775，之后是平地） |
| 波浪 | `50-59` | **10 m** | **21 s** | 同上 |

`--stop-progress` 的语义与训练侧一致：**逐 env 按自己的里程**置零指令（phase 记为 `coast`、
指令粘住），所以同一轮里 0.5–2.0 m/s 各档都在**同一个里程**停，不需要按速度分轮；
`--tow-duration` 只作为「最慢档走不到就该报错」的上限（校验 `tow × min(v) ≥ stop`）。

**过滤列之后「env i」不再等于「网格第 i 条 lane」**，所以有两处映射必须按 case 取，否则机器人会
站到别的 lane 上（坡度量级/连接/长度全错，训练机实跑会报 `case 的坡度量级与 env_spec 不一致`）：

- 逐 env 参数（连接长度/刚度/阻尼/初始距离/坡度/地形族掩码）用
  `case_specs(cases)` = `connection_grid.env_spec(case.cell_index)`；
- 出生原点用 `case_tile_origins(terrain_origins, cases)` = 该 case 的 `(row, column)` 地砖原点，
  **覆盖** Isaac Lab 默认按 env 序号的 `scene.env_origins`：地形是整张网格、每块地砖位置固定，
  所以只需把机器人放到正确的那块上。

不带 `--columns` 时这两者与原来的 `i//COLUMNS, i%COLUMNS` 逐位一致（有回归测试）。

出生点到障碍的距离（**不改**，仅记录）：5°/10°/波浪 **2.25 m**（0.5 m/s 4.5 s）；减速带 **5.475 m**
（0.5 m/s 11 s，因为凸条放在剖面窗口中心 5.625 m）。用户 2026-10-17 明确**不前移凸条**。

### 2.1 「完整的 cmd=0 直到真正停住」

`cmd = 0` 之后要一直记到**机器人真的停住**，不能按时长硬切：

- `--coast-duration 5`：归档实测机器人从归零到 `|vx| < 0.05 m/s` 的 `stop.settle_time_s`
  中位 ~0.5 s（2.0 m/s 也不超过 ~1.5 s），小车滑到静止约 0.7 s ⇒ 5 s 有 ~3 s 余量；
- 报表**自带校验**（不靠人眼）：读每个 case `coast` 段最后一行，`|robot_vx| ≤ 0.05 m/s`
  （`REST_SPEED_MPS`）记「已停住」，否则在报表开头打「⚠ n/N 个 case 在 coast 结束时仍在动 ⇒
  把 `--coast-duration` 加大」；全停住时打「✅ 停车段走完」；
- 第 5 节有两列：**coast 末已停住（n/N）** 与 **coast 末机器人速度**。

高速档的注意点：步态周期至少需要 40 行（1 s @ 40 Hz）才估，2.0 m/s 时波浪的单向段
（1.125 m）只有约 22 行、减速带斜坡（0.1 m）只有 2–3 行 ⇒ 这些格里步态周期显示「—」，
不是估算失败而是样本不足。速度跟踪/张力/冲击不受影响。

## 3. 跑法（训练机）

```bash
cd /root/Desktop/imgo2
P=logs/rsl_rl/base_move_rough/2026-10-16_21-26-48/exported/policy.pt   # 先按 §5 导出

# 五轮：每个地形一轮，四档速度都在同一轮里（按里程停车 ⇒ 不需要按速度分轮）
run() {  # $1=名字 $2=列 $3=停车里程 $4=tow 上限
  bash imgo2_rl/scripts/run_isaaclab.sh imgo2_rl/scripts/towing/play_towing_test.py \
    --policy ppo --policy-checkpoint "$P" \
    --columns "$2" --stop-progress "$3" --tow-duration "$4" \
    --num-envs 100 --velocities 0.5 1.0 1.5 2.0 \
    --coast-duration 5 --write-csv all --headless --compact-log --run-name "ppo_$1"
}
run flat 0-19  4.5 10
run g5   20-29 10  21
run g10  30-39 10  21
run bump 40-49 10  21
run wave 50-59 10  21

# 出报表（五个 run 一起给）
python3 imgo2_rl/scripts/tools/towing_segment_report.py \
  imgo2_rl/logs/towing/play_test/<ppo_flat> \
  imgo2_rl/logs/towing/play_test/<ppo_g5> \
  imgo2_rl/logs/towing/play_test/<ppo_g10> \
  imgo2_rl/logs/towing/play_test/<ppo_bump> \
  imgo2_rl/logs/towing/play_test/<ppo_wave> --out /tmp/ppo_segment
```

说明：

- `--num-envs 100` = 10 列 × 10 行（每轮每族 100 条 lane，绳 48 / 刚体 32；平地轮是 20 列，可用 200）。
  五轮合计约 **35 min** 仿真、CSV ~0.3 GB（平地轮最短 16 s 回合，其余 27 s）。
- 想统计更稳就每轮 200（20 行）：约 70 min、0.6 GB。
- 停车段靠 `--coast-duration 5` 走完，报表的「coast 末已停住」会告诉你是否真的停住。
- 对照组：`--policy amp` 同参数再跑五轮，报表里两侧各出一份。
