> 同日入口精简：旧ppo_check、imu_reader、go_probe已删除；本程序继续保留。当前构建开关和测试建议见 [精简记录](go_imu_entry_cleanup_2026-10-15.md)。本文32项测试及独立ppo_check数值为精简前的历史结果。

## 用途与实现

`imgo2_deploy/real/fsm_check.cpp`是新增的独立测试入口，main直接包含配置加载、模拟反馈、键盘事件、FSM更新、推理提交、面板刷新与退出流程。它链接现有SDK，不复制状态实现。

复用正式部署的`DeploymentConfig`、`PolicyConfig`、`RobotFSM`及`fsm/states`状态、`DeploymentInput`、`RobotAdapter`、`PolicyRunner`、`InferenceWorker`、`Safety::clamp`和`TerminalDisplay`。不创建RealHardware实例，不打开电机或IMU，也不发送串口报文。

唯一替代的是反馈来源：

- 初始反馈：MotorConfig中四条总线的`start_pose_rad`，与正式主程序归零姿态一致。
- 站起、趴下、保持：模拟关节理想跟随上一控制周期的目标q/dq，便于观察8秒五次轨迹以及趴下后的到位卸力。
- PPO：每个周期固定以`deployment.yaml`中的`stand_pose`作为关节反馈，dq为零；IMU RPY为0/0/0、四元数wxyz为1/0/0/0、gyro为零。策略输出不回灌为反馈。若stand_pose不同于策略default_dof_pos，观测中的关节偏差仍按正式SDK计算。
- 不创建动力学、接触或真实执行器模型；不能据此证明真机稳定。

测试入口仅在自身内存中将`mapping_confirmed`设为true，以允许模拟PPO切换；保留配置中的实际排列，仍走RobotAdapter。源YAML、关节宏、策略和真机入口不改，正式程序的映射锁继续有效。

## 工程内构建与运行

从仓库根目录运行；本机LibTorch位于下述已存在目录，无需额外安装测试专用库：

```bash
cmake -S imgo2_deploy/real -B imgo2_deploy/real/build_layout \
  -DCMAKE_BUILD_TYPE=Release -DGO_IMU_BUILD_RL=ON \
  -DCMAKE_PREFIX_PATH="$PWD/imgo2_deploy/ros2_ws/library/inference_runtime/libtorch"
cmake --build imgo2_deploy/real/build_layout -j2
./imgo2_deploy/real/build_layout/fsm_check \
  --policy-dir ./imgo2_deploy/real/policy \
  --config ./imgo2_deploy/real/config/deployment.yaml
```

直接运行`build/fsm_check`也会读取可执行文件旁复制的policy/config。显式指定源路径可确保使用刚修改的YAML。保留`--duration 秒数`供定时退出测试，默认0即持续运行；`--help`显示参数。CMake随其他RL入口构建、复制资源和安装本程序。

## 操作与显示

| 输入 | 行为 |
|---|---|
| `0`后回车 | 初始保持/卸力后8秒站起；PPO返回Stand用2秒，结束为StandHold |
| `1`后回车 | StandHold达到配置稳定时间后进入PPO；过早输入需等稳定后重新输入 |
| `2`后回车 | 显示AMP未开放，当前状态不变 |
| `9`后回车 | StandHold/PPO进入Passive趴下；8秒轨迹、连续到位确认后卸力 |
| WASDQE | PPO内即时更新速度指令，不需回车 |
| 空格 | PPO速度指令归零 |
| 其他整行/当前状态不接受的数字 | 沿用正式FSM，忽略，不自动排队 |
| Ctrl+C / 输入流关闭（EOF） | 回收推理线程并恢复终端；无硬件退出动作 |

输入`0`但未回车时不切换；输入数字时终端不回显，回车后第一行直接更新当前状态。首次站起或PPO回站完成后，默认均需连续稳定0.5秒再输入1。提前输入会提示尚未就绪、不排队；默认PPO回站总等待至少约2.5秒。

面板固定位置刷新约10Hz，显示刷新频率不代表推理频率。第一行当前状态，随后四腿目标，最后为速度、推理序号、PD、限幅和最新提示：

```text
State: PPO | OFFLINE
Target(rad)       Hip         Thigh         Shank
FL            0.000000     0.870000    -1.820000
FR            0.000000     0.870000    -1.820000
BL            0.000000     0.870000    -1.820000
BR            0.000000     0.870000    -1.820000
cmd: 0.00 0.00 0.00 | seq=1 | PD=60.00/2.00
Limit: OK | 进入PPO，等待有效推理结果
0/1/2/9 + Enter | WASDQE / Space | Ctrl+C exits
```

上面角度仅示意版式，不是策略实测输出。每行顺序髋/大腿/小腿，单位rad，硬件展开顺序FL/FR/BL/BR。PPO目标已包含action_scale、default_dof_pos、映射、状态交接及Motor限幅；最初0.5秒还包含正式交接的插值，稳定后显示策略最终设定值。PD显示第一关节的值，其余角度仍各自独立计算。

Passive运动时显示`Passive / Crouching`，实际到位后显示`Passive / Unloaded`，PD为0/0。0可从模拟趴下反馈重新站起。Fault在首行显示，底部显示原因；锁定行为沿用正式FSM。

终端采用已有备用屏幕、隐藏光标和原地刷新；正常退出/异常/Ctrl+C恢复。终端至少53列、10行，过小时显示缩小提示，避免换行滚屏。重定向输出按已有显示接口输出纯文本快照，不包含终端控制码。

PPO反馈固定为stand_pose，所以PPO→Stand的轨迹起点已经等于站姿，显示角度可能立即回到站姿并保持；仍执行完整2秒Stand计时与0.5秒稳定门槛，PD按当前值平滑恢复60/2。真实程序从实际测量角出发，不能用离线目标的跳变推断真实运动。

## 错误与待确认

模型/config路径错误或非法参数在启动时报告`FSM check error`；姿态越界、轨迹超速同样在FSM初始化/切换阶段拒绝。推理失败、结果过期等进入Fault并显示原因，需退出再启动。AMP不会加载模型，也不会绕过状态限制。

新增回归覆盖真实8秒站起/趴下、回车门控、无效输入、PPO/即时速度、AMP占位、卸力后再次站起、窄屏、固定刷新、Ctrl+C/EOF恢复、重定向及无文件日志。验证结果见下方记录。

待确认：真实关节映射、实际反馈/推理频率、倾斜IMU、到位阈值、站起/趴下机械裕量和卸力效果仍按README的DEPLOY-13跟踪；必须使用真实硬件才能完成。本程序不提供这些结论，也不修改正式PPO锁。
