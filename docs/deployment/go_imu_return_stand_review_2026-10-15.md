# PPO重复切换与回站检查（2026-10-15）

## 现象、原因与用户确认

现象：0→1→0→1的最后一次1看起来没有生效。原逻辑从PPO回Stand仍使用stand_s=8秒，进入StandHold后还需反馈连续稳定0.5秒；轨迹期间的1被忽略，未排队。用户随后确认是未等够8秒。本轮不将该现象归因为状态对象不能重复使用。

用户明确选择：首次/Passive卸力后站起仍8秒，仅PPO回站2秒；提前输入1时提示未就绪，就绪后重新输入，不排队。

## 当前调用流程

两个入口`rl_real_imgo2.cpp`和`fsm_check.cpp`都按同一链路调用：

```text
键盘字节 → DeploymentInput（状态数字需回车）
        → RobotFSM::request（检查当前状态与就绪条件）
反馈快照 / 最新推理结果 → RobotFSM::update
        → 当前State::run → 目标q/dq/kp/kd/tau
真机：RealHardware::sendCommand → Motor安全检查 → 四总线
离线：Safety::clamp → 固定位置显示；无串口
PPO激活时：RobotAdapter::toPolicy → InferenceWorker → PolicyRunner
         → next update按generation检查 → PPOState目标交接
```

0从InitialHold/Passive进入Stand，使用stand_s（8秒）；0从PPO进入Stand，使用新增return_stand_s（2秒）。进入前用实际反馈到stand_pose验证同一时长的轨迹端点、增益和峰值速度；通过后将已验证时长交给唯一StandState，不另造回站状态。

Stand入口保存当时测量角和上一份控制增益。角度沿五次曲线、dq沿曲线导数回stand_pose；增益同时在blend_s（0.5秒）沿五次进度从上一份值变至fixed_kp/fixed_kd（当前60/2）。例如PPO25/0.5返回时，0秒为25/0.5，0.25秒为42.5/1.25，0.5秒达60/2，2秒到站姿；没有先等PD完成再启动位置轨迹。

2秒轨迹结束进入StandHold，实际角度/速度连续满足配置容差0.5秒，才接受重新输入的1。因此理想反馈下，PPO回站后至少约2.5秒才可重进PPO；真实跟随未稳定时会更长。过早1显示“尚未就绪”，不会自动切换，用户需重新输入1＋回车。

离线PPO的反馈仍按先前要求固定stand_pose，而非将策略目标回灌。故离线0回Stand时测量起点已经是stand_pose，显示目标可能立即回站姿；2秒计时与PD过渡仍执行。真实程序从真实测量角规划，行为不可用固定反馈面板直接代替。

## 修改与其他检查

- 配置新增return_stand_s，默认2秒；启动前拒绝零、负数、NaN/Inf。站起时长8秒、趴下8秒、姿态、关节宏和限位不改。
- RobotFSM选择并校验实际时长，StandState使用该时长；仍是同一个状态实例重复enter/run，不增加State文件或第二份实现。
- Stand期间收到1新增明确未就绪提示；StandHold稳定不足的提示也说明需要重新输入。
- 重复进入Stand会重置轨迹起点/计时/阶段；PPO重新进入清空首结果和交接计时，worker按新generation重置last_action。旧代次结果不会覆盖新状态；速度指令切换时清零。
- Fault锁定保持，0不能绕过故障；AMP未注册；无真实设备运行。

## 同日补充：Stand实测起点与PPO切入突变复审

用户强调每次Stand必须从当前电机角度出发，并询问切入PPO的常见处理。本轮只核对、补文档，未改控制代码、姿态、增益、策略或blend_s。

源码确认：beginMotion每次执行start.q=measured(h)，将该反馈存入context.measured；StandState::enter再锁存为该段start_。后续8秒/2秒轨迹保持这一固定起点，不每周期重新取角度改写起点。这里“当前”是入口拿到的最新有效反馈快照，并非12关节同时采样；不用上一条PPO目标，也不重新按offset归零。现有robot_fsm回归人为让反馈角与最后策略目标相差0.03rad，断言首个Stand目标恰等于反馈。

PPO切入则是另一条交接：PPOState::enter保留previous目标，在首个有效新代次结果到达后，按blend_s=0.5秒五次进度执行q_cmd=(1-alpha)*q_previous+alpha*q_policy(t)，KP/KD同样由60/2过渡至25/0.5；q_policy=default_pose+action_scale*action。交接起点为上一份控制目标，用于保持目标连续；真实PPO观测仍来自实际反馈，不能为了平滑把真实反馈替换成设定值。离线fsm_check按原要求使用固定反馈，不能据此推断机械动作。

现有限制：策略每20ms更新，交接终点也是随推理更新的q_policy(t)，所以0.5秒交接并不保证之后每个策略周期目标都满足某个速度/加速度硬上限。Motor对dq字段的幅值限制也不能替代对目标q相邻周期差分的限制。当前0.35rad小腿偏移若近似为固定终点，在0.5秒五次插值下峰值参考角速度约1.31rad/s（75°/s）；这是单一固定终点的数学估算，不是实测或在线上限。最终目标与固定站姿相差20°，即使连续也可能看到显著运动。真实腿突动还需关联实际q/dq、目标q、KP/KD、时间戳判断，本轮未归因于某一个未经测量的故障。

公开实现对照（2026-10-15读取主仓源码）：[Unitree RL Gym deploy_real.py](https://github.com/unitreerobotics/unitree_rl_gym/blob/main/deploy/deploy_real/deploy_real.py)先读取当前关节角并用2秒线性运动到默认姿态，保持等待后进入策略；run直接发送default_angles+action*action_scale，并不包含通用PPO入口交接器。因此不能声称“强化学习算法自动消除状态切换突变”或“公开部署全都采用相同滤波”。[legged_gym训练源码](https://github.com/leggedrobotics/legged_gym/blob/master/legged_gym/envs/base/legged_robot.py)包含动作相邻差平方惩罚；它是训练目标的一部分，不能取代部署FSM交接的保证。

建议（未实施）：先确认用户观察的是离线面板数字还是实机动作，并量化切换前后相邻控制周期的目标差；保留稳定站姿、零速度指令、训练一致的策略重置和短时间目标/增益交接。若现有0.5秒过快，可单独设计PPO入口更长的交接参数，并在需要时增加目标变化率保护；持续滤波、限速会改变策略实际控制动态，需要在仿真和真实闭环验证，不能随意减action_scale、改default_pose或给策略输出减去偏置来强行对齐站姿。具体时长/限速尚未确定，不擅自修改。

本轮检查：robot_fsm与inference_worker **2/2通过（0.29秒）**，复用了实测起点、交接初值/增益、反复切换及在途结果隔离测试；未重跑全量，前节30/30为上一轮验证。已确认/完成：Stand实测起点、PPO现有交接实现与公开源码对照。待确认：突变发生在显示还是硬件、实际每周期目标/反馈变化与力矩情况，及是否需要调整交接；需要用户说明观察对象和相应运行证据，仍属于DEPLOY-13。本轮无硬件运行。

用户已明确，所述突变是fsm_check目标数字变化，尚无实机突然运动的报告。先前“需要区分显示/硬件”的信息已补齐；不能继续把它描述为实机故障。

源码显示面板100ms刷新一次，PPO入口blend_s=0.5秒，主循环5ms、推理20ms。一次交接在面板上只呈现约5个刷新间隔，而策略目标和PD在控制循环中仍继续计算；看到相邻显示数字较大变化，不等同于单个5ms控制周期的目标跳变。

此前保存的同一PPO交接PTY输出中，BL小腿连续显示为：-1.820000 → -1.806441 → -1.723895 → -1.587384 → -1.491512 → -1.470067rad。该序列来自前轮已运行的离线记录，本轮仅重新读取核对，不作为新硬件/新全量测试；与当前未修改的PPOState交接逻辑一致。它说明屏幕上存在过渡帧，不能证明每个控制周期的变化率都小，也不能代表真实腿角度。
