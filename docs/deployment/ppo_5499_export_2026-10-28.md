# PPO model_5499 导出与「USD 文件找不到」修复（2026-10-28）

## 现象

从 `imgo2_rl` 执行正式导出命令，建场景阶段直接崩掉，`exported/` 不生成：

```text
File ".../isaaclab/managers/command_manager.py", line 61, in __init__
    self.set_debug_vis(self.cfg.debug_vis)
File ".../isaaclab/envs/mdp/commands/velocity_command.py", line 172, in _set_debug_vis_impl
    self.goal_vel_visualizer = VisualizationMarkers(self.cfg.goal_vel_visualizer_cfg)
File ".../isaaclab/markers/visualization_markers.py", line 351, in _add_markers_prototypes
    marker_prim = cfg.func(prim_path=marker_prim_path, cfg=cfg)
File ".../isaaclab/sim/spawners/from_files/from_files.py", line 307, in _spawn_from_usd_file
    raise FileNotFoundError(f"USD file not found at path at: '{usd_path}'.")
FileNotFoundError: USD file not found at path at:
'https://omniverse-content-production.s3-us-west-2.amazonaws.com/Assets/Isaac/5.1/Isaac/Props/UIElements/arrow_x.usd'
```

同一天 14:33、14:41、15:06 三次尝试同样失败（只留下 `outputs/`，没有 `exported/`）。

## 根因（已由 traceback 确认）

**不是模型、不是 URDF、不是 checkpoint**。真正的原因是
`LocomotionVelocityRoughEnvCfg` 里 `commands.base_velocity.debug_vis = True`
（[velocity_env_cfg.py:108](../../imgo2_rl/source/imgo2_rl/imgo2_rl/tasks/manager_based/locomotion/velocity/velocity_env_cfg.py#L108)）。
`CommandManager.__init__` 在**建场景时**就按它调用 `set_debug_vis(True)`，于是
`UniformVelocityCommand._set_debug_vis_impl` 创建速度指令可视化箭头，而两个 marker 原型
（`goal_vel_visualizer_cfg` / `current_vel_visualizer_cfg`）的 `usd_path` 是**远端** S3 资产
`arrow_x.usd`。`_spawn_from_usd_file` 先用 `check_usd_path_with_timeout` 做 `omni.client.stat`，
判定不可用就抛上面那条 `FileNotFoundError`，建场景中断。

要点：

- 这一步发生在 `runner.load()` 之前 ⇒ 连 RSL-RL5 兼容副本和 `exported/` 都不会出现，看起来像
  「导出不了」，实际 checkpoint 还没被读。
- 箭头在 `--headless` 下**没有视口可显示**，纯属白跑一次远端请求。
- 这不是「固定的网络故障」而是**可达性不稳定**：同一台机器 15:20 有一次恰好 stat 成功并通过
  （日志里有两条 `/Visuals/Command/velocity_goal|velocity_current` 的 fabric 警告，说明 marker
  确实被创建了），15:31 再跑就失败。所以「多试几次」有时会侥幸通过，不可依赖。

## 修法

新增 [play_utils.py](../../imgo2_rl/scripts/rl_lab/play_utils.py)：

- `disable_command_debug_visualizers(env_cfg)`：遍历 `env_cfg.commands.*` 里带 `debug_vis`
  的项，置 `False` 并返回被关闭的项名；`commands` 为 `None`/缺失、项没有该属性时安全跳过。
- 只在**没有视口**的场景调用，GUI 回放行为不变：
  - [ppo/play.py](../../imgo2_rl/scripts/rl_lab/ppo/play.py)：`--headless` 或 `--export_only` 时调用；
  - [amp/play.py](../../imgo2_rl/scripts/rl_lab/amp/play.py)、
    [himloco/play.py](../../imgo2_rl/scripts/rl_lab/himloco/play.py)：`--headless` 时调用。
- 每次会打印一行 `[INFO] Disabled command debug visualizers: ['base_velocity']`，便于确认生效。

为什么可以关而不影响导出：`VisualizationMarkers` 只写 `/Visuals/Command/*` 的显示 prim，
不改动力学、不进观测、不进 reward，除了可视化本身没有别的消费者。

```bash
export PYTHONPATH="$PWD/source/imgo2_rl:$PWD/scripts/rl_lab${PYTHONPATH:+:$PYTHONPATH}"

  --task=Imgo2-basemove-rough-ppo \
  --checkpoint="$PWD/logs/2026-10-28_00-34-30/model_5499.pt" \
  --num_envs=1 --device=cuda:0 --headless --export_only
```

前两条 `export` 不能省：`run_isaaclab.sh` 不读已激活的 conda 环境（缺 `IMGO2_ISAACLAB_PYTHON`
会去找本机不存在的 `/opt/conda/envs/isaaclab/bin/python`），缺 `PYTHONPATH` 会 `import cli_args`
失败。`--task` 用训练 ID（不带 `-play`）是对的，PPO 没有注册 `-play` 变体。

## 限制与待确认

- **`amp/play.py`、`himloco/play.py` 的同一行改动没有实跑**：只做了 `py_compile` 与 helper 单测。
  两者只在 `--headless` 下生效，GUI 路径未动；它们的 `commands` 继承自同一份
  `LocomotionVelocityRoughEnvCfg`，所以同样受益，但「实跑通过」仍待补。
- 网络侧：本条 URL 现在又能取（`curl` 返回 HTTP 200），所以本轮成功**不能单独证明**「断网也能过」；
  依据是源码路径（`debug_vis=False` ⇒ 不创建 `VisualizationMarkers` ⇒ 不调用 `spawn_from_usd`）
  加上 marker 警告消失这两条。
- 未做：部署 LibTorch 加载探针（8400 那次做过，方法见 [8400 记录](ppo_8400_export_2026-10-27.md)）、
  替换部署策略、5499 的 MuJoCo/Gazebo 步态评测。

## 手动备选（不想改代码或在其它机器上）

- 任意 headless 入口都能用 Hydra 覆盖达到同样效果：
  `env.commands.base_velocity.debug_vis=false`（修复前未单独实跑过；修复后已由代码自动完成）。
- 只想让远端可达而不改配置：先清代理再跑
  `unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY ALL_PROXY all_proxy`
  （Isaac Sim 读这些变量，代理不通时 `omni.client.stat` 直接失败）。
- 若报错路径变成 `/tmp/IsaacLab/usd_.../imgo2_real.usd`（本地转换），那是另一类问题，用
  `scripts/tools/convert_urdf.py` 单独转一次才能看到真正的导入错误。
