# PPO髋角、MPC落脚点与公开工程奖励/速度课程对照

核对日期：2026-10-27。范围：本机当前PPO rough源码、三套公开RL配置及MIT Cheetah MPC。这里只复审和提出建议，未修改生产配置、模型、策略或启动训练。已完成的是源码对照和对前一候选方案适用范围的澄清；步态问题仍待PPO-ROUGH-01/PPO-GAIT-01验证。

## 1. 0是参考角，不应把髋锁在0

Imgo2四髋默认角均为0，模型四髋均绕+X轴转动；默认姿态的FK和六处参考一致性已在[站姿核对](ppo_stand_entry_plan_2026-10-27.md)保存。该事实支持保留当前名义站姿，不证明运动时四髋必须为0。

- 静站也需要小幅平衡和负载补偿，实际角、PD目标角和策略原始动作不是同一个量。
- 横移、转弯、抗推和不平地面通常需要髋内收/外展和落脚点调整。硬置零或强力拉零会损失这些自由度。
- 独立髋奖励只是把髋的正则化从大腿/小腿中拆开；四条腿仍受同一策略、机身动力学和跟速/平衡奖励耦合，并不变成四个互不协调的控制器。
- 保留软姿态偏好即可。运动时应比零指令弱；先用较弱的实际髋角偏差项作对照，再根据横移/转向的正常角度分布决定是否需要超范围项。

前一份[软约束设计](hip_angle_constraint_design_2026-10-27.md)的静止5°/运动10°是尚未闭环验证的惩罚转折点。**本次明确不把运动10°作为所有方向和地形的固定要求**。若正常横移需要更大角度，应放宽或取消该加强区间；不能以牺牲跟速/平衡来获得四髋接近0的外观。原候选张量计算仍成立，不等于其参数适合机器人。

## 2. “内八”的含义与MPC

本模型的髋轴不是yaw轴。“髋内收、后脚横向站距变窄”和“脚尖绕竖直轴朝内”须分开。球形足的视觉朝向也不能直接代表落脚/接触质量。

MIT公开MPC的`ConvexMPCLocomotion.cpp`不是把髋角固定为0：

- 从机身髋位置和左右侧横向偏置建立名义落脚点。
- 随前进速度加入前后腿不同的横向交错项。
- 随期望yaw率旋转落脚参考。
- 叠加期望横向速度、摆动剩余时间、实际速度误差和转向相关补偿。
- MPC根据接触计划求地面反力，摆动足使用轨迹；不能把该过程理解为“让四髋全部内收”。

从力学上，落脚点改变地面力对质心的力臂，影响机身roll/pitch/yaw力矩；内收或外展在不同速度/接触相位下都可能合理。脚是否在髋正下方还依赖机械侧向偏置、机身高度及关节弯曲，不能只按角度判断能耗和稳定性。以上是依据模型和控制源码作出的解释，不是本机MPC实测。

当前坏姿态有更具体的证据：最新策略在MuJoCo前进.5m/s时后站宽约.182m，原策略约.337m，两后髋动作持续100%裁剪；同次静站/运动及分布退化见[实测](../deployment/mujoco_policy_comparison_2026-10-27.md)与[奖励审计](ppo_hip_saturation_reward_audit_2026-10-27.md)。这不等价于正常MPC的适度落脚调整，也不能证明是完整任务的最优解。

原`joint_mirror`的对角同号规则允许“前外后内”，但零髋也同样零代价；反例只能证明它不是外展对称约束，不能单独解释饱和的全部因果。建议先将髋从该角度同步项拆出，并用独立软偏差项；不要修改轴符号或简单把所有关节差值改成相加。

## 3. 当前工作树与8400历史配置有区别

本次读到用户尚未提交的rough配置变动，保持原样：

| 项目 | 此前8400审计快照 | 本次工作树 |
|---|---:|---:|
| feet_air_time | 1.0 | 1.2，threshold仍.5s |
| feet_height_body | -5.0 | -6.0，target仍-.20m |
| joint_pos_penalty | -.1 | -.5 |
| feet_height | 权重0，target .08m | 权重仍0，target .10m，仍不生效 |
| vx范围 | ±1.0m/s | ±1.2m/s |
| vy范围 | ±.8m/s | ±.8m/s |
| yaw范围 | ±1.5rad/s | ±1.0rad/s |

`joint_pos_penalty`仍选全部12关节，函数是L2范数而非平方和；低命令且实际速度不超过.5m/s时再乘5。权重改为-.5后，静止分支等效系数为-2.5，运动分支-.5（均还要乘dt和直立门控）。它会同时惩罚大腿、小腿，不能把此加权理解为只加强髋约束。

本次机器记录保存上述事实与源码SHA256：[对照元数据](ppo_hip_mpc_public_comparison_2026-10-27.json)。历史报告保留当时读数，不把用户后改的数值套回model_8400。

选择明确的示例配置，不概括为每个项目所有任务。数值为乘公共控制dt之前的weight；本机、Isaac Go2及HIM A1的控制步长均为.02s。0或“无”表示所查配方没有该项的非零贡献，不代表框架绝无相应函数。

| yaw跟踪 | .6 | .5 | .75 | .5 |

| 机身高度平方 | -10，目标.30m | 0 | 无 | -1，目标.30m |
| 滞空时间落地项 | 1.2，阈值.5s | 1，阈值.5s | .01，阈值.5s | 0 |

| 独立四髋回正 | 0 | 无 | 无 | 无 |

宇树Go2配置继承基础配置，因此必须两份一起读；基础`base_height_target`虽有数值，weight=0时不产生高度奖励。Isaac Go2也覆盖公共滞空权重为.01，不能把父类.125误写成Go2最终值。

如何解读：

1. 跟速、抑制机身垂直运动、角速度和一阶平滑属于相近配方，本机并非所有权重都异常。
2. 本机扭矩系数是两个Go2示例的1/80，关节加速度系数是它们及HIM的1/50；可能弱化对高频动作的代价，但不同执行器/动作尺度下不能仅凭该比例定因果。
3. 本机水平姿态相对HIM为25倍、高度为10倍；roll/pitch在坡地可能需要倾斜，不能机械继续加重“水平”项。
4. 足高项差异尤其值得查公式。本机是`sum((z_body+.2)^2*tanh(2*v_rel_xy))`，HIM是`sum((z_body+.2)^2*v_rel_xy)`。同样直立、有运动命令且相对足速.5m/s时，两者单脚误差平方前系数分别为`6*tanh(1)=4.5696`与`.01*.5=.005`，相差约914倍；这是同一假设输入下的算例，不是整回合奖励实测比例。足link原点、模型和门控仍不同。
5. 两者足高公式都未通过触地状态严格隔开摆动/支撑。支撑脚相对机身也有速度；本机强足高项可能与支撑、机身高度竞争。加大-6不等于只奖励摆动脚抬高。`feet_slide`另有减去机身速度的语义问题，见既有审计。
6. 滞空阈值.5s不是步态周期.5s，更不是直接设置2Hz。落地时短于阈值会负贡献，足高/滞空均不能保证某个周期。需要分别记录每足触地周期、滞空和摆动净空。
7. 总回报口径也不同：宇树示例开启only_positive_rewards，本机没有同样的总和零截断；HIM A1将其关闭。动作裁剪/动作缩放、状态噪声和是否用真实平方和也须一起比，不能直接复制weight。

## 5. 有没有先低速后高速

| 配方 | 实际速度训练机制 |
|---|---|
| 宇树RL Gym Go2 | 基础commands.curriculum=False，Go2未覆盖；在固定范围随机采样，不是先低速训完再训高速。其名字有rough，但基础terrain.mesh_type=plane，terrain课程flag不能当实际复杂地形证据。 |
| Isaac Lab v2.3.2 Go2 rough | 继承速度范围xy±1m/s、yaw±1rad/s；课程只有terrain_levels，没有速度课程项。 |
| HIMLoco A1 rough | commands.curriculum=True，x初始±1m/s，max_curriculum=2；两组平均跟速均超过对应理论上限80%后，每次向两端扩.2m/s。约80%环境x始终采样±1，约20%使用扩展范围；高速组\|vx\|≥1时清零vy。是同一训练中低/高混合加课程，不是两份独立policy按轮次切换。 |
| 本机PPO rough | 地形课程开，两项速度课程被设None；当前从vx±1.2、vy±.8、yaw±1范围采样，显式零指令比例.02。平面模长≤.2m/s的指令被清零，非零超低速没有连续覆盖。 |

“命令范围在扩展”和“每个机器人从0平滑加速”是两件事；这些随机命令配方一般不是按时间给每台机器人平滑加速。HIM的低/高分组也不是“专家权重比例”。

针对本机建议（尚未实施）：先用小平地和足够的零指令/前后/横移/yaw低速样本形成可验收基线，再逐步扩速度，同时保留静止低速采样。可在同一训练内做速度课程，不必先训练一个完全不能动的站姿policy。若使用现有速度课程，先对齐其初始范围与.2m/s死区，否则课程可能把希望训练的低速变成零指令。逐阶段保留相同观测/模型/动作接口；flat/rough完整续训的Critic维数限制仍按既有记录处理。

## 6. 下一步与验收范围

优先顺序为修正奖励语义/分布退化、拆分髋项、改善静站和低速覆盖，再进行受控短训消融，而非同时加大全关节/足高/滞空三个权重。运动髋正则先弱，暂不规定未测过的统一10°上限。若后续加站宽或跨腿惩罚，应在机身坐标中按方向、相位与模型允许范围定义，不能奖励越宽越好。

验收需包括零指令、前后、左右横移、左右原地转向、行走转弯和减速；看实际髋角/目标角/原始动作裁剪率、足端落脚宽度、跟速、机身高度、roll/pitch/gyro及足滑。零命令与运动分开统计，不能只看四髋是否贴0或总回报上升。修正探索后仍需监控每个动作通道的均值/std，髋姿态奖励不能直接约束原始mu无限增大。

**待确认**：上述建议尚无Isaac短训和横移/转向闭环A/B；没有证明某个髋权重/转折角最优；旧policy_now原训练配方仍未知。本次未改变用户工作树里的-.5/1.2/-6等值。
