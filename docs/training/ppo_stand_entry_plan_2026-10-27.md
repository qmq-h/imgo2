# PPO站立接管与低速训练方案（2026-10-27，建议尚未实施）

## 结论

用户当前优先目标是站起后零指令切入PPO时，腿部不发生明显突然换姿态，再逐步获得稳定低速运动。需要同时改善**训练的零指令姿态、策略分布边界和部署入口交接**；仅改一个奖励weight不够。当前证据不支持先修改髋默认角或关节轴。

本轮仅做源码/配置核对、标准库URDF FK和CPU静态JIT输入测试；没有修改训练/部署代码、模型、policy或PD，没有训练、动力学切换运行或硬件运行。以下数值均为可对照的首版建议，不是已验证的最佳配方。

## 1. 当前默认髋角有问题吗

六处独立来源一致：当前训练资产、8400保存的init_state、仿真base.yaml、仿真PPO配置、独立真机PPO配置、真机stand_pose，均为每腿：

```text
hip=0.00，thigh=0.87，shank=-1.82 rad
```

默认位姿标准库FK：四足碰撞球最低点刚接触水平地面时，base原点高约**0.30452m**，前后足球左右间距均为**0.3376m**；与目标高度0.30m相容。这只是刚性几何，不证明动态稳定或真机编码器标定正确。但原策略同模型静站约0.303m、髋角接近零的闭环结果也支持该默认姿态具有可用依据，见 [两策略对照](../deployment/mujoco_policy_comparison_2026-10-27.md)。

当前reference不是“必须保持的角度指令”。PPO执行`q_des=q_default+scale*action`，仍可在零指令下主动改变站姿。最新策略在名义站姿/零指令/零last_action的固定45维输入下，两个后髋第一拍目标就相对默认偏移**-0.375/+0.375rad（约±21.49°）**。这是静态输入推理，不是完整切换回放；它说明即便参考完全一致，也可能出现很大的策略接管目标差。

不要把后髋reference改成饱和角来贴合坏策略，也不要给输出硬减偏置。改default会同时改变相对关节角观测零点与动作偏置，需要训练/部署共同重新验证。真机若存在真实机械零位错误，应独立标定，不与策略学坏混为一谈。

### PD与重力补偿的区别

当前名义训练和仿真PPO为25/.5，固定站姿60/2；独立真机PPO文件当前为25/.8（用户设置，本轮保留）。不同PD会改变实际静态误差和接管感受，但不能据此认定它是后髋21°偏置的原因。

静态负载下，维持同一个实际角度往往需要非零PD位置误差来提供支撑力矩。因此不应以“零指令时全部原始action严格为0”作为验收条件；应关注实际q、机身高度、速度与接管连续性。目标q可因重力补偿而有小偏移，这与后髋持续动作饱和不同。

## 2. 源码中另有PPO入口交接缺口

| 链路 | 当前源码行为 | 限制 |
|---|---|---|
| 仿真PPO公共FSM | `fsm_robot/fsm_imgo2.hpp:165`进入后调用RLControl，后者收到队列目标直接赋q/dq/kp/kd | 没有发现PPO入口目标/增益的显式平滑段；percent_transition变量只置零，未用于PPO Run |
| Gazebo外层RobotControl | `rl_sim.cpp:616`现有policy_transition条件只识别AMPLocomotion | 不能在PPO配置里仅添加policy_transition_duration就认为会生效 |
| MuJoCo RobotControl | 直接StateController后下发PD命令，使用同一公共PPO FSM | 当前未发现额外PPO入口交接 |
| 独立真机程序 | `real/fsm/states/ppo_state.cpp`收到首个有效结果后，用blend_s=.5s五次曲线交接q、kp、kd | 已有平滑机制，但终点随策略刷新；不保证坏策略最终姿态变好或每拍变化率有硬界 |

这属于源码发现，不等于本轮已复现用户每次切换的实际瞬态；当前运行二进制、目标/反馈时序需要带时间戳短流程确认。既有受控无界面对照绕过GUI/FSM异步调度，不能替代这项验收。

建议仿真PPO接入**首个有效新策略结果后的0.5–1.0s可配置目标与增益交接**，从切换前实际下发的目标开始；等待首拍期间保持原命令，清零速度指令并正确重置last_action/历史、清理旧策略队列，观测仍读取真实反馈。交接曲线只改变切换快慢，不能修好随后长期的内收/低机身。延长到1.0s是待验证选项，不是已生效设置。

## 3. 建议第一阶段：平地静站与低速

### 任务与速度采样

- 使用现有`Imgo2-basemove-flat-ppo`链路作为平地基础，做独立的站立/低速配置，保留当前rough作对照。该flat配置继承rough奖励，单选flat任务不会自动解决后髋或奖励问题。
- 首版速度范围建议vx±0.3m/s、vy±0.15m/s、wz±0.4rad/s；显式静站组比例由0.02提高至**0.25**。这是初期覆盖设计，不是长期高速范围。
- 初期关闭heading_command/heading组，直接采样可控yaw速度，确保静站组的三轴指令确实全零。
- 当前命令类平移模长<=0.2m/s会归零，低速训练前必须改为可配置门限（首版建议0.05m/s），只给该低速PPO配置启用，避免全局硬改影响AMP/HimLoco等任务。否则0.1m/s训练目标可能被清零。
- 训练中覆盖稳定站姿初始化、零指令保持后启动、运动后回零三个条件；先用小扰动保证能学，再逐步恢复部署所需的随机化。不能把只在标准零输入上输出小动作当作闭环站稳。

### 首版奖励调整建议

| 项 | 当前rough | 首版静站/低速建议 | 目的/限制 |
|---|---|---|---|
| 对角joint_mirror | -1，含hip/thigh/shank | weight仍-1，先仅配对thigh/shank | 避免把髋原始角同号同步当成站宽目标；对角同步本身并非总是错误 |
| 独立hip joint_deviation_l1 | 0，关闭 | **-0.2** | 对实际髋偏离默认0位施加软代价，不锁死转向/横移 |
| stand_still | -0.1 | **-0.5**，仅零/极低指令 | 加强四腿实际姿态接近默认；实际q而非强制action=0 |
| 新增零指令joint velocity惩罚 | 无独立门控项 | `I_zero*sum(dq²)`，建议weight **-0.01** | 静站时约束关节动态，避免用全局大速度惩罚压制正常摆腿；函数尚需实现 |
| joint_pos_penalty | -0.1，静态×5 | 首版保留 | 与新增静态项存在叠加，需看分项/梯度和实际站姿，不能无限增加 |
| base_height_l2 | -10，target .30 | 首版保留-10/.30 | 默认几何高度相容；先修正确测量，再按高度误差作增权对照 |
| feet_height_body | -5，target -.20，支撑脚也参与 | 第一阶段先关闭；修正摆动门控/测量点后单独评估 | 避免以“抬脚”目标牵引支撑姿态；-.20不是固有错误值 |
| feet_air_time | +1，threshold .5s | 第一阶段先关闭 | 先验收静站/跟速，不同时强求长滞空；.5s不是步态周期 |
| feet_air_time_variance | -8 | 随第一阶段air_time一起暂时关闭 | 减少尚未验证的步态时长约束；后续逐项启用 |
| 跟速/水平/竖直速度/动作差等 | 现有值 | 首版不同时大幅调动 | 保留基本平衡与跟速目标，以受控对照决定后续调整 |

权重-0.2/-0.5/-0.01是建议的试验起点，没有短训验证，不能称为已确定最佳值。增加静止样本与正确门控往往比孤立地放大一个weight更直接。静站时跟踪目标速度0、yaw0仍然提供收益；不能把所有稳定性都寄托于姿态L1。

脚滑项应先改为触地脚的世界水平速度代理（必要时用接触点），不能继续把机身相对足速称为世界脚滑；rough高度射线回退应按环境处理有效性，避免整批误差清零。平地flat本来将base_height的sensor_cfg设None，可绕开该分支做第一阶段对照，但rough问题仍需单独修复。

## 4. 探索分布是必须同步处理的另一项

8400后髋均值/std已严重越界；普通奖励看到裁剪后的物理动作，不能直接区分原始-4与-78。该机制和12个checkpoint证据统一见 [专项审计](ppo_hip_saturation_reward_audit_2026-10-27.md)。

首版建议在实际训练使用的RSL版本实现并验证：逐维std保持正值并设置上界（低速阶段可先以0.1–1.0作对照）、记录逐维mu/std/裁剪率，并通过合适的分布或优化正则限制原始mu长期越界。entropy_coef可从.01降至.003作候选，但降低entropy不是std/均值边界约束的替代，也不会自动清除旧checkpoint的异常参数。当前配置没有已验证的max_std字段，不提供虚构配置键。

新建网络可将init_noise_std=.5作为候选；加载checkpoint会覆盖已学习的std，改init_noise_std不代表旧分布已重置。若要重置，需显式处理参数和相应优化器状态。

## 5. 用什么checkpoint开始

优先评估同run的`model_2000.pt`：当前静态筛查后髋std .858/.995，名义站姿原始均值-.493/.956，没有8400后期那种极端越界；**步态尚未验证**。

若从rough2000迁移到flat：Actor输入相同为45，但Critic的地形特权观测维度不同（现有rough235、flat48），不能把它当普通完整resume。建议新建run、明确迁移Actor权重，重新初始化不兼容的Critic与优化器，并保存新配置。Actor迁移/旧格式训练加载兼容尚需实现与验证；已有play导出兼容不表示训练resume可用。

另一条路径是保留rough观测结构，只在独立低速配置中改为平地，以避免Critic结构变化；仍需验证传感器/奖励配置、修正后的训练更新与新日志。没有完成这些前置前不提供声称“一条命令即可可靠续训”的指令。

## 6. 验收标准建议

按可观察效果选策略，下面是初期可讨论的门槛，不是已通过结果：

1. 平地零指令连续30s不跌倒、没有持续自转或明显位移；检查真实q/dq而不只看目标值。
2. 稳态实际髋偏离默认的典型值先以5°以内作目标，机身高度约.29–.31m；这是小幅平衡容许，不要求所有关节/动作严格0。
3. 重复站起→PPO→站起至少10次，记录每控制拍q_des/q/kp/kd与状态时间；交接首拍连续、没有后髋突然到±.375rad的目标接管。分开判断首拍跳变和0.5s之后最终换姿态。
4. 闭环静站/低速主要动作不持续饱和；把逐髋mu/std/饱和率与实际姿态一起审查，不用平均entropy掩盖两维异常。
5. 通过±.1/±.2/±.3m/s前后、低速横移/转向、运动回零，再逐个加入净空和滞空目标；最后另做rough台阶能力验收。
