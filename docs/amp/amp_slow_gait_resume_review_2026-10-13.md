## 2. 当前真实奖励缺口

依据本次run保存的params/env.yaml、agent.yaml及当前`base_move/amp_env_cfg.py`。步长.005×4=.02 s，RewardManager再乘dt；以下是直立状态下的有效每步系数：

| 项目 | 当前设置 | 与慢、高抬脚目标的关系 |
|---|---|---|
| 平面速度tracking | 4×exp(−误差平方/.5²) | 跟到速度就得分，不检查用什么接触/步态实现 |
| yaw tracking | 2×exp(−误差平方/.5²) | 滑着转也可能得分 |
| 身体高度 | −5×(z−.30)² | 约束身体高度，不是足底抬高 |
| 身体z速度 | −1×v_z² | 约束身体上下运动；身体稳定时抬脚不会被这一项直接惩罚 |
| 身体roll/pitch角速度 | −.05×(ω_x²+ω_y²) | 约束身体摇摆，不设定足端周期 |
| 关节限位 | −2×违限量 | 安全范围约束，不直接限制迈步频率 |
| feet_air_time/feet_height/feet_slide/feet_gait | 全部None | 没有直接的滞空、足底高度、防滑或接触协调任务项 |
| action_rate/joint_acc/joint_vel/torque等 | 全部None | 没有这些显式动作变化/关节运动/力矩代价；实际执行器仍有限幅 |

混合公式是`.3×task + .7×AMP_style`，AMP coef=2；.3/.7是公式系数，不是实际分项贡献百分比。判别器有运动位置/速度等隐式风格信息，但没有显式接触计时或目标周期。

确认的结论：当前目标**允许**贴地、短促卸载、高频小幅运动获得较高回报；跟速和稳定性好不意味着足端步态达标。关闭足端项是明确的约束缺口。没有单项奖励消融，不能宣称某一项已被证明直接造成高频，也不能把AMP当成完全没有步态约束。

不建议先大幅削弱身体z速度/姿态惩罚：它们控制身体跳跃/摇摆，不能等同于抬脚惩罚。比如身体v_z=.2 m/s的该项每步−.04；高度偏差.02 m的项每步−.002。不能把保存的weight −250与速度weight 200直接比较强弱。已修正源码中“高度−5比速度4强”的错误注释，参数未改。

## 3. 为什么不能只恢复旧air_time并加权

原函数在落地时计算`sum((last_air_time−threshold)×first_contact)`。以t_air=.05 s、threshold=.3 s举例：每只脚落地原始项−.25；一直不抬脚、没有落地事件时该项可能为0。若使用历史weight100，dt=.02，单脚事件的task贡献为−.5（尚未乘task混合比例）。

因此强负事件奖励可能让策略通过减少离地事件逃避惩罚，而不一定延长完整步态周期。这是公式允许的路径，不是对旧训练全部失败原因的因果证明。当前25000的air_time已经None，不能把这项旧负奖励说成当前策略正在受到的惩罚。

目标周期T=.6 s，是同一只脚一次完整摆动+支撑的周期；不等于滞空threshold=.6，也不能简单把threshold=.3当周期控制器。旧GaitReward约束足对同步/异步时间差，没有独立的周期目标，直接启用它也不能保证.6 s。

## 4. 建议的微调顺序

1. 保持当前45维接口、模型、motion_new及控制步长，保留原身体稳定性约束和AMP混合作为基线。
2. 先实现正确的摆动脚离地高度与支撑脚地面滑动项；足底目标4–6 cm可作为渐进实验起点。FOOT原点高度需要考虑碰撞几何偏移/旋转，不能直接把target_height=.05当足底抬高5 cm。现有feet_slide先减base速度，启用前必须修正。
3. 再加入完整接触周期区间目标.5–.6 s，配合适度摆动时长（例如.20–.25 s的实验起点）和对角协调。应防止“永不抬脚无事件”及“正落地事件越频繁累计越多”的取巧路径；避免仅用落地次数奖励。纯yaw命令也需要启用合适的步态约束，静止时不强迫迈步。
4. 每步奖励按真实函数范围校准；当前RewardManager权重为每步系数/dt，再检查混合后的实际贡献。不要一次大改混合系数、抬脚、周期、跟速核和稳定性惩罚。仅提高task比例不会自动获得缺失的足端目标。
5. 新奖励通过短恢复/数值检查后，从25000做单独运行；先观察500–1000轮趋势并固定前/后±.4、左右yaw±.5及组合指令回放。这是检查窗口建议，不是收敛保证。以每脚离地高度、接触/滞空/完整周期、跟速及摔倒率判断，不只看总reward或air_time是否转正。

目标周期.5–.6 s在50 Hz下约25–30控制步。24步rollout=.48 s不是步态周期上限；环境跨rollout连续运行，GAE有bootstrap。不要通过改变推理频率或专家FrameDuration来人为放慢这个策略。

## 6. 现存足端奖励可以复用到什么程度

2026-10-13再次逐函数核对 `velocity/mdp/rewards.py` 与 `velocity_env_cfg.py`、`base_move/amp_env_cfg.py`。文件名是 `rewards.py`。

| 函数 | 实际目标 | 复用限制 |
|---|---|---|
| `feet_height`（523行） | 足端link原点世界高度与目标高度的平方误差，乘水平足速的tanh | 需负权重；高度不是足底离地间隙；以速度加权，没有接触门控，慢摆动或不动时约束弱 |
| `feet_height_body`（543行） | 足端相对机身的高度误差，以相对机身水平足速加权 | 需负权重；不是地面净空，机身高度和姿态会影响两者关系 |
| `feet_air_time`（356行） | 落地时结算 `sum((last_air_time-threshold)*first_contact)` | 正权重鼓励较长滞空，不能直接指定完整周期；无落地事件时该项为0，阈值太高可能产生规避事件行为 |
| `GaitReward`／配置名 `feet_gait`（173行） | 指定两组足端的同步与反同步接触/滞空计时关系 | 约束配对协调，没有目标周期；`max_err` 是计时误差裁剪上限，不能作为周期设置 |
| `feet_air_time_variance_penalty`（402行） | 足间滞空/支撑时间方差 | 约束一致性，不指定平均时间或周期 |

当前AMP Height的六项保留名单没有这些项，均被设为None。只修改通用RewardsCfg中的weight不能重新启用；还须调整AMP保留名单并配置足端匹配和步长尺度。

结论：粗略高度目标可复用现有函数；若要求摆动脚的实际足底净空，应改进高度定义与摆动门控。用户指定同一只脚相邻两次落地间隔0.5–0.6 s（约1.67–2 Hz）时，需要新增或扩展周期项；现有同步奖励和滞空阈值不能直接做到。周期项仍需处理初始化/重置、缺失落地事件、站立门控和纯转向指令。

## 7. 静止、低速到高速的训练课程建议

后续源码核对发现平移≤0.2 m/s会被硬编码清零，所以下述初步vy±0.1建议不能直接应用。实施以 [低速微调方案](amp_low_speed_finetune_plan_2026-10-13.md) 为准，先处理可配置死区、纯侧移/转向采样与门控；本节保留为当时讨论背景。

2026-10-13核对公开方法及本地恢复链路。代表性实践：legged_gym在跟踪达到阈值后扩大指令范围；[Rapid Locomotion](https://arxiv.org/abs/2205.02824)研究自适应速度课程；[四足AMP论文](https://xbpeng.github.io/projects/AMP_Locomotion/index.html)将参考动作风格奖励与任务奖励结合。这些说明课程与AMP是可用方法，不构成所有项目必须分三轮训练的结论。

本工程 `Imgo2AmpMoveEnvCfg` 的两个速度课程项均为None，固定范围vx±1、vy±.4、yaw±1；静止指令抽样2%，参考状态初始化概率1。AMP观测组不含速度指令，判别器对整个参考动作分布评分，不会仅凭actor的静止指令自动选择静止参考。`AMPOnPolicyRunner.load()`同时恢复actor/critic、判别器、归一化、优化器与iteration；默认完整续训不等同于仅继承行走能力。

建议为兼容checkpoint的新运行分两步微调（尚未实施）：

1. 先混合静止与低速全方向，零指令比例约10%作为试验起点；例如vx±.4 m/s、vy±.1 m/s、yaw±.5 rad/s。保留前进、后退、左右转与启停，修静止/平滑及低速足端品质。已有策略不必先单独只训静止。
2. 低速/零指令确定性回放达标后逐渐扩展到当前目标范围，继续抽样零指令和低速，避免只训练高速；扩展按分方向跟速、跌倒、足底净空/滑移与切换响应判断，不按固定轮数或总reward判断。以上范围/比例是待验证建议，不是文献推荐常数或已验证最优值。

先保留已核对的motion数据与模型，只改变一个实验组的命令分布或奖励，便于判断效果。若站立与运动先验冲突，需检查静止参考、参考片段权重、初始化及风格混合比例，而非直接强加静止惩罚。高速阶段的周期/净空可能需要随速度变化，不保证固定0.6s能满足全部速度与执行器限制。

不应只关注奖励与motion：还须核对命令采样/小指令阈值、重置状态与指令一致性、dt尺度和task/style实际贡献、PD/力矩与速度限制、部署观测/动作契约及随机化。首次实现可保持已验证契约，不必同时修改所有参数。更换数据集时先做关节/FK、时间间隔/速度与方向覆盖验证；新建运行，检查是否适合恢复旧判别器/归一化，必要时需实现单独的策略迁移恢复入口，不能默认全量load即可适配。
