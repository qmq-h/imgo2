# AMP 与 PPO：理论和当前实现对照

核对日期：2026-11-22。范围：本机工作区源码、任务注册和现有离线配方测试；没有启动训练、仿真或硬件，没有用历史指标推断当前策略效果。

## 1. 两者是什么关系

PPO 是策略优化算法，规定如何利用交互样本和奖励更新控制策略。AMP（Adversarial Motion Priors，对抗运动先验）学习一个来自参考动作的风格奖励，再用强化学习优化策略。本仓库的 AMP 用的仍是 PPO，因此主要变化在奖励来源、训练数据和辅助网络。

| 内容 | PPO 基线 | 本仓库 AMP |
|---|---|---|
| 策略优化 | PPO 裁剪目标、价值回归、熵项 | 保留这些机制 |
| 任务奖励 | 人工定义跟速、姿态、能耗等 | 保留所选任务奖励 |
| 动作风格 | 由奖励设计间接约束 | 额外从参考状态转移学习 |
| 网络 | actor、critic | actor、critic、discriminator |
| 参考动作 | 算法本身不要求 | 训练判别器和参考状态初始化使用 |
| 部署 | actor 推理 | 同样可只部署 actor |

当前 PPO 的 `scripts/rl_lab/ppo/train.py` 导入外部 `rsl_rl.runners.OnPolicyRunner`，不是仓库自带的 `rl_lab/algorithms/ppo.py`。后者适合对照核心公式，但不能据它断言已安装外部库的全部行为。AMP 入口使用仓库内 `AMPOnPolicyRunner` 和 `AMPPPO`。本轮未定位或核对外部库的实际安装源码版本。

## 2. PPO 的基础

策略根据观测和速度指令产生动作：`a_t ~ πθ(a_t | o_t)`；本机 AMP actor 为高斯策略，部署时 `act_inference()` 返回均值。critic 估计未来累计折扣回报，允许读取训练时才有的额外信息。

强化学习目标是最大化 `E[Σ γ^t r_t]`。忽略终止掩码时，GAE 写为：

```text
δ_t = r_t + γ V(s_{t+1}) - V(s_t)
A_t = δ_t + γλ δ_{t+1} + (γλ)^2 δ_{t+2} + …
```

优势为正表示这次动作的后续回报高于价值基线，为负则低于基线。实际 `rollout_storage.py` 会处理 done 掩码，算法也处理超时 bootstrap，并标准化优势。

PPO 的概率比和最大化目标为：

```text
ρ_t = πθ(a_t | o_t) / πold(a_t | o_t)
Jclip = E[min(ρ_t A_t, clip(ρ_t, 1-ε, 1+ε) A_t)]
Lactor_critic = -Jclip + c_v Lvalue - c_h H(πθ)
```

裁剪削弱有利方向上过大的概率比带来的优化收益；`ε=0.2` 不是参数变化不得超过 20% 的硬约束，也不保证所有样本的概率比都留在区间内。

本机 PPO 基线配置和两套 AMP 配置都声明 `clip=0.2`、`gamma=0.99`、`lambda=0.95`、5 个 epoch、4 个 minibatch、初始学习率 1e-3、自适应 KL 目标 0.01、熵系数 0.01。actor/critic 的隐藏层也同为 `[512, 256, 128]`。这些共同项不能当作 AMP 的独有改进。

## 3. 为什么要新增风格奖励

只给跟速奖励时，很多步态都可能取得高分，包括人不希望得到的碎步、滑步或过大的身体摆动。PPO 只优化得到的奖励，不知道设计者隐含的步态偏好。人工可以不断增加足端高度、接触相位、动作平滑等约束；AMP 则用参考动作定义一部分偏好。

判别器接收 `x_t = [z_t, z_{t+1}]`，其中 `z=Φ(s)` 是选出的运动特征。训练时区分专家数据与策略实际产生的状态转移。这里的专家指参考数据，不要求提供对应控制动作，也不要求在线运行 MPC 教师。

当前单帧判别特征按顺序为：

| 特征 | 维数 | 口径 |
|---|---:|---|
| 关节角 | 12 | 绝对角，非 actor 的默认角偏差 |
| 四足位置 | 12 | 基座坐标系 |
| 根线速度 | 3 | 基座坐标系 |
| 根角速度 | 3 | 基座坐标系 |
| 关节角速度 | 12 | 与参考相同关节顺序 |
| 根高度 | 1 | 当前平地任务为世界系 z |
| 合计 | 43 | 两帧拼接为 86 |

判别器是 `86 → 1024 → 512 → 1`，隐藏层 ReLU、输出为线性分数，没有 sigmoid，因此分数不是概率。它不读速度指令、完整动作周期或参考相位。两帧提供短时运动信息，不能保证完整周期与参考逐帧一致。

`height` 的 actor 使用 45 维观测：角速度 3、投影重力 3、速度指令 3、关节角偏差 12、关节速度 12、上次动作 12。`fanziqi` 进一步去掉角速度，为 42 维。判别器、actor 和 critic 的输入用途不同；actor 去掉基座线速度是部署观测设计，也适用于 PPO，不是 AMP 的理论创新。

参考动作入口来自 `assets/imgo2.py`，默认目录由源码推导为 `imgo2_rl/datasets/imgo2_motion_new`，可由 `IMGO2_AMP_MOTION_DIR` 覆盖；不是另一份 `assets/amp_motions.py` 的 mocap 搜索规则。具体运行还须以该次环境变量及配置快照为准。

## 4. 判别器怎样学习，怎样生成奖励

当前最小二乘判别损失为：

```text
L_D = 0.5 × (Eexpert[(D(x)-1)^2] + Epolicy[(D(x)+1)^2])
L_gp = 10 × Eexpert[||∇x D(x)||²]
```

专家标签为 +1，策略标签为 -1。梯度惩罚让判别器在专家样本附近更平滑；这里的目标梯度范数是 0，不是 WGAN-GP 常见的 1。优化器还对判别器主干和输出层施加 weight decay。

忽略正则化、假设等权采样和充分表达能力，逐点最优判别器为 `D*(x)=(p_E(x)-p_π(x))/(p_E(x)+p_π(x))`。它反映两种样本分布的相对密度。因此当两种分布完全相同，理想分数是 0，而不是所有策略样本都为 +1；不能把判别损失越接近 0 当作最终策略越好的充分依据。

风格奖励先计算 `r_style = 2 × max(0, 1 - (D(x)-1)²/4)`，再与任务奖励混合。两套 runner 均配置 `amp_reward_coef=2`、`amp_task_reward_lerp=0.3`：

```text
r_total = 0.7 × r_style + 0.3 × r_task
        = 1.4 × max(0, 1 - (D(x)-1)²/4) + 0.3 × r_task
```

| D 分数 | 未乘 2 的风格奖励 | 最终风格分量（已乘 2 和 0.7） |
|---:|---:|---:|
| +1 | 1 | 1.4 |
| 0 | 0.75 | 1.05 |
| -1 | 0 | 0 |

函数在 D=1 处最高，并非 D 无限制增大时奖励也一直增大。例如 `r_task=4、D=0` 时，总奖励为 `1.2+1.05=2.25`。

0.7/0.3 是系数，不能直接叫作实际奖励占比。必须比较实际分项；任务奖励的尺度和惩罚会改变占比。Isaac Lab RewardManager 对任务奖励乘 step_dt，而判别器奖励直接按控制步计算；`height` 已将任务系数除以 step_dt，调整频率或迁移配置时必须保持单位一致。

## 5. 训练更新的真实数据流

```text
actor 与环境交互 → 当前两帧 AMP 特征 → 判别器给风格奖励
人工任务奖励 + 风格奖励 → rollout → GAE / returns → PPO 更新 actor / critic
参考转移 + 策略历史转移 → 最小二乘损失 / 梯度惩罚 → 更新判别器
```

`amp_ppo.py` 把 PPO 损失、判别损失和梯度惩罚相加，用同一个 Adam 的不同参数组更新。不过 `predict_amp_reward()` 使用 `torch.no_grad()`，采样得到的状态和 PPO 存储也不保留策略计算图；判别器分类损失不会直接反向传播到 actor。actor 是通过奖励影响优势，再通过 PPO 改进。

AMP 学习的是所选特征下的状态转移分布相似性，不要求第 t 帧与某段参考的第 t 帧重合。它可以组合数据中的局部运动；这不同于直接监督 `π(s)=a_expert` 的行为克隆，也不同于指定参考相位的逐帧跟踪。

本机工程还新增了：

- 100 万条容量的策略转移 replay buffer，供判别器训练；PPO 的 actor/critic 仍使用当前 rollout，并未因此变成 SAC 式离策略更新。
- 200 万条预加载专家转移；是插值采样缓存，不代表有 200 万条独立录制动作。采样时间间隔由 `time_between_frames=env.dt` 对齐控制周期。
- 专家和策略使用同一套 AMP 特征归一化；统计量用原始物理特征更新。
- 参考状态初始化：`height` 训练默认全部使用参考状态；`fanziqi` 为 85%。帮助从步态不同阶段开始探索，play 配置会关闭该事件。
- episode 结束时保存 reset 前的终止 AMP 特征。否则会把跌倒前状态与新回合出生状态拼成虚假的运动转移。

部署只需要 actor 和正确的观测、动作处理；无需在线读取参考动作或执行判别器。训练可以用仿真线速度和足端真值，不要求将这些输入追加到部署 actor。

## 6. 当前两套配方和适用边界

| 配方 | 任务奖励 | actor 维数 | 参考初始化概率 | 动作噪声标准差下限 |
|---|---|---:|---:|---|
| `Imgo2-basemove-flat-amp-height` | 跟速、高度、竖直速度、横滚俯仰角速度、关节限位、滞空缺口 | 45 | 100% | 关闭 |
| `Imgo2-basemove-flat-amp-fanziqi` | 仅线速度和偏航角速度跟踪 | 42 | 85% | 开启 |

AMP 的收益是从数据学习难以逐条手写的运动偏好，减少部分风格奖励设计，并允许不带控制动作的参考数据。它不保证更快收敛、更强抗扰或更好的 sim2real。参考的关节轴、顺序、坐标系、速度单位、采样时间和数据覆盖都决定了监督是否有效；平地参考也不自动提供楼梯能力。

判别器与策略共同变化，使奖励非平稳；判别器过强、过平、输入错误或参考缺少目标速度时，风格反馈可能无效或与任务目标冲突。即使单帧分布相似、跟速很好，也可能出现周期不匹配。

仓库已记录 AMP-06 的步频/步幅差距，历史与分析统一见 [步态调整方案](amp_gait_adjust_plan_2026-09-18.md) 和根 README 问题表。本轮没有复跑旧 checkpoint，没有验证修改梯度惩罚或其他超参数能够解决它。参考样本也不是真实硬件动力学模型，不能据此认定换成 AMP 就会消除当前实机横滚。
