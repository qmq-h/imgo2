# AMP 风格模仿与滞空奖励复核（2026-10-10）

## 结论与范围

已完成本地源码和参考运动数据离线复核，未改训练奖励、未启动新训练。当前 AMP 通过局部状态转移间接学习抬脚与节律，没有显式滞空时间、接触状态或完整周期约束。增加滞空奖励可能帮助降低高步频，也可能鼓励偏离参考的长摆腿或跳跃；目前无法确认服务器新 run 已发生这种副作用。

已修正说明：0.3 s 是落地事件奖励转正门槛，并非最优滞空目标；历史记录中的策略接触占空比不能作为参考数据的接触占空比。

## 1. 判别器到底模仿什么

`amp_env_cfg.py:AMPObservationCfg` 包含关节位置 12、足端 base 系位置 12、身体线速度 3、身体角速度 3、关节速度 12、根高度 1，共 43 维。`motion_loader.py:get_amp_observation_from_full_frame` 对专家使用同一顺序；`amp_discriminator.py:predict_amp_reward` 拼接相邻两帧，共 86 维。Height 的两帧相隔 0.02 s。

没有输入：接触力、接触标志、累计滞空时间、步态相位、历史完整周期、速度命令。足端位置和关节速度包含抬脚与运动快慢的信息，因此不能说 AMP 完全不模仿滞空；但 20 ms 的局部转移判别不保证每 0.6 s 落地一次。策略优化混合标量奖励，风格是软约束，不是逐帧跟踪某一段录制轨迹。

当前混合公式为 `0.7 * style + 0.3 * task`，style 原值在 [0, 2]。系数不等于实际奖励占比；任务权重和量纲仍影响折中。专家混合所有 21 段，未按当前速度命令筛选；某个速度下的相似动作可能来自别的专家片段。

## 2. 当前滞空公式与可能副作用

在首次接触时结算：

`task_air = C * sum((last_air_time - 0.3) * first_contact) * command_gate * upright_gate`

`C = raw_weight * step_dt`，本地默认 raw weight=50，step_dt=0.02，故 C=1。命令三维范数 >0.1 才开启，并乘直立门控。它没有上限，也没有接近 0.3 的误差项。单脚单次落地，忽略门控：0.1 s 得 −0.2，0.24 s 得 −0.06，0.3 s 得 0，0.4 s 得 +0.1；之后仍混入任务总奖励。

所以奖励会推动少而长的摆腿；固定占空比 d 和周期 T 时，单位时间的四足贡献近似 `4*C*((1-d)-0.3/T)`，增大 T 可减少每秒反复扣门槛的次数。它不能独立固定周期为 0.5–0.6 s，也不能固定腿间相位。

潜在副作用包括过长摆腿、改变支撑占比、跳跃、左右不对称或跟速下降。零落地事件时这一项为零，也可能比频繁负分更有利，但是否站着不动或拖脚还受跟速、风格等项影响。上述是公式允许的激励方向，不是当前策略已出现的实测结论。

## 3. 参考数据与当前策略差多少

参考基线 `gait_reference_baseline.json`：19 段有效行走的周期中位数 0.6001 s、步频 1.6663 Hz；stance 和名为 backward_0.3 的近静止片段不能用作行走节律依据。forward_0.6 片段的实际平均根速度约 0.481 m/s，周期约 0.6001 s。文件名不是实际速度保证。

本轮标准库脚本从根高度、xyzw 四元数和足端 base 系坐标重建世界足端高度，以每脚第 5 百分位高度作近地基线，统计高于基线的完整连续区间；排除片段边界截断。复现：

```bash
/usr/bin/python3 imgo2_rl/scripts/tools/check_reference_swing_proxy.py
```

## 4. 调整建议与待确认

先补同速稳定窗口的每脚接触滞空、支撑时间、周期、相位、抬脚高度与跟速误差，再决定是否增权。0.3 s 可以保留作试验门槛，但不能宣称它已等于参考真实摆腿时长；0.5–0.6 s 完整周期也不能简单除以二，支撑比例未必是 50%。

若目标是忠实模仿并固定在一个范围，比无限线性增奖更可控的候选是奖励目标区间或目标时间附近的落地事件，同时按命令速度启停/调整目标。简单截断为非负会丢掉短摆腿惩罚，也不保证目标；需要另设计验证。更长判别器历史或接触/相位特征能提供节律信息，但会改变判别器输入与归一化契约，需要重新初始化相关模块，不能直接当作兼容续训改动。

待确认：服务器当前 env.yaml/agent.yaml 和日志、真实参考接触标签或同模型参考回放接触、当前策略同速接触测量、单变量微调后的表现。当前只有源码与离线运动学验证；没有证明 0.3 s 奖励导致跳跃，也没有证明继续加权能改善模仿。

## 5. AMP Height 调参入口复核

当前 `base_move_amp_height` 对应 `base_move/agents/amp_rsl_rl_cfg.py` 的 `AMPHeightRunnerCfg`：`amp_reward_coef=2.0` 是风格奖励的内部倍率，`amp_task_reward_lerp=0.3` 是任务混合系数，最终为 `0.7*style + 0.3*task`。增大 lerp 会减小风格系数、增大任务系数，不是增强模仿。不要误改同文件 Fanziqi 配置。

普通任务的各项系数由 `base_move/amp_env_cfg.py:_keep_only_amp_task_rewards` 中 `*_PER_STEP` 常量设置（线速度 4、偏航 2、高度 −5、竖直速度 −1、横滚俯仰角速度 −0.05、关节限位 −2、滞空 1），随后除以 `step_dt` 转为 RewardManager 权重。滞空门槛同函数为 0.3 s。只改共用 `velocity_env_cfg.py` 的 weight 会被 AMP 此处重新赋值。

训练速度在 `base_move/amp_env_cfg.py:Imgo2AmpMoveEnvCfg.__post_init__`：vx [−1,1.5] m/s、vy [−1,1] m/s、yaw [−1.57,1.57] rad/s；这是训练采样范围，play 子类和 CLI 可另设固定评估命令。本轮只核对位置，未改训练配置；AMP-13 接触对齐和副作用验证仍待完成。
