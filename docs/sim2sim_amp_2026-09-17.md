## 3. 关键依据（源码核对）

- `rl_sim_mujoco.cpp` 的 `GetState` 读 `sensordata[3*n + 0..3]`（四元数）与 `[3*n + 4..6]`（角速度），
  关节量按 `joint_mapping` 取下表；`SetCommand` 用 `ctrl[joint_mapping[i]]`。因此
  **场景的传感器与执行器顺序必须与策略顺序一致**。
- `ComputeObservation()` 按配置 `observations` 列表顺序拼接，`dof_pos` 项内部做
  `obs.dof_pos - default_dof_pos`，`gravity_vec` 项做 `QuatRotateInverse(base_quat, {0,0,-1})`。
- `obs.lin_vel` 只在 `InitObservations()` 里被置零，**全仓没有任何地方写入它**；`lin_vel` 观测
  在 MuJoCo 链路上恒为 0。

## 6. 模型副本与"一启动就飞"（补充排查）

### 6.1 现象与根因

GUI 一启动机器人就被弹飞。根因**不在控制器**，在场景初始姿态：

- `mujoco_utils.hpp:436 PhysicsThread` 只做 `LoadModel → mj_makeData → mj_forward`，
  **从不套用 `<keyframe>`**；`Simulate::Load` 也不会。所以实际使用的 qpos 是模型默认值
  （关节角全 0，即直腿）。
- 我们原先的 `scene.xml` 写 `<body name="base" pos="0 0 0.35">`，直腿时
  **足端 z = −0.0758 m，起点在地面以下** → 巨大约束力把机器人弹出。实测 12 s 回放
  `z_max = 1.3623 m`。
- 参考项目写的是 `pos="0 0 0.5"`，直腿时足端 z = **+0.0743 m**，所以不飞。
  两者同一机器人，足端偏移都是 0.4258 m，差别只在这个初始高度。

### 6.2 第一次尝试（已撤销）：`<joint ref>`

给 12 个关节加 `ref="0/0.87/-1.82"` 确实把 `mjModel.qpos0[7..9]` 设成了目标姿态，
但 MuJoCo 的关节运动学以 `qpos − ref` 为有效角，等于把姿态抵消回直腿，实测足端仍
−0.0758 m、仍然弹飞。**`ref` 不是"初始关节角"，已全部撤销。**

### 6.3 最终修法：照参考项目改场景（参数，动的是资产不是运行逻辑）

| 项 | 改前 | 改后（= 参考项目） |
|---|---|---|
| `base` 初始高度 | `pos="0 0 0.35"`（足端 −0.0758，穿地） | `pos="0 0 0.5"`（足端 +0.0743，与参考一致） |
| `<option>` | `timestep="0.005" integrator="implicitfast"` | `timestep="0.005" cone="elliptic" impratio="100"` |
| 12 个腿关节 | `damping="0" armature="0"` | `damping="1" armature="0.1"` |
| 碰撞 geom | 无接触参数 | `condim="3" solref="0.005 1" friction="1 0.01 0.01"` |
| 足端 geom | 同上 | `friction="0.4 0.02 0.01"` |

`timestep` 保持 0.005（与 `base.yaml` 的 `dt` 一致，策略周期才是 20 ms）；参考项目
未设 timestep（默认 2 ms）却配 5 ms 控制周期，这一点没有跟着抄。

|---|---|---|---|---|

### 6.5 参考项目的 description 与我们的模型副本对照（回答"能不能统一"）

**物理上不是"更好"，而是同一个机器人。** 逐项核对：

| 对照 | 结论 |
|---|---|
| 参考 `imgo2_description.urdf` vs **训练 URDF** | 17 个公共 link 的**质量/质心/惯量/碰撞体数全部相同**；同名关节的 axis/limit/父子 **0 处不同**；base 质量都是 `5.53394020`。差异只有：参考那份多一个 `imu_link` + `imu_joint`，且用 `FL/FR/RL/RR` 命名 |
| 参考 `imgo2_description.urdf` vs **我们的 `imgo2_description`** | 命名体系不同：我们的是 `LF_HAA/LF_HFE/LF_KFE`（LF/LH/RF/RH，采集侧命名）；参考那份是 `FL_hip_joint/...`（训练侧命名） |
| 参考 `mjcf/imgo2.xml`、`mjcf/scene.xml` vs 我们仓库里的同名文件 | **逐字节相同**（`bcfdc3f44e1e` / `1d2ab8cb4a81`） |
| 但那份 MJCF 在本仓库能否加载 | **不能**：它引用 `FL_hip.STL/FR_hip.STL/RL_hip.STL/RR_hip.STL/L_shank.STL/R_shank.STL`，而我们 `imgo2_description/meshes/` 用的是 `LF_hip/LH_hip/L_calf/...`，10 个引用里有 6 个不存在 |
| 参考 MJCF 的物理 | 关节 axis/limit 与训练侧一致；但 base 惯量仍是旧值 `mass=6.53394 + diaginertia 0.08017/0.0664867/0.0246935`，不是训练侧规范值 `5.53394020 + 0.03866860/0.10411461/0.12554111` |
| 参考 MJCF 的求解器/接触 | 明显更完整：`cone=elliptic impratio=100`、关节 `damping=1 armature=0.1`、碰撞 `condim=3 solref="0.005 1"` + 分几何 friction、`equality` 约束，以及 `accelerometer/framepos/framelinvel` 传感器（我们的场景只有 framequat + gyro） |

**因此：**

- **参考 description 不能"直接用"于本仓库的训练**：它的 URDF 就是训练模型加一个 IMU link，
  换过去不带来任何物理收益，却要重跑 AMP FK 对齐与 `check_model_sync` 验证（AMP 恒等映射的
  依据是训练 URDF 与录制数据 FK 吻合到 0.002 m）。
- **也不能"直接"用于 sim2sim**：它的 MJCF 在本仓库缺 6 个网格，加载即失败。它在参考项目里能用，
  只因为那边 `meshes/` 是 `FL_*` 命名。
- **真正值得照抄的是它的求解器/接触/关节阻尼设置**，而不是它的 URDF 或 MJCF 文件本身。

**决策点与实际执行（历史记录，保留原方案）**

用户提议：**一切都统一到 `imgo2_description`**；RL 用最朴素的 URDF，deploy 的 Gazebo 链路需要
IMU、关节控制器（transmission）等附加设置，MJCF 只服务 MuJoCo；因此把 Gazebo 内容从
description 里独立出去，在 launch/构建时组装。

**支撑该方案的实测事实：**

1. `imgo2_description/urdf/imgo2_description.urdf` **已经把 Gazebo 内容混在里面**：
   `<transmission>`×12（`transmission_interface/SimpleTransmission`）＋ `<gazebo reference="...">`×17
   （全是按 link 的摩擦/材质，无插件）。插件与 IMU 不在 URDF 里，而在
   `xacro/common/gazebo.xacro`（`gazebo_ros_control` + `liblegged_hw_sim.so`、`libgazebo_ros_p3d.so`）
   与 `xacro/common/imu.xacro`（`imu_link` + Gazebo IMU 传感器），由 `robot.xacro` 组装。
   注意 `robot.xacro` 同时 include 了已含 transmission 的 URDF 和 `gazebo.xacro`，存在重复叠加的风险。
2. `imgo2_description/urdf/imgo2.urdf` 是**纯 URDF**（无 gazebo、无 transmission，17 link），
   与 `imgo2_description.urdf` 去壳后只差 meshdir 写法和注释。也就是说"内核 / 附加"两半其实已经存在。
3. 部署份 URDF **既无 transmission 也无 gazebo 插件**（DEPLOY-05 的成因），所以 Gazebo 链路从没通。
4. **三套网格其实是同一套内容，只是改名**：`imgo2_description/meshes` 的 10 个文件与共享集
   （`bc421eb1cbef`）逐字节相同，改名映射为
   `LF_hip→FL_hip`、`LH_hip→RL_hip`、`RF_hip→FR_hip`、`RH_hip→RR_hip`、`L_calf→L_shank`、`R_calf→R_shank`，
   其余 `base/foot/L_thigh/R_thigh` 同名。**"统一网格"是纯改名，不涉及几何。**
5. 参考项目那份 `imgo2_description.urdf` 与训练 URDF 物理完全相同（17 link 逐项相同），只是多
   `imu_link/imu_joint` 并采用 `FL/FR/RL/RR` 命名；它的 `mjcf/imgo2.xml` 与本仓库逐字节相同，
   但在本仓库缺 6/10 网格（命名不匹配）→ 网格改名后即可加载。

**目标结构（草案）：**

