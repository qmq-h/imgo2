# 上层「双头」方案（cmd vel 头 + 关节残差头）与冲击窗口独立统计（2026-10-10，**已实现，v3**）

## 起因（用户 2026-10-10 的两点判断）

1. **「用残差的方式很难学会在 cmd=0 之后继续前进」**。源码事实支持这一点：`upper_mdp.process_actions()`
   在 STOP 之后 `loco_command.zero_()` 且 `[:, 0] = where(towing, tow_speed, 0)` —— 冻结 AMP 策略收到的
   是 **(0, vy_PD, wz_PD)**，即「站住 + 横向修正」。冻结策略是按速度指令训练的，对它的原生响应就是站立
   ⇒ 想「继续走两步」只能由残差把**站姿重建成步态**，与牵引段的「在行走步态上做小幅修正」难度完全不同，
   却是同一个网络、同一组梯度。
2. **「抗击冲击是一定要关节调整的；停止后继续走两步可能就需要指令侧调整」** ⇒ 两类量的时标与手段不同：

   | 头 | 层面 | 时标 | 为什么必须在那一侧 |
   |---|---|---|---|
   | 关节残差（12 维，已有） | 力矩级：绷直冲量、负载扰动、坡上反驱 | 单步级（20 Hz） | 冲击要关节「硬一下」扛住，速度指令表达不了这种响应 |
   | **cmd vel 头（新增）** | 行为级：cmd=0 后是否再走、按车重/坡度调度 | 秒级 | 冻结策略本来就会走，只是被叫停；用指令最便宜 |

   协同：cmd 头可在绷直前**降速**（少灌能量），关节残差接住到达的冲量。**不是替代关系**。

## 与现有设计的冲突（必须先解决，否则新头与奖励对打）

- `post_stop_distance`（权重 −0.1）的 docstring 明写「教『说停就停，别继续滑』」，`relu(x − stop_origin_x)`
  ⇒ **惩罚的正是「cmd=0 后继续前进」**。
- `tracking_velocity` 的参考量**也是** `loco_command[:, 0]`（`forward_error = vx_meas − loco_command[:,0]`）
  ⇒ 现在只有**一个**命令量同时承担「送冻结策略」和「给奖励当参考」。

**防作弊红线**：新增指令头后，**新指令值绝不能同时喂奖励**，否则策略只要把偏移开大就能自己给自己发目标。
必须拆成两个量：

- `task_command`：脚本调度、到点归零 —— **只给奖励**（`tracking_velocity`、`post_stop_*`）；
- `loco_command`：脚本 + 策略偏移 —— **给冻结策略 + 进 actor 帧**（策略因此看得见自己下了什么指令）。

## 三个设计决定（待用户确认）

1. **维度**：建议 **1 维（只 vx）**。用户 2026-10-09 已定「中线和 heading 用 PD，不让策略学」，横向/朝向惩罚
   也已关闭 ⇒ 开 3 维等于推翻那条决定。
2. **加性偏移还是有界绝对指令**：建议**加性 + 有界**：`loco_command[:,0] = clamp(scripted_vx + offset, −0.2, +0.6)`，
   偏移头限幅，且只在 `elapsed ≥ tow_start` 后生效（出生段不许推机器人）。
3. **是否同时给脚本 ramp 作底**：**强烈建议要**。若偏移初值为 0、基座指令在 STOP 就是 0，则「多走两步」仍要
   策略从零学（回到原困难）；若脚本侧改成「STOP 后 1–2 s 内 `tow_speed` 线性降到 0（或降到 0.2–0.3 m/s 慢走）」，
   行为**第 0 步就存在**，新头只做**按车重/坡度/冲击的自适应修正**。

## 便宜的预研（不改契约、不训网络）

测试台已有 `--command-shaping ramp`（Fixed Ramp 基线）：先在 800 cell 上看「斜坡降速 / 慢走」能否改善停车段
指标（`stop.cart_coast_distance_m` / `cart_coast_time_to_rest_s` / `stop.joint_rms_rad` / `min_clearance_coast_m` /
`startup.torque_saturated_frac`）。ramp 有效再上 13 维契约迁移；无效则省一轮迁移。

## 冲击窗口必须独立统计（用户 2026-10-10 明确要求）

**问题**：如果只报全程/牵引段的关节响应 RMS，起步与停车的冲击会被运动中的小响应**平均掉**，看不出安全性与
改善。**要求**：把「冲击窗口」与「稳态」拆成两个独立统计量，并给出两者的比值/增量：

1. 保留现有固定窗口口径（起拖后 / 指令归零后 `--transition-window`，默认 1.0 s）——**归档基线对照依赖它，
   语义不得改**；
2. **新增**瞬态窗口（如首 0.2 s，`--impact-window`）的 `joint_rms_rad` / `joint_max_rad` / 逐关节 / 力矩饱和；
3. **新增**稳态量（牵引段去掉首尾各 N 秒）的 `steady_joint_rms_rad`；
4. **新增**两者的比值/增量（冲击 vs 稳态），使「有没有冲击」不依赖读者心算；
5. **新增**与**真实冲击时刻对齐**的窗口：从记录的绳张力里判定绷直/穿绳时刻（首个 |F| 越阈样本），围绕它取窗口
   （`takeup_*`），因为那才是冲量的真正发生点；
6. **新增**停车撞击窗口（`stop_contact_*`：接触发生时刻对齐），与「指令归零窗口」区分开。

**口径不变**：阈值、判定码、既有字段名与语义都不动，只新增字段；文档与测试同步。

### 已实现（2026-10-10）

**只新增、不动既有口径**：新增纯函数 `impact_stats()`（四个时刻各取窗口独立统计 + 稳态分母 +
比值/增量）。CLI：`--impact-window`（默认 0.2 s）、`--steady-margin-s`（默认 1.0 s）、
`--takeup-force-threshold`（默认 1.0 N，取 `|rope_tension_n|` 模长 ⇒ rigid 连杆负张力也算绷直）。
`report.md` 增「## 冲击窗口 vs 稳态（关节响应）」一节、`report.json` 增 `impact_statistics`、
`report.csv` 增 `impact_<窗口>_*`。既有 `--transition-window` 的 `startup.*`/`stop.*`、
`DEFAULT_THRESHOLDS`、判定码与 `classify_case` **全未改**，新参数不进判据（AST 守卫）。
字段名/单位/读法、验证方式与未验证项见 [独立记录](towing_impact_window_2026-10-10.md)。
