对象：`imgo2_rl` 的 `Imgo2-basemove-flat-amp`（训练 9496 轮；基座高度 0.306 m、贴地 0.5%，
但线速度误差恒为 1.65 m/s、关节幅值 0.014 rad ≈ 姿态锁死；~1000 轮后指标全平）。
参考实现（本机都有）：

## 结论（先说答案）

**① `clamp(min=0)` 不是差异**：两份参考的公式与我们的**逐字相同**，都有这个地板。
真正差异在**任务奖励的组成**：参考 a1 的 AMP 任务**只有速度跟踪两项、其余全 0**；
我们**额外留了一个每步 −10 的 `base_height_l2`**，量级比两份参考都大（a1 没有这一项，
go2 每步只有 −0.02，见第 11 节）。于是速度误差一大（σ=0.5、e=1.65 时
`exp(-(1.65/0.5)^2) ≈ 2e-5`）速度项梯度≈0，高度项梯度把策略按在「精确站在 0.30 m」这个局部最优上
→ 锁死站姿 → 判别器对冻结策略给出近乎常数的风格分（`mean_disc_pred≈-0.52`，风格≈0.467/步）
→ PPO 优势≈0 → 全指标变平。与观测（高度达标、关节不动、速度误差恒定、1000 轮后全平）完全一致。

## 逐条对照

### ① 风格奖励（`predict_amp_reward`）

- 参考两份**完全相同**，也**有** `min=0` 地板，`d` 是**裸 logit**（`amp_linear` 输出 1 维，无
  sigmoid/tanh）：
  `reward = amp_reward_coef * torch.clamp(1 - (1/4) * torch.square(d - 1), min=0)`
- 我们与之逐字相同 ⇒ **d≤-1 时同样没有梯度，但这不是差异**。

### ② 判别器 loss

- 两份参考相同：`expert_loss = MSE(expert_d, +1)`、`policy_loss = MSE(policy_d, -1)`、
  `amp_loss = 0.5*(expert+policy)`、`grad_pen = compute_grad_pen(*expert, lambda_=10)`（**只对 expert**）、
  `loss = surrogate + value_coef*value − entropy_coef*entropy + amp_loss + grad_pen`；
  **与策略共用一个 Adam**（`lr=1e-3`，trunk `weight_decay=10e-4`、head `10e-2`，KL 自适应缩放 lr），
  另有 `std.data.clamp(min=min_std)`。
- 我们相同 ⇒ 也不是差异。

### ③ 风格:任务 配比

下表第三列已按**每步真值**（= 原始权重 × dt）书写，推导见第 11.1 节：

| | amp_reward_coef | amp_task_reward_lerp | 任务项（**每步**重量） |
|---|---|---|---|
| 我们（dt 0.02） | 2.0 | 0.3 | track_lin_vel **1.0**、track_ang_vel **0.3**、**base_height_l2 −10** |
| `AMP_for_hardware` a1（dt 0.03） | 2.0 | 0.3 | tracking_lin_vel **1.5**（原始写 50）、tracking_ang_vel **0.5**（原始写 16.7）、**其余全 0**（无 base_height） |
| `amp_go2`（dt 0.02） | **0.2** | **0.8** | tracking_lin_vel **0.08**（原始 4.0）、tracking_ang_vel **0.04**（原始 2.0）+ lin_vel_z −0.02、base_height **−0.02**、<br>ang_vel_xy −0.001、dof_acc −5e-9、torques −2e-6、action_rate −2e-4、collision −0.02、<br>dof_pos_limits −0.04、feet_air_time 0.02 |

### ④ 速度/角速度奖励

- 形式（两份参考与我们都一样）：`exp(-error²/tracking_sigma)`（或等价的 `std=sqrt(0.25)`），
  `tracking_sigma = 0.25` ⇒ σ=0.5；角速度同式。
- **量级不是差异（原结论作废）**：a1 配置里写的 `1.5 / (0.005*6)` 是**原始权重**，
  `_prepare_reward_function()` 会再乘 `self.dt`（`legged_gym/envs/base/legged_robot.py:705-710`）
  ⇒ **每步 1.5**。我们写 `1.0/step_dt`，Isaac Lab 的 RewardManager 会乘 `step_dt` 抵掉
  ⇒ **每步 1.0**。两者同量级（差 1.5 倍），不是 50 倍。
- **真正的离群项是高度**：a1 的 AMP **没有任何高度项**，go2 每步 −0.02，我们 **−10**（比 go2 强 500 倍）。
  加上终止条件只有 `base` 触地（a1 还把 `thigh`/`calf` 纳入终止），所以「趴着滑」在我们这里不进惩罚区。

### ⑤ 探索与初始化

- `init_noise_std = 1.0`、`min_normalized_std = [0.05, 0.02, 0.05] * 4`、`entropy_coef = 0.01`、
  `learning_rate = 1e-3`、学 `log_std`（rsl_rl 的 `std` + `clamp(min=min_std)`）——**与 a1 逐字相同**
  ⇒ 不是差异。

### 其他（都一致或无害）

- 判别器结构 `[1024, 512]`（ReLU）、`amp_num_preload_transitions=2000000`、
  `amp_replay_buffer_size=1000000`：与 a1 相同。
- **AMP 观测组成相同**：joint_pos + foot_pos_base + root_lin_vel_b + root_ang_vel_b + joint_vel + root_z
  （参考：joint_pos、foot_pos、base_lin_vel、base_ang_vel、joint_vel、z_pos；**都不含 commands**）。
- 复位时 commands 是随机采样（参考 `legged_robot.py:409-417`，并把 |v|<0.2 置零）——两边一致。
- 终止：我们保留 `illegal_contact`（base 触地终止）；参考的 `termination` 奖励权重为 0。
- 指令范围：我们 x∈(−1,1.5)、y∈(−1,1)、yaw ±1.57，且 `command_levels_* = None`
  （**无课程**，一开始就满量程）；参考 a1 `curriculum=False`，范围默认 ±1。

### 9.1 复核结论

1. **⚠ 单位口径必须先钉死（2026-09-18 更正，取代原先的"双变量"结论）**：上表第一行是**原始权重**，
   第二行才是每步真值。若 Run2 写进配置的 `50 / 17 / −1` 是**原始权重**，则两次运行的**速度项完全没变**
   （原始 50 就等于 `1.0/step_dt`，按 11.1 节换算每步都是 1.0），唯一实质改动是**高度项 −500 → −1
   （弱 500 倍）** ⇒ "趴着滑"由去掉高度惩罚单独解释，「50/17 会趴着滑」这条结论**不成立**。
   反之若 Run2 想表达的是"每步 50/17"，原始权重应写 2500/850，那是比参考（每步 1.5/0.5）大 33 倍的另一类实验。
   **两种可能对应相反的结论，所以下一步不是再跑一次，而是先贴出 Run2 的 `amp_env_cfg.py` 原文确认单位。**
   仓库里既有的单元测试断言 `lin_ps < height_ps`（内部按 `weight × step_dt` 计算）倾向第一种可能。
2. **两次运行的判别器都是死的**（−0.52 / −0.99，AMP loss 0.26 / 0.005）：风格奖励没有在塑造步态
   ⇒ 这才是"只站不走"与"只会趴着滑"这两种退化解的共同背景。Run2 里 `disc=−0.99` 更像是
   **结果**（策略跑到专家流形之外 ⇒ 判别器轻松分开 ⇒ 风格奖励归零 ⇒ 更没人拉它回来）。
   **2026-09-18 补充**：训练侧已在 `b53ffeb` 把 `AMP/disc_expert_pred` 与 `AMP/disc_policy_pred`
   两条原始打分写进 TensorBoard（此前只打印在控制台）。下一轮训练可直接判读：**expert 也显著为负**
   ⇒ 判别器把专家判成假（此时风格奖励必然失效，训练只剩任务奖励在驱动）；**两者分开**
   ⇒ 判别正常，问题在奖励配比/终止而不是判别器。注意本文 11.4 已用离线证据排除了
   "专家速度是世界系"这一种会造成 expert 负分的具体原因，所以若 expert 仍为负，
   下一顺位要查的是 AMP 观测的**量纲/归一化一致性**（`joint_vel` 12 维的真机差分噪声、
   `amp_normalizer` 的统计口径），而不是坐标系。
3. **已排除一条新怀疑**：专家与策略的 AMP 观测**维数与顺序一致**。`AMPLoader` 的
   `get_amp_observation_from_full_frame_batch` 取 `第7..48列（joint_pos 12 + toe_pos_local 12 +
   lin_vel 3 + ang_vel 3 + joint_vel 12 = 42）+ root_pos_z（1）` = **43 维、root_z 在最后**，
   与策略侧 `AMPGroupCfg`（joint_pos, foot_pos_base, root_lin_vel_b, root_ang_vel_b, joint_vel,
   root_z）一致；判别器第一层 store 大小 `2*43*1024*4`（352256 B）也印证 obs_dim=43。**不是错位。**
4. **仍在场的头号嫌疑：专家数据与仿真的"域差"**。`AMPLoader` 对 `lin_vel`/`ang_vel`（第 31–36 列）
   **原样透传、不做任何旋转**，而策略侧是 `mdp.base_lin_vel/base_ang_vel`（**体系**）。录制的
   `imgo2_motion` 是**真机**数据（四元数已确认是 `(x,y,z,w)`；位姿 FK 已核对到 0.002 m，
   **速度场只做过相关性/符号，没核过坐标系与量级**）。若录制里存的是**世界系**速度，判别器仅凭
   这 6 维就能把专家与策略彻底分开 ⇒ 风格奖励必然失效，与 Run1/Run2 的判别器表现一致。
   **验证方法（不用重训，15 行脚本）**：在训练机上把 `preloaded_s`（43 维）与第 0 轮 rollout 的
   `amp` 观测各取一批，**逐维**打印 mean/std（或标准化后的分布差），看哪几维的差距最大——
   预期嫌疑是 `lin_vel`/`ang_vel` 那 6 维（其次 `joint_vel` 12 维，真机差分速度可能偏噪）。
   若确实是坐标系问题，修法是把录制速度旋到体系（或在 loader 里按四元数旋转）后再喂判别器。
   **2026-09-18 复核结果：这条怀疑已排除（本机离线可验，见第 11.4 节）**——三份数据集

   ⇒ **不存在坐标系域差**。
   训练机上原本要做的逐维分布对比可以降级为可选项（仍有价值：找 `joint_vel` 噪声等其他分布差）。

## 10. 速度奖励核：数值对比与建议（2026-09-18）

对方结论「指数核在实际误差处已死（e=1.65、σ=0.5 ⇒ exp(−10.9)≈1e-15），加权不产生梯度」**成立**；
Run2 能动也确实是误差被拉进 σ 敏感区（0.78 m/s）所致，而不是权重的功劳。这一节把可选核的
**值与梯度**摊开，作为单变量实验的依据（本机直接可算）：

| 误差 e | exp,σ=0.5 值/梯度 | exp,σ=1.0 值/梯度 | exp,σ=1.5 值/梯度 | 1/(1+e²/σ²),σ=0.5 | 1/(1+e²/σ²),σ=1.0 |
|---|---|---|---|---|---|
| 0.20 | 0.8521 / 1.3634 | 0.9608 / 0.3843 | 0.9824 / 0.1746 | 0.8621 / 1.1891 | 0.9615 / 0.3698 |
| 0.50 | 0.3679 / 1.4715 | 0.7788 / 0.7788 | 0.8948 / 0.3977 | 0.5000 / 1.0000 | 0.8000 / 0.6400 |
| 1.00 | 0.0183 / 0.1465 | 0.3679 / 0.7358 | 0.6412 / 0.5699 | 0.2000 / 0.3200 | 0.5000 / 0.5000 |
| 1.65 | 0.0000 / 0.0002 | 0.0657 / 0.2168 | 0.2982 / 0.4374 | 0.0841 / 0.0934 | 0.2686 / 0.2381 |

读法：
- **σ=0.5（现状/参考）**：e≥1.0 之后梯度掉到 1e-2 量级以下，e=1.65 时 2.4e-4 —— 这就是"死"。
- **σ 放宽到 1.0（1 行改动）**：e=0 处峰值仍是 1.0（**量级不变，不需要重新归一化奖励**），
  而 e=1.65 时梯度 0.217（**比现状大 900 倍**）、且角速度项同样受益（我们 ang 误差 1.5–2.0 rad/s
  本来也完全没被跟踪）。**首选**：单变量、保持核形状与量级、不动参考既有的 `tracking_sigma` 语义
  之外的东西。
- **σ=1.5**：远场更强（e=1.65 梯度 0.656），代价是峰值附近更平（e=0.2 值 0.983），
  最终跟踪精度会略降；可作为第二档。
- **换成 1/(1+e²/σ²)（柯西核，对方方案 1）**：远场梯度也不错（e=1.65 → 0.093），但形状改变
  （e=0.5 时 0.5 对 0.37），且**不再是参考项目的核**——若之后要与参考对齐会比较麻烦。作为备选。
- **加 −k·|e| 稠密线性项（方案 3）**：梯度恒定、远场最稳，但它**改变目标函数**且容易与核抢权重；
  若要用，必须同时加"低姿态终止"，否则像 Run2 一样"趴着滑"仍是最优（线性项对趴滑同样给分）。

### 11.1 单位口径：为什么"任务奖励差 50 倍"是误读

| 侧 | 代码位置 | 每步奖励怎么算 |
|---|---|---|
| a1（legged_gym） | `legged_gym/envs/base/legged_robot.py:705-710` `_prepare_reward_function()` | 先把**非零** `reward_scales[key] *= self.dt`，`compute_reward()` 再 `rew_buf += func()*scale` |
| go2（legged_gym 另一分支） | `legged_gym/legged_gym/envs/base/legged_robot_amp.py:691-696` | 同一句 `reward_scales[key] *= self.dt` |
| 我们（Isaac Lab） | `isaaclab/managers/reward_manager.py:142-152` | `value = func(...) * term_cfg.weight * dt`，再求和 |

两侧都是"原始权重 × dt"，所以**配置里写的数不是每步值**：

- a1：`tracking_lin_vel = 1.5/(0.005*6) = 50` → 每步 **1.5**（a1 的 `dt = 0.005*6 = 0.03`）；
  `tracking_ang_vel = 0.5/(0.005*6) ≈ 16.7` → 每步 **0.5**。
- go2：`4.0` → 每步 **0.08**；`2.0` → **0.04**；`base_height −1.0` → **−0.02**（dt 0.02）。
- 我们：`1.0/step_dt` → 每步 **1.0**；`0.3/step_dt` → **0.3**；`−10/step_dt` → **−10**。

⇒ **我们的速度项（1.0 / 0.3）与 a1（1.5 / 0.5）同量级，只差 1.5–1.7 倍，不是 50 倍。**
原报告 ③④ 的"差 50 倍"与"把权重 ×50"的建议都建立在这个误读上，已作废（见开头更正框）。
同理，Run2 记录里的 `50 / 17 / −1` 到底是**原始权重**还是**每步值**必须先确认：
按原始权重算，Run2 的速度项与 Run1 **完全相同**、高度项弱了 500 倍（见 9.1-1）。

### 11.4 已离线排除的两条怀疑（新增证据）

用标准库（`json` + 旋转公式）直接读三份数据集即可复核：

1. **速度坐标系域差 ⇒ 不存在**。把相邻帧 `root_pos` 差分得到世界系速度，再用该帧根四元数的**逆**
   旋转到体系，与文件里存的 `lin_vel` 比：
   - **a1 是决定性的**：body 误差恒为 **0.0003 m/s**（说明它的录制脚本就是用**前向差分**
     `p[k+1]-p[k]` 在体系里算的速度），而按世界系直接比是 **0.082–0.352 m/s**；
   - **我们**：在**带转向**的文件上 body 比 world 好 **4.3–7.4 倍**
     （如 `backward_0.5_turn_left_0.5`：0.063 对 0.376；`turn_left_1.0`：0.020 对 0.145）；
     纯直行的文件两种假设几乎一样（1.1 倍）——因为不转向时旋转本来就不起作用，所以"没差别"不构成反证；
   - **go2**：world 与 body 的均值 0.063 对 0.055，数据本身分辨力弱（它的动作几乎都是直行、
     转向文件速度近 0），但它的录制脚本 `datasets/record_legged_control_amp.py:133` 明确写着
     "Base velocities in base frame"。
   ⇒ 三份数据存的都是**体系**速度，与策略侧 `mdp.base_lin_vel/base_ang_vel` 同系，
   loader 原样透传是**正确**的。
   （顺带验证：把四元数解出的偏航角速度与文件里的 `ang_vel_z` 对比，除去 ±π 回绕后一致，
   如我们 `turn_left_1.0` 0.753 对 0.750 rad/s；a1 的 `rightturn0.txt` 自身略有出入 0.80 对 2.27。）
2. **录制速度与标称指令的差距 ⇒ 真实存在，且影响指令设计**。
   逐文件统计 |v_xy| 与偏航率：`forward_0.3/0.6/0.9/1.2` 实测 0.305 / 0.471 / 0.639 / 0.834 m/s，
   `backward_1.2` 1.060，`turn_left_0.5/1.0` 0.364 / 0.753 rad/s ⇒
   真机在 ≈0.85 m/s、≈0.75 rad/s 处就饱和了，文件名里的标称值只是**指令**。
   我们的 AMP 指令范围（x 1.5、yaw 1.57）因此有相当一部分是参考数据无法演示的动作；
   go2 的数据（最大 1.33 m/s、0.82 rad/s）与它自己的指令范围几乎重合。
