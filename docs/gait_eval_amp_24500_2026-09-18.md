## 4. 本轮修掉的测量缺陷（**v1 JSON 中相关字段作废**，共 4 处 + 1 处加载健壮性）

### 4.1 逐环境占空比索引错轴（已修 + 测试锁定）

`per_foot.*.contact_air_fraction_per_env` 原写成 `1 − c[:, e].mean()`，而 `c` 是 `[E, T]`：
`c[:, e]` 取的是**第 e 个时刻、全部环境**的一列，不是第 e 个环境的时间序列。于是它给出的
是「某一时刻有几成环境腾空」＝ k/8 的离散值，v1 里出现 `1.0 / 0.0 / 0.125 / 0.375` 这种
数值，看起来像「7/8 个环境的 RL 足整段不落地」——**那是索引 bug，不是策略行为**。
正确写法是 `c[e].mean()`，且必须满足自洽条件
`mean(逐环境空中占比) == 全样本时间加权空中占比`；现在这条自洽性由
`build_report()` 里的断言强制，并有单元测试覆盖。

**同一份数据里聚合量（占空比/步频/空中支撑时长）是正确的**（它们一直按时间加权算），
所以 §3.1 的数值仍然可用；只有那一列明细作废。

### 4.2 v1 的相位是「单环境 + 首个落地事件」估计，不可用；新版改圆周平均

v1 相位只取 **0 号环境**每只足的**第一个**落地事件，再按周期取模。在周期 0.193 s、`dt = 0.02 s`
下，一个采样点就是 0.1 个周期，加上落地抖动，单次事件无法代表整段；v1 给出
FL/FR/RL/RR = 0.00/0.80/0.41/0.71（FR−FL ≈ 288°），与 Gazebo 同 checkpoint 的 **176.9°** 不符。
改成「**全部落地事件 × 全部环境**对各自环境参考足栅格做圆周平均」，并同时输出集中度 R
（越接近 1 越规整），与 `dt` 无关。另外新版把 **FL-FR 相位（trot 判据）** 和 `gait_period_s`
直接打进摘要与 JSON。

> 修订过程中新版相位一度写成「周期乘 `dt` 换成秒、再与以步为单位的事件下标取模」——
> 合成 trot 立刻算出 0° 而不是 180°，被新增的单测抓住后修掉。这也说明**相位不能只有一次
> 实跑证据**：两次都是靠合成信号才发现的。

### 4.3 `episode_length_mean_steps = 499.5` 是斜坡均值，不含重置信息

`episode_length_buf` 在没有重置时就是 `0…T−1`，它的时间均值恒为 `(T−1)/2 = 499.5`。
v1 把它当成「情节长度约 500 步」来读是错的。判断有没有被中途重置要看 **done 计数**与
**末步缓冲值**：v2 记录 `resets_total` / `resets_per_env` / `episode_length_final_steps_*`
并在摘要里打印。v1 因此**无法确认**回放期间是否发生过终止重置（峰峰类指标是否被重置打断）。

### 4.4 旧字段名 `shank_peak_to_peak_rad` 其实含全部 12 个关节

v1 打印里 12 个值都被标成 shank。v2 增加 `joint_peak_to_peak_rad`（按腿展开），
真正的 shank 是每腿第 3 个（`leg2/5/8/11`）；旧字段名保留但值指向同一份数据。

### 4.5 顺带修的一处 checkpoint 加载健壮性（`map_location`）

`AMPOnPolicyRunner.load()` 原来是 `torch.load(path, weights_only=...)`，**没有 `map_location`**：
在 GPU 机上等价于按存档设备号恢复（自洽），但（a）在另一块 GPU 号上存的 checkpoint 会载不进来，
（b）CPU-only 机器直接报
`Attempting to deserialize object on a CUDA device but torch.cuda.is_available() is False`。
已改成 `map_location=self.device`。**验证边界**：写这一处是为了在本机沙箱做 CPU 冒烟测试，
它确实让加载越过了这一步（随后卡在 PhysX，见 §5 第 1 条）；**GPU 路径按构造是恒等映射（同设备重映射），
但没有在 GPU 上回归过** ⇒ 仍是「已修，待验证」。PPO/HIM runner 有同样写法，本次**未动**。

### 4.6 抬脚高度与前/后腿不对称：v1 数值被出生瞬态污染（**结论已更正**）

v1 没有 `--warmup`，把「出生在 0.35 m、落到稳态 0.31 m」那段也算进足端 z/x 的峰峰值：
机器人在空中时腿是默认姿态、落地后腿压缩，于是足端在 base 系的 z 峰峰值被抬到 0.17–0.18 m。
加 `--warmup=50`（1 s）后同一 checkpoint 的实测是 **0.066–0.083 m**，与参考同速档
（0.083–0.121 m）同量级甚至偏低 ⇒ **「高抬腿」这条撤回**。前/后腿比也从 1.33 降到 **1.10**
（参考前进档 0.87–0.96、后退档 1.01–1.06），属轻微、不再是主要问题。

### 4.7 关节峰峰值全为 0.000：又一次堆叠轴写错（v2 已修 + 加形状校验）

重构时把 `joint_pos` 用 `np.stack(..., axis=1)` 堆成 `[E,T,12]`，而 `build_report` 按 `[T,E,12]`
取 `[:, :, i]`，于是峰峰值算成了「同一时刻跨环境的散布」≈ 0，12 个关节全打印 0.000。
其余指标恰好都是 `axis=0` 堆叠，看起来完全正常，极易漏过。修法：
① 统一成「**时间轴一律在 0**」并由 `_expect()` 严格校验形状，写反直接报错；
② 新增 `test_transposed_input_is_rejected` 等单测。**因此 §1 的 shank/thigh 峰峰值需下次回放重测。**

### 4.8 相位估计器：改用「插值到相邻两个参考落地之间」

v2 的相位仍是取模法：集中度只有 **0.15–0.17**（FL-FR 156°），而 Gazebo 侧同一 checkpoint
是稳定的 ±180°。根因是真实步周期不是整数个仿真步（0.1927 s ÷ 0.02 s = 9.6 步），取模会把
每周期的 0.4 步误差累积上百个周期后抹平圆周平均。已改为把每个落地事件插值到
「相邻两个参考足落地」的区间上（对周期漂移免疫），并用合成漂移周期单测锁定。
**相位与集中度需下次回放重测。**

### 4.9 新增的离线回归

`imgo2_rl/tests/test_gait_metrics.py`（18 项，纯 numpy，无需 GPU）：逐环境聚合顺序、
游程覆盖全时长、落地事件、相位（含半周期 180°、同相 0°、脏事件不被单点带偏）、
峰峰值/逐环境均值、姿态欧拉角与「恒定倾斜」判定、yaw 漂移率区分漂移/摆动、
以及 `build_report()` 的端到端汇总（warmup 切窗、重置计数、时间序列长度）。
