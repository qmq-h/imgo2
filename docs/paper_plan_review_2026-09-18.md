# 评审：`paper_plan_imgo2.md`（未知绳索负载下的瞬态启停控制）

日期：2026-09-18。对象：用户本地未提交的 `paper_plan_imgo2.md`（279 行，已从原「Imgo2 小论文与毕设选题规划」
整体重写；本文件只做评审，不改动那份规划本身）。
评审依据：该规划的正文、本仓库已有的实测证据（[Gazebo 记录](gazebo_ros2_bringup_2026-09-17.md)、
[AMP 对照报告](amp_standstill_diagnosis_2026-09-17.md)、`docs/gait_reference_baseline.json`），
以及公开文献中最接近的几项工作。

## 1. 结论

**方向成立、milestone 顺序正确、定位诚实**，可以作为当前项目的第一个明确 milestone。它是一个
**范围内可做、创新偏窄但真实**的选题：把"未知负载 + 绳索 + 轮式被动负载"的问题收敛到
**启停瞬态**，并把它交给一个**冻结底层 locomotion 之上的 command shaper**。风险不在"做不出来"，
而在"证明这不是一次普通的减速斜坡调参"——这一点规划已经意识到（先做必要性实验、再上 RL），
但**判据仍是软的**（详见 §3.3）。

## 2. 与最近工作的关系（定位核对）

| 工作 | 它做什么 | 与本案的差别 |
|---|---|---|
| Yang et al. 2022，*Collaborative Navigation and Manipulation of a Cable-towed Load by Multiple Quadrupedal Robots*（[ar5iv](https://ar5iv.labs.arxiv.org/html/2206.14424)） | 多四足 + 绳索拖曳**重物**，把负载建成刚体 + 切向/扭转**滑动摩擦**，机器人简化为质点；混合 slack/taut 动力学 + 并行轨迹优化，在线重规划 | 多机、**规划**为主；负载是**被拖在地上的刚体**，不是带脚轮的滚动负载；不研究"人给的速度指令 → 0"的瞬态，也不做负载参数未知下的自适应 |
| *Hybrid Dynamics Modeling and Trajectory Planning for Cable-Trailer With Quadruped Robot System*（[IEEE](https://xplorestaging.ieee.org/document/11244209)） | cable-trailer 的混合动力学建模 + 轨迹规划 | 同样是**系统级规划**视角；用户的定位（"我的尺度更低：full-body locomotion 在负载交互力快变下的响应"）成立 |
| *MULE: Multi-terrain and Unknown Load Adaptation for Effective Quadrupedal Locomotion*（[arXiv 2505.00488](https://export.arxiv.org/pdf/2505.00488v1)） | 四足在**未知负载**下的适应 | 负载是**背在机器人身上**（改变自身动力学），不是通过绳索从外部拖曳；无 slack/taut 与轮子 breakaway |
| *Robust Adaptive MPC for Wheel-Legged Robots Under Unknown Loads*（[IEEE](https://ieeexplore.ieee.org/abstract/document/11376286/authors)） | 未知负载下的自适应 MPC | 负载在机体上、模型预测视角；可为"经典自适应基线"的参照 |

⇒ 规划里"**不要写成首次考虑负载惯性 / 首次考虑 slack-taut**"这条自我约束是对的：
那两件事已被上面第 1、2 项占据。**可以站得住的新意**是：
(a) **单机**、**轮式被动负载**（滚阻 + breakaway 是主导非线性，而非滑动摩擦）、
(b) 关注 **command→0 的卸载瞬态**（0–2 s）而不是稳态拖曳或路径规划、
(c) **冻结底层策略**，只学"现在该加/减速多快"的 **command shaping**。

## 3. 三个必须补的问题（按影响排序）

### 3.1 先定"看得见什么"（可观测性），否则方法与基线都无法定型

规划里的上层输入是 $(v_{\rm user}, v_R, v_{\rm ref}, h_t)$，全是**本体感觉**。但真机上
**绳索张力 $T$ 用一个拉力计就能测**，它恰好是信息量最大的信号。这个选择会改变整篇论文：

- **有张力传感器**：问题更接近 *admittance / 参考调节器*（reference governor），方法可以很务实，
  真机 demo 也更容易；但"未知负载"的难度下降，需要说明为什么仍要学（breakaway 非光滑 + 步态耦合）。
- **无张力传感器**：要从本体感觉（pitch、足端力、$v_R$ 与 $v_{\rm ref}$ 的偏差）**估计**负载状态，
  这本身就是一个贡献点，但风险与工作量都上升。

另外：负载速度 $v_L$ 是否可观测？（无编码器 ⇒ 不可；相机/视觉 ⇒ 可能）。规划里 $v_L(t)$ 是核心曲线之一，
但没写它怎么来。**建议在进入阶段 1 之前把"传感器清单 + 可观测量"写成一张表**：
真机测什么、仿真里怎么模拟该传感器的噪声与延迟。

### 3.2 缺一个经典反馈基线，"为什么用 RL" 会被问死

实验矩阵是 Direct / Fixed Ramp / Adaptive(RL) / Oracle，缺了最强也最容易实现的非学习基线：

$$ a_{\rm ref}=k_p(v_{\rm user}-v_{\rm ref})-k_T\big(T-T^\star\big)\quad(\text{或基于打滑/牵引极限的限制器}) $$

即**用实测张力（或打滑）做反馈的自适应限速/参考调节器**。评审必问："既然有 $T$ 的反馈，为什么要 RL？"
诚实的答法要靠实验：说明在 **breakaway 非光滑 + 步态耦合 + 负载参数未知** 下，固定增益的调节器要么
在轻载时过慢、要么在重载时触发打滑。**建议把它列为与 Adaptive 并列的主基线**，
并再加一个 **per-load 最优固定 ramp（调度器上界）**，用来区分"按负载类别离散适应"与"连续自适应"。

### 3.3 把"必要性"做成可证伪的判据（当前最软的一环）

规划里的论证是"若 $a_{\rm optimal}=f(\text{load dynamics})$，则假设成立"。这句几乎同义反复——
任何系统的最优加加速度都随负载变化，评审不会接受。建议**预先注册**一个定量判据，例如：

- 在负载网格 $m_L\times F_{\rm rolling}\times v_0$ 上，**单一最优固定 ramp** 相对"每负载最优 ramp"
  在 $\max|\dot T|$ 或 $D_{\rm robot-stop}$ 上损失 **≥ 20%**，**或**在响应时间（到 90% 指令速度）上多花 **≥ 0.5 s**；
- 或者画 **安全-响应 Pareto 前沿**：横轴"响应时间"、纵轴"$\max|T|$ / 打滑 / $\max|\theta_{\rm pitch}|$"，
  证明**前沿本身随负载平移**，因此任何单点固定 ramp 都不在 Pareto 前沿上。

**这条建议同时把论文的核心图定死了**：不是"我们训了一个 RL"，而是"**固定 command smoothing 的
安全-响应前沿随未知负载平移，因此需要负载自适应 shaping**"。这比"$a_{\rm optimal}$ 随负载变化"强得多。

## 4. 仿真与物理细节（会直接影响结论可信度）

1. **绳模型刚度会主导 $T_{\rm peak}$**。Kelvin–Voigt $T=\max[0,k(d-L)+c\dot d]$ 在 slack→taut 瞬间是
   一次带相对速度的碰撞式接触，$T_{\rm peak}$ 主要由 $k$ 与相对速度决定（量级 $\sim v\sqrt{k\,m_L}$），
   **与控制器关系不大**；而且仿真步长必须满足 $\Delta t \lesssim 1/(20\sqrt{k/m_L})$，否则冲量随步长漂移。
   必须：(a) 由绳索物理估 $k=EA/L$、$c$ 由阻尼比定；(b) 报告 $k,c$ 敏感性（例如 $k$ 取 50/200/800 N/m 三档）；
   (c) 或改用带应变率限制/非线性硬化的绳模型。否则"降低 $T_{\rm peak}$"这个主指标站不住。
2. **滚阻/breakaway 的数值处理**。$-\tau_c\operatorname{sgn}(\omega)-b\omega$ 在 $\omega\approx0$ 会抖振，
   且 breakaway 需要一个**静平衡分支**：当 $|\tau_{\rm applied}|<\tau_{\rm breakaway}$ 时强制 $\omega=0$。
   建议用 Stribeck 正则化 $\tau_c\tanh(\omega/\omega_s)$ + 显式静摩擦判定，并把"cart 单独滑行"
   （阶段 5）与**解析解**对齐：$D_{\rm stop}=\frac{m_L v_0^2/2}{\tau_c/r_{\rm wheel}}$（无 $b$ 时），
   作为模型验证的硬指标。
3. **4 个固定轮 ⇒ 横向刮擦**。直拖没问题，但姿态一旦偏航，四个固定轮会产生巨大的横向阻力
   （非完整约束冲突），cart 会 crabbing、绳力方向不可控。建议阶段 1 明确二选一：
   (a) 把 cart 约束成沿直线运动（锁横向 + 锁 yaw，并在文中写明这是 phase-1 简化）；
   (b) 改成 2 万向 + 2 固定，或把 swivel caster 从阶段 17 提前。
4. **机器人自身牵引极限没进模型**。缺 $\mu$（足-地摩擦）与可用牵引 $F_{\max}\approx\mu N_{\rm drive}$：
   没有它，"foot slip" 没有可控来源，也无法界定"拖不动"的边界。建议加入无量纲比值
   $F_{\rm req}/(\mu N_{\rm drive})$，先做一次**静力学可行性分析**，得到"可拖 / 打滑 / 不可拖"的
   区域图（regime map）——**它同时给参数扫描划了合理范围**，扫描就不再是拍脑袋。
5. **Go2 还是 Imgo2 必须二选一**。规划写的是 Go2 + rope + cart；本仓库的机器人是 Imgo2。
   - 选 **Go2**：Isaac Lab 有现成资产，参考项目里有能走的 Go2 策略，若有真机则论文强度大幅提升（推荐）。
   - 选 **Imgo2**：冻结的底层策略就是瓶颈——本机实测（Gazebo，每条命令一条新栈）：我们自己的 AMP
     在 $v\ge1.0$ 跟速 97–99%，但 $v=0.5$ 只有 76%、$v=0$ 还漂 0.047 m/s、步态周期 0.21–0.46 s
     （参考动作是恒定 0.600 s / 1.67 Hz，见 `docs/gait_reference_baseline.json`）。而**"卸载/停止"瞬态
     恰好落在低频段工作区**，即底层策略最弱的区域。若坚持 Imgo2，建议低速段用键 1 的 PPO（0.5 → 93%、周期强度 0.96）
     或把"底层策略的可用包线"作为研究的前置结论写进论文。
6. **真机参数测量应当提前**。阶段 18（拉力计测 breakaway/rolling）是阶段 2/6（轮阻模型 + 参数扫描）的输入，
   现在排在很后面。建议把它提到扫描之前（顺手也测绳子的 $k,c$：一次拉伸试验即可）。

## 5. 规划里没写、但很可能是"最好的那个现象"

**停车后的负载追尾（overrun）。** 指令 $v\to0$ 后，机器人减速、绳会松，而**负载靠自身动量继续滑行**；
如果它的残余动能超过当前松弛余量 $(L-d)$，cart 会**撞上机器人并推它**（真机上就是事故）。
这让"平滑卸载"变成一个**有硬约束的真问题**：停车剖面必须保证
$\int(v_L-v_R)\,dt \le L-d_{\rm attach}+\text{余量}$，或者策略必须**故意保持一点前向蠕动**
让负载把动能耗掉再停。建议：

- 指标新增：停车阶段的**最小机器人-cart 距离**、**松弛余量消耗比例**、**绳再绷紧次数/冲量**；
- 把它写成研究问题的一部分（"在有限停车时间/距离约束下平滑退出拖曳"这条规划里已经提到，
  但没意识到"追尾"是它的主要失败模式）。**若参数扫描里真的出现追尾，这会是论文最漂亮的一张图**，
  也天然解释了"为什么不能简单地把 $a_{\max}$ 调小"（调小只是把问题推迟到停车段）。

## 6. 实验矩阵与指标的具体补充

- 基线：Direct / Fixed Ramp / **经典反馈调节器** / **per-load 最优 ramp** / Adaptive(RL) / Oracle。
- 指标：现有 $T_{\rm peak}$、$\max|\dot T|$、$D_{\rm robot-stop}$、$t_{\rm stop}$、$\max|\theta_{\rm pitch}|$、
  foot slip、velocity tracking、torque/energy 之外，补
  **命令响应延迟（到 90% 指令速度的时间）**、**绳松弛余量消耗/再绷紧冲量**、**后腿峰值关节力矩**
  （pitch 扰动的传导路径）、**偏航偏差**（单绳后挂点会横向拽机头）。
- **归一化**：$T_{\rm peak}/(m_L g)$、$\dot T/(m_L g/{\rm s})$，否则不同负载的数字不可比。
- 协议：≥5 个种子/配置、测试集用**未见过的** $m_L,F_{\rm rolling},L,k$、DR 范围与训练范围分开报告。

## 9. 建议的"最近一步"（对规划第 6 节的小修正）

同意 `Cart → Passive Wheel → Rope → Go2 towing → Direct Stop → 参数扫描` 的顺序，只加三条：

1. 先把**传感器清单**与**静力学可行性区域**（$F_{\rm req}/(\mu N)$）做出来；
2. **经典反馈调节器基线**要在上 RL 之前就位（否则 §3.2 的问题会被评审直接击中）；
3. **预先注册必要性阈值**，并把**追尾/松弛余量**加进指标——这两条决定"假设是否成立"的定义，
   一旦扫描结果出来再改就来不及了。
