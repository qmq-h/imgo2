## 起步/停车窗口（各 1 s）：负载有没有带来「关节冲击」？

| 分组 | n | 起步 RMS | 起步**峰值** | 停车 RMS | 停车**峰值** | 力矩饱和占比 | 速度过冲 | 90% 到位时间 | vx RMS 误差 |
|---|---|---|---|---|---|---|---|---|---|
| 拖曳 全部 | 700 | 0.218 | **0.877** | 0.154 | **0.537** | 0.0000 | +0.009 | 0.20 s | 0.405 |
| 无负载 全部 | 100 | 0.191 | **0.876** | 0.151 | **0.557** | 0.0000 | +0.138 | 0.55 s | 0.293 |
| 拖曳 0.5 / 1 / 1.5 m/s | — | 0.169 / 0.218 / 0.249 | 0.593 / 0.877 / 0.926 | 0.145 / 0.155 / 0.164 | 0.421 / 0.542 / 0.681 | 0 | +0.130 / +0.072 / **−0.057** | 0.17 / 1.15 / 0.75 s | 0.159 / 0.405 / 0.711 |
| 无负载 0.5 / 1 / 1.5 m/s | — | 0.161 / 0.191 / 0.226 | 0.591 / 0.876 / 0.926 | 0.148 / 0.152 / 0.167 | 0.454 / 0.563 / 0.760 | 0 | +0.142 / +0.138 / +0.103 | 0.17 / 0.57 / 0.55 s | 0.135 / 0.293 / 0.500 |

（完整表见 `windows_and_crossings.txt`。）

结论：

1. **起步/停车没有"关节冲击"**：起步**单点峰值 0.877（拖）vs 0.876（无）**、停车 **0.537 vs 0.557（无负载更高）**；
   RMS 只多 **+0.027 / +0.003 rad**。**峰值只随速度变**（0.59→0.93，两侧一致），不随负载变。
2. **不是"PD 硬扛"**：两侧 `torque_saturated_frac` 都是 **0**（|τ|max 远低于 23.7 N·m）；
   拖曳对关节力矩的额外要求只有 ~0.3 N·m（分段表 `平均|τ|` 2.80 → 3.13），折算静差 0.3/25 ≈ 0.012 rad ✓
   与实测 `Δ静差` 0.001–0.018 同量级 ⇒ **PD 本来就留了 `τ/kp` 的静差，负载只把它推大一点点**。
3. 负载的代价在**跟速**：`Δ|vx−cmd|` 最大 +0.32 m/s（10° 上坡），而且 **90% 到位时间**从 0.55 s 拖到
   1.15 s（1 m/s 档）、1.5 m/s 档的速度过冲甚至变成 **−0.057**（那一秒内根本没到指令）。

## 「过冲」到底在哪个字段：口径澄清

- **本测试台没有"关节过冲"这个量。** `startup`/`stop` 的关节字段只有 `joint_rms_rad`（池化 RMS）、
  `joint_max_rad`（窗口内**单点最大** |q − q*|，是**最大偏差**不是过冲）、`worst_joint`、
  `per_joint_rms_rad`、`torque_saturated_frac`。
- 唯一叫 overshoot 的是 **`startup.overshoot_ratio`，定义是速度**：
  `max(robot_vx_b_mps 在起步窗口内) / 指令 − 1`（负值 = 那 1 s 内没到指令，是**滞后**不是过冲）。
- 仓库里其它"过冲"都不是关节：`summarize_tow` 的「绷直过冲」是**绳张力**瞬态；
  `docs/gait_eval_amp_24500_2026-09-18.md` 的「摆动过冲」是**足端轨迹**；
  `rope_model.py` 的 `position_gain ≤ 1` 是防**绳约束**过冲。
- 用「最接近过冲」的可用定义补算（`--crossings`，反号样本占比 + 越界量 p95）：

  | 分组 | 起步(前 1 s) 越过设定点占比 / 越界量 p95 | 停车(前 1 s) 占比 / p95 |
  |---|---|---|
  | 拖曳（70 抽样） | 34.7% / 0.115 rad | 13.3% / 0.049 rad |
  | 无负载（70 抽样） | 33.6% / 0.112 rad | 12.1% / 0.058 rad |

  ⇒ 两边几乎一样（差 1 个百分点、0.003 rad），与"负载没带来关节冲击"一致。
  ⚠️ 这些穿越主要来自 **`q*` 每 20 ms 被策略改写**，不是欠阻尼过冲（PD 为 kp=25 / kd=0.5，阻尼比很大）。
- 要**严格**的关节过冲指标得先定义（`q*` 不是阶跃）：① 单拍阶跃过冲（把每拍 `q*` 变化当阶跃，
  看随后几拍越过幅度/占比）；② 瞬态 `Mp = (max q − q_ss)/(q_ss − q_0)`。两者都能用现有
  `--write-csv all` 轨迹离线算。**当前状态：未实现，报告里也不给这个量。**

## 已知瑕疵（不影响上面的结论）

1. `_nocart` env 的**小车运动类字段**（`cart_coast_distance_m` / `cart_coast_to_rest_m` /
   `cart_speed_at_stop_mps`）仍照算但**没有意义**（小车停在 2 m 外、绳力为 0）；判定侧已中性化
   （无负载 env 不产出 `COL`/`LOW`），但报告里这些数要看 `case.cart_present=false` 就跳过。
   下一轮在 `compute_case_metrics` 里把它们一并置 `None`。
2. **「平地(出口)」段两轮都没有样本**：5 s 内只有 1.5 m/s 档接近 9 m ⇒ 想看出口平地段需
   `--tow-duration` 8–10 s。
3. 拖曳段的「坡顶/下坡」样本行数少（1.5 m/s 专属），按 `(段, 速度)` 单元比较才严格；
   本目录的 `stats.txt` 里有每一边的「段 × 速度」矩阵可用于该口径。
