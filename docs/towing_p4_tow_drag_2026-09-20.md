## 2. 场景与布局约定

- 机器人在前、小车在后，两者都朝 **+x**；速度指令为正即向前拖。
- 机器人挂点：base 坐标系的 `(-0.16, 0, 0)`。依据：base 碰撞箱长 0.315 m
  （`urdf/imgo2.urdf`）⇒ 后表面在 x = −0.1575 m，取 −0.16 略过后表面。
  **工程取值，没有实测挂点**；换实物尺寸只改 `ROBOT_ATTACHMENT_OFFSET_M`。
- 小车挂点：`cart.urdf` 的 `rope_attachment`，车体坐标 `(+0.25, 0, 0)`（前轴之前）。
  小车在后时该点朝向机器人 ⇒ 受力方向与拖曳一致。
- 绳长 `L0` 默认 **0.8 m**（`--rope-length`）、`--slack` 默认 **0.40 m** ⇒ 初始挂点间距 **0.40 m**。
- 初始挂点间距 = `L0 − slack`：`--slack` 既是**松了多少**，也等于**机器人要走多远绳才发力**，且 slack 越大两者初始越近。默认 `slack = 0.40 m` ⇒ 间距 0.60 m、机器人走 0.40 m（0.5 m/s 下 0.8 s）后绳才张紧发力。`cart_x_for_attachment_gap()` 实现该算术，
  测试用**场景常量 + `cart.urdf` 实读挂点**反解校核：间距必须等于 `L0 − slack`
  （差一点初始张力就错了，所以这条专门锁住）。
- 机器人初始高度用显式参数 `--spawn-height`，默认 `ROBOT_SPAWN_HEIGHT_M = 0.35 m`
  （= 训练侧 `IMGO2_CFG.init_state.pos` 的 z）。README 记录过「训练多数从录制帧
  ≈0.297 m 起、play 从 0.35 m 起」可能对应**高/低两个稳定站高分支**，因此这里不写死，
  由训练机确认哪一个给出可复现的稳定拖曳。
- 关节初始角按契约的 `default_dof_pos` 给（与 `IMGO2_CFG` 一致），不使用随机初始状态。

## 3. 每物理步的顺序与力臂处理

与 P1/P2 相同（显式欧拉，力的口径一致）：

```text
按当前状态算绳力（P3 的 rope_state）与轮阻（-b·ω）
  → robot/cart.set_external_force_and_torque(...) / cart.set_joint_effort_target(...)
  → scene.write_data_to_sim() → sim.step() → scene.update(dt) → 记录
```

- **力臂交给仿真**：`set_external_force_and_torque(positions=...)` 的作用点坐标是**连杆坐标系**
  （`articulation.py` 的 `apply_forces_and_torques_at_position` 真正消费它），所以直接把挂点
  常量传进去，由 PhysX 自己算力矩，不手写 `offset×F`，也不用纠结 CoM 约定
  （实测 `base` 的惯性原点偏移 < 3 mm）。**整套调用必须用同一个 `is_global` 口径**，
  否则 Isaac Lab 会警告并改变全体的作用坐标系；这里统一用默认的连杆系。
- 力本身从世界系转到连杆系用 `quat_apply_inverse`。
- 绳数学走 `rope.py` 的**标量路径**（`num_envs = 1`），即已经被 31 项测试覆盖的那条路径。
- 策略抽帧：`decimation = round(control_dt / dt)`，契约要求 `control_dt` 是物理 `dt` 的整数倍，
  不满足直接报错。默认两者都是 0.005 s ⇒ 1:1。
- 启动时会核对：关节数、**关节名与顺序**是否与策略契约完全一致、`base`/`base_link` 唯一、
  小车四关节与四轮接触；不一致立即报错（而不是跑到一半形状不匹配）。

## 4. 运行与判据

**多组合扫描：同一进程内顺序跑完**（`--cart-mass` × `--wheel-damping` 的笛卡尔积）。
每个组合一个 `case_NN_m<质量>_b<阻尼>/` 子目录（含 `config.json`/`tow.csv`/`summary.json`），
运行根目录另写 `sweep.json` 汇总。**为什么不是并行多 env**：地面摩擦是**共享**的地面材质，
要按 env 区分就得给每个 env 单独建地面 prim；而重复启动 Isaac Sim 才是主要开销（每次 ~15 s），
所以先做「一次启动、顺序多例」，与 P1/P2 的 `cart_coast.py` 同一模式。

```bash
cd imgo2_rl
# 稳定拖曳（计划 P4）
bash scripts/run_isaaclab.sh scripts/towing/tow_drag.py --velocity 0.5 --duration 5 --headless

# 阶跃停止（计划 P6）：拖 5 s 后指令归零，机器人停下、小车继续滑行
bash scripts/run_isaaclab.sh scripts/towing/tow_drag.py --velocity 0.5 --duration 10 --stop-at 5 --headless
```

**启动时会打印追尾预判**（不拦，只警告——计划 P6 本来就想观察「追尾」）：

```text
[PLAN] L0=0.8 m, v=0.5 m/s, b=0.016 ⇒ 预测停车后小车滑行 0.518 m，最小间距 +0.282 m
```

预判用的是 P2 已经验收过的黏性衰减解析式 `D = v0·τ·(1 − v_stop/v0)`、`τ = m_eff·r²/(4b)`
（P2 的 8 个工况实测吻合 **0.27%–0.96%**）。**L0 / 速度 / 轮阻必须一起选**：

| b（每轮） | v=0.5 滑行 | v=1.0 滑行 |
|---|---|---|
| 0.008 | 1.037 m | 2.117 m |
| 0.016 | 0.518 m | 1.058 m |
| 0.032 | 0.259 m | 0.529 m |

`最小间距 = L0 − 滑行距离`。所以 0.5 m/s + b=0.016 时 L0=0.8 留 **+0.28 m**；而
**v=1.0 m/s + b=0.016 时即使 L0=1.0 也会追到机器人**（−0.06 m）——那一步要改用
`--wheel-damping 0.032`（滑行 0.53 m）或加长 L0。

**可视化（去掉 `--headless` 即可）**：`SimulationContext.step()` 默认 `render=True`，所以
非 headless 会正常刷新视口，不需要额外代码。相机由脚本用 `sim.set_camera_view()` 设死
（拖曳场景为眼位 `(2.5, 2.5, 1.8)`、注视 `(-0.7, 0, 0.2)`），而机器人/小车会沿 +x 走 2–3 m，
**长跑会出画**，需要时在窗口里手动移相机。

```bash
# 看「机器人停下、小车滑行」这一幕（计划 P6）
bash scripts/run_isaaclab.sh scripts/towing/tow_drag.py --velocity 0.5 --duration 10 --stop-at 5
# 看小车落地与滑行（P1/P2）
bash scripts/run_isaaclab.sh scripts/towing/cart_coast.py --mode drop --duration 3
bash scripts/run_isaaclab.sh scripts/towing/cart_coast.py --mode coast --velocities 1.0 --damping 0.016 --duration 10
```

播放速度取决于渲染帧率与物理 `dt` 的比值，可能快于实时；想慢一点用 `--dt 0.0025`
（P2 的 dt 复核显示停止距离只变 0.23%）。暂停会阻塞 `sim.step()`，画面保留、可慢慢看。

产物在 `imgo2_rl/logs/towing/tow_drag/<run_id>/`：`config.json`（含策略/模型哈希、绳参数、
抽帧、挂点）、`tow.csv`（逐物理步）、`summary.json`、`experiment.json`。
`--output-dir` 只能指向尚不存在的目录。

### 5.1 训练机第一次实跑暴露的问题：Isaac Lab 的 DOF 顺序 ≠ 策略顺序

第一次实跑（2026-09-20）在启动时的契约核对就报错退出，报告的两份顺序是：

```text
模型（PhysX）: FL_hip, FR_hip, RL_hip, RR_hip, FL_thigh, FR_thigh, RL_thigh, RR_thigh,
               FL_shank, FR_shank, RL_shank, RR_shank      ← 全部 hip → 全部 thigh → 全部 shank
契约（策略）  : FL_hip, FL_thigh, FL_shank, FR_hip, ...     ← 逐腿
```

**根因**：Isaac Lab / PhysX 的 DOF 顺序按运动学树**广度优先**排列，而 `urdf/imgo2.urdf`
是**逐腿**声明（FL hip/thigh/shank, FR …）。AMP 任务在 `amp_env_cfg.py` 里把策略的观测
（`observations.policy.joint_pos/joint_vel`）与动作（`actions.joint_pos.joint_names`）都
**显式**设成逐腿顺序，所以训练出来的策略按逐腿顺序收发关节量，而 Isaac Lab 的资产数组是
广度优先顺序 —— **两者必须显式置换**。

**这不是契约错、也不是模型错，是运行端漏了重排**。第一版把「模型关节顺序」与「策略关节
顺序」直接比较并要求相等，于是启动即失败；若当时改成「把契约顺序改成广度优先」来消掉报错，
就会让观测拼错、动作打到错误的关节上（**静默且致命**）。

**修法**：`policy_cfg.asset_permutation(asset_joint_names)` 比对关节**集合**并给出
「策略第 i 个 ↔ 资产第 perm[i] 号」的置换；入口用它把 `joint_pos`/`joint_vel` 重排进观测、
把策略输出的关节目标换回资产顺序再下发。另外用**一条强校验**确认置换是对的：资产
`default_joint_pos` 按置换重排后必须等于契约的 `default_dof_pos`
（URDF 用正则把 hip/thigh/shank 统一设成 0/0.87/-1.82）。
置换与会话两端顺序都写进运行配置的 `config.json`，便于事后核对。

**回归覆盖**：`test_towing_policy_contract.py` 的 `JointOrderTests` 用**实跑报告的那份
真实顺序**做固定样例，断言置换是合法重排、关键下标（策略 FL hip/thigh/shank → 资产 0/4/8）、
恒等置换会错（资产第 1 号是 FR_hip）、重排后能复现契约默认姿态、以及 URDF 声明顺序确实
与 Isaac Lab 顺序不同（记录差异来源）；`test_towing_tow_drag.py` 另加源码契约，禁止退回
「直接比较关节名列表」的写法。

### 5.2 第二次实跑暴露的问题：记录器与入口都建运行目录

第二次实跑（`20260920T142354Z_38639b47`）已经**通过了关节顺序检查**（说明 §5.1 的修复生效），
但随即报：

```text
[FAILED] FileExistsError: [Errno 17] File exists:
  '/root/Desktop/Imgo2/imgo2_rl/logs/towing/tow_drag/20260920T142354Z_38639b47'
```

**根因**：目录归属在两处重复。`main()` 在开头就用 `output.mkdir(parents=True, exist_ok=False)`
独占创建运行目录（保证新运行绝不落进已有目录），而 `TowRecorder` 照抄了 `CartRecorder` 的
「自己建目录」语义又建了一次 ⇒ 自己撞自己。`CartRecorder` 服务「一个运行里多个 case 子目录」，
每个实例收到的是**尚不存在**的子目录；拖曳运行只有一个目录，我把它传给了 recorder。

**修法**：明确职责——运行目录由入口用 `exist_ok=False` **独占创建**，`TowRecorder` 只负责
写入，并要求目录已存在、拒绝覆盖已存在的 `tow.csv`/`config.json`。

**为什么离线没抓到**：当时的单测只**单独构造 recorder**（沿用了 `CartRecorder` 的用法），
没有覆盖「入口先建目录、再交给 recorder」这条集成路径。现已补上三条：
`test_accepts_an_already_created_run_directory`（模拟入口已建目录）、
`test_requires_an_existing_directory`、`test_refuses_to_overwrite_existing_artifacts`，

### 5.8 修 `UnboundLocalError`：阶段算术抽成纯函数

上一提交加的 `--stop-at` 引入了一个**先用后赋值**的错误：

```text
[FAILED] UnboundLocalError: cannot access local variable 'stop_steps' where it is not associated with a value
```

`stop_steps` 在 `config` 字典里被引用（算 `tow_phase_s`/`coast_phase_s`），而它的赋值写在
字典**之后** —— `main()` 只有跑仿真才会执行，所以 213 项离线测试全过、一跑就崩。

**修法**：不再把这段算术内联在 `main()`，抽成纯函数 `make_schedule()` / `PhaseSchedule`
（含 `phase_of()` 与三段的步数），`main()` 只拿结果用。算术进入离线测试覆盖后，
这类顺序错误不会再静默发生：

- `ScheduleTests` 6 项：三段步数、无 `--stop-at` 时 `coast=0`、**station→tow 与 tow→coast
  的边界下标**（包括阶跃点那一步）、`coast` 段样本计数自洽、退化输入报错；
- 源码契约：`schedule = make_schedule(` 必须早于 `config = {`，且不允许再出现内联的
  `stop_steps` / `total_steps` 局部量。

**教训记录**：AST/字符串契约测试与纯标准库测试都**抓不到**「只在仿真路径里执行的顺序错误」。
可用的 lint 工具（pyflakes/flake8/ruff）在本机都没有装，所以当前的防线是
「把可测的算术搬出 `main()`」+ 关键顺序写成契约。

| 站定段张力峰值 | **0.0000 N** | — |

即：**出生高度回到 0.35 m、松弛放到 0.40 m 之后，站定阶段小车本来就不动**（张力全程为 0，
所以没有任何东西推它）。而 `reset_cart_for_tow()` 是按**机器人当前位置**解算的，机器人窜了
0.097 m，于是把小车往前挪 0.081 m，`scene.update` 之后还带来 −0.039 m/s 的速度——
**它把一个已经正确的初始条件弄坏了**，并且这个「传送」在可视化里也是可见的跳变。

**修法**：删除 `reset_cart_for_tow()`（连配置里的 `cart_reset_at_tow_start` / `cart_reset_note`
与循环里的 `tow_started` 一起删），初始条件改由「设计保证 + 事后检查」：
出生高度 0.35 m + slack 0.40 m 让绳在站定段拉不直，小车因此自然静止在设计位置。

**判据替代强制**：新增 `load_moved_during_settle`（站定段小车位移 > 0.02 m 即失败），
与既有的 `rope_taut_during_settle`、`robot_lurches_during_settle` 一起守住这条性质——
**不再用代码强行摆正，而是让跑完的判定来发现它**。

用真实轨迹复算运行 `a07c6662`：站定段小车位移 **−0.000002 m**、张力峰值 **0.0000 N**、
机器人窜动 **+0.0967 m**（< 0.15 阈值）⇒ `failures = []`。

**由此也确认了「拉近」的真实收益**：`slack` 让绳在站定段不必张紧，小车才会老老实实待着；
之前的 0.24 m 自漂是绳被拉直造成的，与小车生成方式、与是否需要重置都无关。

### 5.12 支持重量/摩擦参数，并记录「是否追尾」与「最终停车距机器人多远」

**新增参数**：

| 小车质量 | b=0.016 | b=0.032 |
|---|---|---|
| 5 kg | 0.259 / **+0.541** | 0.130 / +0.670 |
| 10 kg | 0.518 / **+0.282** | 0.259 / +0.541 |
| 15 kg | 0.778 / **+0.022** ⚠ | 0.389 / +0.411 |
| 20 kg | 1.037 / **−0.237** ⚠撞 | 0.518 / +0.282 |
| 25 kg | 1.296 / **−0.496** ⚠撞 | 0.648 / +0.152 |

**摩擦扫描的预期**：摩擦**不耗散轮子的滚动**，停车距离由轮轴阻力 `b` 决定，所以不同

`PlanTimeOrderingTests`——用 AST 按源码顺序检查 `main()` 里的局部量不得「先用后赋值」。
**这个守卫是补上来的**：`stop_steps` 与 `scale` 已经各踩过一次（都只在跑仿真时执行、
离线测试全过、一跑就 `UnboundLocalError`），而注释里出现同一个词会让朴素的字符串检查假阳性。

### 5.13 多 case 扫描：一次启动跑完重量 × 轮阻的组合

用户要求「headless 跑就行，每次早点 reset，或者多开 env」。据此把入口改成**一次启动、
进程内顺序跑完所有组合**：

- `--cart-mass` 与 `--wheel-damping` 都接受**多个值**（`nargs="+"`），笛卡尔积即 case 列表
  （`sweep_cases()`）；单词形式仍然可用，所以之前给的命令不变。
- 每个 case 一个 `case_NN_m<质量>_b<阻尼>/`（`cart_coast.py` 的命名风格），
  内含 `config.json`/`tow.csv`/`summary.json`；运行根目录另写 `sweep.json`（逐 case 结论 +
  `all_valid`）。判读仍走 `summarize_tow.py`，所以每个 case 都能离线复算。
- 质量/惯量以**启动时读到的名义值**为基准逐 case 缩放（`nominal_masses`/`nominal_inertias`），
  不能读回上一次的结果，否则会累积。

**关键：逐 case 必须显式复位。** `Articulation.reset()` **只清执行器与外力缓冲，不写位姿**
（IsaacLab `articulation.py:172` 已核对），所以 `reset_case()` 里要自己写两个刚体的
root pose/velocity 与关节状态（与 P1/P2「每个 case 前重写小车状态」同一约定）。
这与 §5.10 删掉的「拖曳段中途传送」不同：那是运行中途按机器人当前位置挪小车、会掩盖问题；
这里是每个 case 的初始条件。

为什么**没有**做并行多 env：地面摩擦是共享的地面材质（要按 env 区分得给每个 env 单独建
地面 prim），而重复启动 Isaac Sim（每次约 15 s）才是主要开销——一次启动顺序跑完就把它去掉了
（15 个组合从约 5 分钟降到约 1.5 分钟）。若还需要更快，可以把质量与轮阻维度真正并行到多个
env（这两者都能按 env 设置），留作后续。

对应的 0.5 m/s 扫描命令见 §4。

### 5.14 第一次重量扫描的实测结果与一个新发现的模型偏差

> **2026-09-21 更正（详见 §5.17）**：本节第 3 条结论（「低速段存在模型外的额外耗散」）
> **是错的**。逐帧核对发现那些「提前硬停」是**撞到机器人**：黏性衰减常数与预测吻合到
> 0.14%~4.4%，滑行段没有额外耗散；实测滑行远小于预测的每一行都对上了撞击事件。
> 表里的「追尾=否」是**假通过**——那一列当时用挂点间距判定，而撞击时的挂点间距在
> 0.34~0.37 m，看不出碰撞。25 kg 那行实际撞上了，20 kg 已接近到 0.3528 m。

用户跑完两批 0.5 m/s 的扫描（`git af3ce2e`，均 `state=completed`）：

**重量扫描**（`--cart-mass 5 10 15 20 25 --wheel-damping 0.032`，L0=0.8、slack=0.40、`--stop-at 5`）：

| 质量 | 跟速比 | 稳态 T | 最小间距 | **最终间距** | **追尾** | 实测滑行 | 预测滑行 | 偏差 |
|---|---|---|---|---|---|---|---|---|
| 5 kg | 0.945 | 10.09 N | 0.396 | **0.667 m** | 否 | 0.136 | 0.130 | +0.007 |
| 10 kg | 0.945 | 10.09 N | 0.396 | **0.540 m** | 否 | 0.262 | 0.259 | +0.003 |
| 15 kg | 0.946 | 10.13 N | 0.396 | **0.444 m** | 否 | 0.398 | 0.389 | +0.009 |
| 20 kg | 0.947 | 10.08 N | 0.349 | **0.353 m** | 否 | 0.515 | 0.518 | −0.003 |
| 25 kg | 0.947 | 10.11 N | 0.343 | **0.343 m** | 否 | 0.515 | 0.648 | −0.133 |

**低轮阻**（`--wheel-damping 0.008`，名义 10 kg，预测滑行 1.037 m > L0=0.8 ⇒ 预期追尾）：
实测滑行 **0.491 m**、最小间距 0.363 m、**追尾=否**、`valid=True`。

三条结论：

1. **5 例全部 `valid=True`、无追尾**，跟速比一致（0.945–0.947），稳态张力几乎不随质量变化
   （10.08–10.13 N）——这与 §5.5 的发现一致：稳态张力由**绳阻尼项 `c·ḋ` 对步态纹波的响应**
   主导，而不是准静态拖曳阻力（`4b·v/r` 只有 0.76 N）。改 `b` 才会明显改变它
   （b=0.008 时稳态 T=2.85 N）。
2. **短滑行段与解析预测吻合到 1% 以内**（5/10/15/20 kg 的偏差 +0.003…+0.009 m），
   说明 `-b·ω` 力矩与质量/惯量同比例缩放的实现是对的。
3. **长滑行段（b 小、质量大）实测比预测短很多**（25 kg −20%、b=0.008 −53%）。

对第 3 条做了逐帧核对：**衰减常数与预测完全吻合**（实测 τ 2.162 s 对预测 2.160 s；
1.354 对 1.350），但小车在 **v ≈ 0.1–0.3 m/s 时提前硬停**（b=0.008 那次 1 s 时 v=0.339
（τ 吻合），2 s 时已降到 0.008，而纯黏性模型此刻应为 0.213）。已排除的可能：

- **不是隐藏摩擦**：`cart.urdf` 的关节是 `damping="0" friction="0"`，生成时
  `joint_drive` 增益为 0、刚体 `linear/angular_damping=0`；更关键的是 **P2 实测 b=0 时
  10 s 走 10.0002 m、末速 1.00002 m/s（完全不减速）**。
- **不是测量窗截断**：25 kg 那次在 +3 s 就停了（窗口 5 s）。
- **不是质量没生效**：20 kg 与 25 kg 的实测滑行几乎相同（0.515 vs 0.515），但 5→15 kg
  按质量线性增长且与预测吻合 —— 恰是「额外低速阻力在长滑行段占主导」的表现。

⇒ 低速段存在**模型外的额外耗散**（黏性项之外，可能是接触静摩擦/滚动锁定一类），
它使预测**偏保守**（高估滑行距离）——所以「追尾=否」的结论是可信的，但预测的余量偏悲观。

**诊断手段已补**：往 `tow.csv` 加四个轮速 `wheel_*_omega_radps`（`v/r` 与 ω 的比值能区分
滚动与滑动）。此前没记轮速，无法判断低速段是「轮子被接触锁住」还是别的机制。下一次
b=0.008 / 25 kg 这类长滑行工况跑一遍即可定位。

### 5.15 修「跑完不退出」：成功路径也要显式 `os._exit`

用户跑摩擦扫描时报告「每次不会终止，所以 for 不会进入下一个」。查产物：

```text
20260921T083305Z_5503a068  state=completed  headless=True friction=0.4 case=1/1 sweep.json=有
```

**工作全部做完了**（`summary.json` 与 `sweep.json` 都已落盘、`state=completed`），**卡在退出**——
`application.close()` / 解释器收尾那一步不返回，于是 shell 的 `for f in 0.4 0.8 1.2` 停在第一个值。

这其实是 **CART-02 的同一个坑**：Kit 的关停路径不可靠。而我的**失败路径早就用 `os._exit(2)`
绕过了**（CART-02 的教训写在 `cart_coast.py` 的记录里），**成功路径却还依赖 `close()`** ——
同一份代码里两种退出方式不一致，我自己没统一。

**修法**：成功路径也显式带码退出（`os._exit(0 if all_valid else 2)`）并打印 `[DONE] … 退出码 N`；
产物在退出前都已落盘（CSV 逐行 `flush()`、JSON 写完即关），所以跳过 `close()` 是安全的。
新增源码契约测试：成功路径必须含 `os._exit`，且不得出现真正的 `application.close()` 调用。

**顺带**：这条契约测试第一版又被「注释里出现 `application.close()` 字样」误判——这已经是第三次
被「匹配到散文而非代码」咬到，故改成正则只匹配行首的真实调用（`^\s*application\.close\(\)`）。

### 5.16 其它覆盖与测试抓到的缺陷
覆盖：初始间距算术（用场景常量与 `cart.urdf` 实读值反解）、后挂点在机体后表面之后、
小车挂点朝向机器人、参数校验、记录器的表头/非有限值/时间不递增/拒绝覆盖、以及接口契约
（`positions=` 作用点、`write_data_to_sim()` 必须早于 `sim.step()` 且晚于施力、失败路径
`os._exit(2)` 且不调用 `application.close()`、场景配置只改 `prim_path` 不碰增益/观测/奖励、
入口不导入 `velocity_env_cfg`/`amp_env_cfg`、**初始位姿必须在 `InteractiveScene(...)` 之前
写进配置**）。

**测试抓到的两个真实缺陷（都已修）**：

1. **`--damping 0` / `--slack 0` 被错拒**：第一版把这两个量放进「必须为正」的校验循环，
   于是一个合法的无阻尼绳（`c = 0`）和初始就绷直（`slack = 0`）都过不了参数校验。
   已拆成「严格为正」与「允许为 0」两组。
2. **初始位姿改晚了**：第一版在 `InteractiveScene(scene_cfg)` **之后**才写
   `robot_cfg.init_state.pos`。场景在构造时就把资产按 `init_state` 摆好，之后再改配置
   不生效 ⇒ **`--spawn-height` 会被静默忽略**（而且没有任何报错）。已改为在构造场景前写配置，
   并用测试锁住这个先后顺序。

### 5.17 用户直觉验证：撞击确实发生了，而判据此前是错的

**起因**：用户看完摩擦扫描数据后说「可能是撞到机器人了」。查下去发现两件事：
① 三个 `b=0.008` 的 run 与 `m25 + b=0.032` 真的撞上了机器人；
② 这条链路里「是否追上」的判据用的是**挂点间距**，而挂点间距在碰撞时是 0.34~0.37 m，
所以四个 run 全被判成「没追上」——**假通过**。

#### 证据一：机器人被撞的速度冲量（与位移自洽）

run `20260921T084147Z_3ac8795f`（m10、b=0.008、f=0.8）的滑行段：

| t (s) | 机器人 x (m) | 机器人 vx (m/s) | 机器人 z (m) | 小车 vx (m/s) | 挂点间距 (m) |
|---|---|---|---|---|---|
| 1.220 | 2.5562 | −0.00476 | 0.2735 | 0.3062 | 0.3648 |
| **1.225** | 2.5563 | **+0.08704** | 0.2735 | **0.1771** | 0.3639 |
| 1.230 | 2.5568 | +0.09119 | 0.2737 | 0.1504 | 0.3631 |
| 1.300 | 2.5619 | +0.04575 | 0.2750 | 0.0373 | 0.3645 |
| 1.420 | 2.5642 | +0.00449 | 0.2746 | 0.0012 | 0.3638 |

机器人的 vx 在**一个 5 ms 步**里从 −0.005 跳到 +0.087，随后按 +0.087/0.091/0.093… 平滑衰减，
位移也对得上（2.5562 → 2.5642 共 8 mm），同时 `z` 抬高 1.5 mm、pitch 变化 0.002 rad：
这是典型的碰撞冲量响应。小车侧同一瞬间 v 从 0.3062 掉到 0.1771（Δv = −0.129，a = −25.8 m/s²），
且随后几步 `ω·r/v` 冲到 1.07→2.04（**轮子在打滑**），再回到纯滚动 1.000。

#### 证据二：几何（挂点间距不是间隙）

离线 FK（`scripts/tools/tow_clearance.py`，输入是 URDF + 记录关节角）给出的关系是

    间隙 = 挂点间距 − (|x_min_腿| − 0.16 m) + ε      ε = 0（撞车斗前表面）/ 0.01 m（撞前轮外缘）

`|x_min_腿|` 只由腿的位形决定。实测站高 0.2735 m、足端着地的约束下扫描关节空间：

| 腿的位形 | 机器人最后表面（base 系） | 该姿态下撞上所需的挂点间距 |
|---|---|---|
| 收腿（thigh −0.06 / shank −1.50） | −0.2698 m | 0.110 m |
| 默认站姿（0.87 / −1.82） | −0.3984 m | 0.238 m |
| 后腿伸到最远（1.16 / −0.52） | −0.5913 m | **0.431 m** |

于是「撞上时的挂点间距」在 **0.11~0.43 m** 之间浮动，实测四次撞击落在
**0.3457 / 0.3631 / 0.3649 / 0.3744 m**，全部落在区间内 ✓。也就是说
**同一个 0.3639 m 的挂点间距，在默认站姿下是「还差 0.126 m」，在后腿伸直时是「已经压进去 0.067 m」**。

### 5.18 绳的弹性：实测比真实绳子软 15~800 倍

用户提出「照理说我们的绳子应该不是很弹性」。**诊断已进判读工具**，所以下面每个数都能用
`python3 imgo2_rl/scripts/tools/summarize_tow.py <case 目录>` 对**已有 run 复算，不必重跑**
（字段：`rope_stretch_steady_mm` / `rope_stretch_peak_mm` / `tension_overshoot_ratio` /
`takeup_peak_tension_n` / `rope_reduced_mass_kg` / `rope_natural_freq_hz` /
`rope_damping_ratio` / `spring_dt_limit_ms` / `predicted_takeup_peak_n`）。

实测（`k=4000 N/m, c=100 N·s/m`，13 个 run 全部复算）：

| 量 | 实测 | 说明 |
|---|---|---|
| 稳态伸长 `T/k` | **0.71~2.65 mm**（L0=0.8 m 的 0.09%~0.33%） | 稳态几乎不可伸长 |
| 绷直瞬间峰值张力 | **60.5~83.9 N** | 稳态只有 10 N（b=0.032）/ 2.85 N（b=0.008） |

**一个必须先纠正的量：折合质量要用整机质量。** 绳的折合质量
`μ = ((1/m_eff)+(1/m_robot))⁻¹`，其中 `m_robot` 是**整机 12.6996 kg**（base 5.5339 + 四条腿各
1.7914），我手算时只用了 base 的 5.5339 kg ⇒ μ=3.63 kg、ω=33 rad/s、峰值上界 104 N，
**全都是错的**。正确值随质量从 3.98 kg（5 kg 车）到 8.51 kg（25 kg 车）变化。
（`robot_mass_kg` 现已从仿真读入 `config.json`；旧 run 由 `tow_clearance.robot_mass_kg()`
从 URDF 求和兜底。）

能量界 `½μv² = ½kδ² ⇒ δ=v√(μ/k)`、峰值 `v√(kμ)`（`v` 取绷直瞬间的相对接近速度 ≈ 0.500 m/s）：

| 质量 | μ (kg) | ω/2π (Hz) | ζ | dt 上限 (ms) | 能量界峰值 (N) | **实测峰值 (N)** | 实测/上界 |
|---|---|---|---|---|---|---|---|
| 5 kg | 3.98 | 5.04 | 0.396 | 42.9 | 59.8 | 60.5 | 1.01 |
| 10 kg | 5.84 | 4.17 | 0.327 | 55.4 | 76.4 | 70.0 | 0.92 |
| 15 kg | 7.04 | 3.79 | 0.298 | 62.6 | 85.5 | 76.4 | 0.89 |
| 20 kg | 7.89 | 3.58 | 0.282 | 67.3 | 91.2 | 80.8 | 0.89 |

⇒ 绷直峰值这个**无阻尼上界**在整段质量（5~25 kg）与两个 `b` 上把实测值框在 **12% 以内**，
说明「绳的绷直是一个由 μ 与 k 决定的瞬态」这个理解是对的；实测略低于上界（88%~101%）
也与欠阻尼相符。

真实绳子的轴向刚度 `k = EA/L`：6 mm 涤纶/尼龙绳 EA≈50~100 kN ⇒ k≈6×10⁴~1.2×10⁵ N/m；
4 mm Dyneema ⇒ k≈1.6×10⁶ N/m。**当前 4000 N/m 比它软 15~800 倍**，更像弹性拖车带。

显式弹簧的稳定条件 `dt < 2/(ω(ζ+√(ζ²+1)))`（按 10 kg 车的 μ=5.84 kg 算）：

| k (N/m) | ω (rad/s) | dt 上限 | 5 ms 是否可用 | 绷直峰值上界 `v√(kμ)` |
|---|---|---|---|---|
| 4×10³（当前） | 26.2 | 55 ms | 可用（余量 11×） | 76 N（实测 70 N ✓） |
| 4×10⁴ | 82.8 | 17 ms | 可用 | 242 N |
| 1×10⁵（≈6 mm 绳下限） | 131 | 14 ms | 勉强 | 382 N |
| 1.6×10⁶（Dyneema） | 524 | 3.8 ms | **失稳** | 1528 N |

所以**在「5 ms 步长 + 显式弹簧」这个框架里表示不了真实绳的刚度**；而 k 提到 1×10⁵ 时
绷直峰值会从 ~70 N 涨到 **~380 N**，机器人被猛拽（对照：§5.9 里 236 N 就把机器人拽翻）。
**注意这不会推翻已有结论**：稳态张力 `4bω/r`（实测 10.60 / 2.85 N 吻合）与滑行段都与 k
无关，只有绷直瞬态受影响。

**已实测（见 §5.19）**：三档 `k` × 两种 `c` 的对照已跑完。结论是「峰值 = `max(c·v, v√(kμ))`」
（模型吻合 0.84~1.10）、**稳态与 k 完全无关**、而「临界阻尼」会把峰值抬高 2.1~2.5 倍
——所以**不要**按本节末尾原先设想的「提刚度顺带提到临界阻尼」去做。默认值（k=4000, c=100）不改。

### 5.19 绳刚度扫描实测（TOW-04 结案）：峰值 = max(c·v, v√(kμ))，稳态与 k 无关

用户按 §5.18 的命令跑了 6 个 run（**k = 4000 / 40000 / 100000 × c = 100 / 临界阻尼**，
m=10 kg、b=0.032、f=0.8、`v_cmd=0.5`，只有 station+tow，没带 `--stop-at`）：

| run | k (N/m) | c (N·s/m) | v_rel (m/s) | c·v (N) | v√(kμ) (N) | 模型 max | **实测峰值 (N)** | 实测/模型 | 稳态 T (N) | 松弛占比 | 跟速 | pitch | valid |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| k4000 | 4×10³ | 100 | 0.547 | 54.7 | 83.5 | 83.5 | **70.0** | 0.84 | 10.09 | 0% | 0.945 | 3.8° | ✓ |
| k40000 | 4×10⁴ | 100 | 0.547 | 54.7 | 264.2 | 264.2 | **231.2** | 0.88 | 10.13 | 30.0% | 0.949 | 3.7° | ✗ 断续 |
| k100000 | 1×10⁵ | 100 | 0.547 | 54.7 | 417.7 | 417.7 | **372.6** | 0.89 | 10.03 | 14.2% | 0.942 | 3.7° | ✗ 断续 |
| kc4000 | 4×10³ | 305.6 | 0.547 | 167.1 | 83.5 | 167.1 | **170.5** | 1.02 | 10.09 | 0% | 0.944 | 3.7° | ✓ |
| kc40000 | 4×10⁴ | 966.4 | 0.547 | 528.4 | 264.2 | 528.4 | **562.7** | 1.06 | 10.06 | 0% | 0.943 | 3.7° | ✓ |
| kc100000 | 1×10⁵ | 1527.9 | 0.547 | 835.4 | 417.7 | 835.4 | **921.0** | 1.10 | 10.08 | 7.1% | 0.943 | 3.7° | ✓ |

**四条结论**：

1. **峰值由 `max(c·v_rel, v_rel·√(kμ))` 决定，模型在 6 组配置上给出 0.84~1.10**
   （25× 刚度范围、15× 阻尼范围）。物理含义：绷直时 `ḋ` 从 0 跳到 `v_rel`，
   而 `T = kδ + c·ḋ` 里的阻尼项**立刻**给出 `c·v_rel`；弹簧项要等 δ 长起来才跟上。
   所以**「临界阻尼」在这里是错的选择**——它把 `c·v` 顶到 `5v√(kμ)`~`2v√(kμ)`，
   峰值反而比轻阻尼高 2.1~2.5 倍（kc 系列的 921 N vs k100000 的 373 N）。
   要柔和就该**同时**小 k 和小 c，§5.18 的「提刚度 + 提到临界阻尼」建议被实测否掉。
2. **稳态与 k 完全无关**：6 组稳态张力 10.03~10.13 N（`4bω/r` = 10.6 N）、
   跟速比 0.942~0.949、峰值 pitch 只有 3.7~3.8° —— 连 921 N 的绷直冲量都没让机器人失稳
   （§5.9 那次 236 N 翻倒是因为绳在**出生下落期间就被预张紧**，机理不同）。
   所以**已有结论（稳态张力、滑行段、质量包线）不受 k 影响**，§5.18 的判断成立。
3. **刚 + 轻阻尼会「打颤」**：k=4×10⁴/c=100 的收松弛后松弛占比 **30.0%**、
   k=1×10⁵/c=100 是 **14.2%**，两者因此判 `rope_not_continuously_taut` 失败；
   而 kc 系列（临界阻尼）是 0%~7.1%。机理：刚性绳的静态伸长只有 `T/k` = 0.1~0.25 mm，
   步态纹波让 δ 每个半周期穿过 0 ⇒ 张力断续。**这条判据的适用范围要写清楚**：
   「收松弛后持续绷紧」是**软绳模型**的性质，真实绳（亚毫米伸长）本来就会这样打颤，
   所以它衡量的是「模型是否自洽」，不是「实物会不会打颤」。
4. **当前默认（k=4000, c=100）是这套框架下的合理选择**：峰值 70 N、零打颤、`valid=True`；
   而真实绳的刚度（1×10⁵~1.6×10⁶）在 dt=5 ms 下要么给 373~1528 N 的猛拽、
   要么需要临界阻尼再翻 2.5 倍、要么打颤 30%，且 1.6×10⁶ 直接失稳（dt 上限 3.8 ms）。
   **结论：默认值不改**；要让绳"像真绳"，必须换表述（约束/子步），不是调 k。

**顺带修掉工具里两个 bug（都由这批数据暴露）**：

- **`takeup_closing_speed_mps` 取错了行**：我原先取「首个 T>0」的行，但绳是在上一个 5 ms
  步内绷直的，那一行的速度已被冲量改过（kc100000 的首个 T>0 行 v_R 已从 0.547 掉到 0.176、
  v_L 从 0 跳到 0.431），于是上界算成 195 N 而实测 921 N。力是每步**开始时**按当时状态算的，
  所以必须取**前一个松弛步**。改后 6 组全部落在 0.84~1.10（改前 kc 系列是 10.09/2.36）。
- **四轮 x 分力之和的注释是错的**：我写「正常滚动时只有 ~1.7 N（克服轮阻）」，
  实测稳态和值是 **1.3×10⁻⁵ N** —— 前后轮的摩擦力方向相反、在**和**里互相抵消。
  所以「和值」没有滚动基线，反过来说**任何明显的非零和值都是异常**（撞击只打一个轮子，
  不会成对抵消）。注释与判据说明已按实测定标改正。

**新登记的一个坏情况：生成时就贴上。** 由 FK 间隙算出来，station 段的**最小车头间隙只有
0.0955 m**（t=0.205 s，机器人下蹲 z=0.2521 m、后腿伸到 base 后方 0.4113 m）——
挂点间距 0.40 m 听起来很安全，真实余量只有 9.5 cm。所以新增：
`min_clearance_station_m`（报告初始余量）与判据 `load_touching_at_settle`
（station 段车斗接触力 > 1 N ⇒ 失败，这是初始条件问题，不能混进「追尾」）。

**TOW-03 部分结案**：新记录在真实 run 里全部生效（22 个新列；`policy_joint_names`、
`robot_mass_kg=12.6996` 落盘；`min_clearance_m=0.1123`、`final_clearance_m` 真算出来了），
