## 3. 结论

### 3.1 已确证的根因：任务奖励权重被 dt 缩小了 50 倍

> **2026-09-18 更正**：本小节的「50 倍」是单位误读——参考的 `_prepare_reward_function()` 也会
> `reward_scales[key] *= self.dt`，a1 写的 50 每步真值是 1.5，与我们当时的 1.0 同量级。
> 见 [AMP 对照报告](amp_standstill_diagnosis_2026-09-17.md) 第 11.1 节。下面的实验记录保留原样。

- 参考项目（legged_gym）的 `compute_reward` 是 `self.rew_buf += rew`，**不乘 dt**，
  所以 a1 的 `tracking_lin_vel = 1.5/(0.005*6) = 50` 就是**每步**系数。
- Isaac Lab 的 `RewardManager.compute(dt)` 计算 `term × weight × dt`，`weight` 的语义是**每秒**。
- 我们配置写 `1.0/step_dt`、`0.3/step_dt`，被再乘一次 `dt=0.02` 约掉 → 每步只剩 **1.0 / 0.3**，
  **比参考小 50 倍**。

**Run1→Run2 验证了这一点**：把速度项提到 50/17 后，跟踪奖励/步从 0.009 涨到 1.376（**×150**），
说明「量级」确实是「不动」的必要条件之一。

### 3.2 Run2 的失败：提高到参考量级后又走到另一个退化解

Run2 把高度项从 −10 削到 −1 后，**高度项相对速度项弱了约 3000 倍**：

```
高度偏差 |z−0.30| = 0.128 m → 每步惩罚 = 1.0 × 0.128² = 0.0164
速度项每步最大                              = 50
```

于是策略找到了「**趴低滑行**」这个捷径：低姿态更稳、更容易满足速度指令，而高度惩罚几乎为零。
结果：高度 0.305→**0.172 m**、贴地比例 0.0035→**0.886**、角速度误差反而升到 2.04。

**跟踪质量只到 2.8%**（每步 1.376 / 50），速度误差 0.78 m/s——**比 Run1 的 1.72 好，但远不是可用步态**。

### 3.3 Run2 还暴露两个放大机制（Run1 未触发）

| 现象 | Run1 | Run2 | 判读 |
|---|---|---|---|
| `Policy/mean_noise_std` | 0.13（正常） | **12.17** | `std` **只有下限 clamp、无上限**（`amp_ppo.py:256`），而熵项（+0.01）单向把 std 往上推 |
| `Loss/value_function` | 4.17 | **4710** | critic 要拟合「近乎随机策略」的回报 |
| `Loss/AMP` / 判别器预测 | 0.26 / −0.52 | **0.005 / −0.99** | 判别器饱和，风格奖励失效，训练退化成纯任务优化 |

`std=12` 意味着动作抖动 ±3 rad（乘动作尺度 0.25）——而动作裁剪本就是 ±3.0，
即**策略在训练中期接近随机动作生成器**。

### 3.4 因此的处理：回退到 Run1 的配置

`track_lin_vel / track_ang_vel / base_height_l2` = **1.0 / 0.3 / −10**（每步）。
理由：**Run1 是迄今唯一得到可用站姿的组合**（高度 0.305、贴地 0.35%、触地终止 6.8%）。
Run2 证明「只改速度量级、不动高度」会把问题从「不动」换成「趴着滑行」，两者都不可用。

**回退后的配置已由单元测试锁定**（`tests/test_amp_alignment.py`）：
每步系数精确断言，且断言**高度项强于速度项**（`lin_ps < height_ps`），防止再次被改成反向。

### 3.5 补充：直接看奖励曲线得到的结论（并修正 3.2/3.4 的一处误判）

**口径**（`isaaclab/managers/reward_manager.py:149-153`）：
`value = term × weight × dt` 每步计算，`Episode_Reward/*` 是**情节内累计和**（不是每步值），
`Train/mean_*_step` 才是每步值。

Run1（最初不动那次）的曲线形态是决定性的：

| 指标 | 段1 | 段2 | … | 段10 |
|---|---|---|---|---|
| 每步 任务合计 | 0.241 | 0.258 | | **0.260** |
| 情节累计 速度跟踪 | 7.35 | 8.34 | | 8.19 |
| 情节累计 高度惩罚 | −0.257 | −0.098 | | −0.086 |
| 每步 混合总奖励 | 0.661 | 0.700 | | 0.658 |
| 线速度误差 | 1.545 | 1.680 | | **1.653** |

由曲线反推的实测量级：

- 速度项有效值：`8.19 = 权重 1.0 × E[exp] × 情节步数 ~950` → `E[exp] ≈ 0.0087` → 反推误差 ≈ 1.09 m/s。
- **速度项对速度的梯度** ≈ `1.0 × 0.0087 × 2e/0.25 ≈ 0.07`（每 m/s）——拉力极小。
- **高度惩罚每步仅 ≈ −0.00045**（−0.086 / (950 × 0.02 × 10)）。
- 风格项每步 ≈ 0.79（由 `0.658 = 0.7×风格 + 0.3×0.26` 反推）。

**由此修正前面的判断**：

| 曾经的表述 | 曲线显示的实际 |
|---|---|
| 「高度项 10 倍于速度项，把策略按在站姿上」 | ❌ **错**。高度惩罚每步仅 −0.00045，对策略几乎无影响 |
| 「任务奖励弱 50 倍是根因，抬权重即可」 | ⚠️ **不完整**。Run2 ×50 后跟踪项仅从 0.0087 → 0.0275 |
| 「调风格/任务占比即可」 | ⚠️ 不够。梯度 ∝ 权重 × 8.7e-3，权重 ×50 只把梯度从 0.07 抬到 3.5 |

**真正的根因（由曲线得出）**：速度奖励是指数核 `exp(−e²/σ²)`，`σ=0.5`；
策略实际误差 1.65 m/s 时 `exp(−10.9) ≈ 1e-15`——**奖励项在数学上已经死了，梯度同样为 0**。
任务奖励从第 2 段起完全冻结（0.258→0.260，持续 8500 轮）正是零梯度的直接表现。
**加权只是把 1e-15 乘上一个系数，不产生梯度。**

Run2 之所以能动，是因为它把误差拉到 **0.78 m/s**（落入 σ 敏感区，`exp(−2.4)=0.09`，核重新活过来）——
这反证了「关键不是权重，而是让误差进入核的敏感区（|e| ≲ σ）」。

**据此的方案优先级（均为待验证，未运行）**：

| # | 方案 | 针对根因的理由 |
|---|---|---|
| 1 | **换核**：`1 − e²/σ²` 或 `−e²` 替代 `exp(−e²/σ²)` | 远距离仍有非零梯度，策略能自行爬向目标 |
| 2 | **加指令课程**：从 \|v\|≤0.3 逐步放开 | 初始误差即落入核敏感区，先学会动再学快 |
| 3 | **加稠密速度项**：在核之外加 `−k·\|e\|` | 与核互补，远处提供梯度 |
| 4 | 只调权重/占比 | ❌ 已证不足（梯度 ∝ 系数 × 1e-15） |

## 4. 未解决 / 下一步（都是待验证，未运行）

| # | 事项 | 依据 | 缺什么才能完成 |
|---|---|---|---|
| 1 | **`std` 无上限是独立机制缺陷** | Run2 实测 12.17 | 需在被认为该修的时候单独改（`clamp(max=...)` 或改学 `log_std`）；**不要和奖励配比同时改**，否则无法归因 |
| 2 | **中间量级可能才是解** | Run2 证明两个极端都失败：1.0 太弱（不动）、50 配 −1 太偏（趴着滑行） | 试 **速度 10~20 / 高度 −3~−5** 的中间组合 |

| 4 | **判别器饱和会把风格奖励变成死信号** | Run2 预测恒 −0.99、Loss/AMP 0.005 | 需检查判别器学习率/容量与策略更新节奏的匹配 |
