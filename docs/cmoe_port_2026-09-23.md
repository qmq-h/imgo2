## Rough 任务与观察契约

`CMoE_env_cfg.py` 继承 `Imgo2RoughEnvCfg`，继续使用 PPO rough 的动作、命令和主体奖励，同时对
地形、接触奖励和终止做 CMoE 专用覆盖。5 个专家不和地形类别人工一一绑定，而由 gate 与训练目标
自行分工。

地形列占比固定为：上楼梯 15%、下楼梯 10%、boxes 15%、随机粗糙面 20%、正／反斜坡各 10%、
沟壑 20%，合计 100%。沟壑使用 Isaac Lab `MeshGapTerrainCfg`，宽度随难度从 `0.10 m` 增至
`0.16 m`；Imgo2 base 碰撞盒长度为 `0.315 m`，因此上限约为半个躯干长度。中央平台宽 `4.0 m`，
保留 reset 的 `x/y ∈ [-1, 1] m` 随机位置时，整机仍与沟边保持安全距离。

CMoE 专用奖励／终止覆盖为：

| 项目 | 当前设置 |
|---|---:|
| 足端绊脚 `feet_stumble` | `-1.0` |
| 非足端碰撞 `undesired_contacts` | `-5.0` |
| 足端踩空洞边缘 `feet_edge` | `-1.0` |
| 摆动足世界高度 `feet_height` | 关闭 |
| 足端相对机身高度 `feet_height_body` | 关闭 |
| 足端滑动 `feet_slide` | 关闭 |
| 腾空时间一致性 `feet_air_time_variance` | 关闭 |
| 对角腿镜像 `joint_mirror` | 关闭 |
| base 接触 | 立即终止，阈值 `1 N` |

`feet_edge` 不复用 actor 的 base 高度图，而是在四个足端各挂一个 `0.12 × 0.12 m`、分辨率
`0.04 m` 的向下射线网格。只有足端正在接触，且局部网格同时出现有效地面命中与 gap 的无穷远
未命中时才计罚；普通楼梯的射线都有命中，不会仅因高度不连续被当作空洞边缘。

训练 reset 保留原 PPO 的 `x/y` 位置范围和速度范围，但初始 roll/pitch 固定为 0，仅 yaw 在
`[-3.14, 3.14]` 内变化，避免机器人以倾倒姿态生成后立刻发生 base 接触。

当前观察维度为：

| 输入 | 维度 | 内容 |
|---|---:|---|
| `policy` 单帧 | 45 | 非特权本体感知，不含 base 线速度与高度扫描 |
| `policy` 历史 | 450 | 10 × 45，只对本体感知做历史堆叠 |
| `terrain` | **77**（2026-09-24 起；此前为 187） | height scanner 输出（11×7 @ 0.1 m，覆盖 1.0×0.6 m），训练时保留 `[-0.1, 0.1]` 均匀噪声 |
| actor 总输入 | **527**（2026-09-24 起；此前为 637） | 450 + 77 |
| expert／gate 输入 | **157**（此前 267） | 当前 45 + 显式速度 3 + 状态 latent 16 + 地形 77 + 地形 latent 16 |
| `critic` | **125**（此前 235） | 特权 base 线速度 3 + 本体感知 45 + 高度扫描 77 |

play 配置关闭 policy／terrain observation corruption 和域随机化，使用单环境与固定
`vx=1.0 m/s` 命令；训练配置仍沿用 rough 环境原有的噪声、随机化和命令范围。

## 与原版相比的必要适配

- 原版写死的 `45×10 + 77`、5 个专家和 12 维动作改为构造参数；Imgo2 当前仍使用 5 个专家，
  terrain 维度**已按用户要求于 2026-09-24 改回原版的 77**（11×7 @ 0.1 m，覆盖 1.0×0.6 m；此前一度用继承来的 187 = 17×11 @ 1.6×1.0 m）；
- critic 中显式速度标签与下一帧 proprioception 的 slice 改为配置项，当前排列为
  `[base_lin_vel(3), policy(45), height_scan(77)]`；
- Storage 移除写死的 `[527]`，使用 Runner 传入的 actor observation shape；
- rollout 结束计算 bootstrap value 前重新计算最后一帧 gate，避免沿用前一帧路由权重；
- checkpoint 同时保存两个 estimator optimizer 的状态。

即插即用替代物，部署端仍需实现同样的高度扫描和历史缓存契约。

## 2026-09-24 观测契约变更：地形扫描 187 → 77（用户要求）

`CMoE_env_cfg.py` 的 `__post_init__` 现在**只覆盖 CMoE 自己的场景**（不动 `MySceneCfg.height_scanner`，故 PPO／HIM／AMP 不受影响）：

```python
scan = self.scene.height_scanner.pattern_cfg
scan.resolution = 0.1
scan.size = (1.0, 0.6)                        # 11 × 7 = 77 条射线
self.scene.height_scanner.offset.pos = (0.25, 0.0, 20.0)   # 网格整体前移 0.25 m
...  # 并断言射线数必须为 77
```

**⚠️ 地形参数已更新（2026-09-24，晚于本节的 `b87efa3` 描述）**：沟宽改为按体长的 **0.4–1.0 L = 0.126–0.315 m**（原 (0.08, 0.16)）；上行台阶 `proportion` 0.15 → **0.20**、上下行均 `num_steps` 4 → **6**、`step_height_range` (0.025,0.08) → **(0.03,0.10)**；`random_rough` 0.20 → 0.15。当前值以 [训练准备记录](cmoe_training_prep_2026-09-23.md) §27–§28 为准，本节下文列的旧数值仅代表 `b87efa3` 时的状态。

**几何与理由**：覆盖 **x ∈ [−0.25, +0.75] m（前瞻 0.75 / 后视 0.25）、y ∈ [−0.3, +0.3] m**，分辨率 **0.1 m**。
- 前移是为了恢复前瞻（原 187 几何前瞻 0.8 m；居中 11×7 只有 0.5 m），过沟依赖前瞻。
- **分辨率不能降到 0.15 m**：当前课程沟宽约 0.13 m，间距 0.15 m 时沟可能整条落在两条射线之间而漏检；间距 0.1 m 时任意 0.13 m 区间必含至少一条射线。
- 只动观测用的 `height_scanner`；`height_scanner_base`（`base_height_l2` 用，9 条射线）必须留在基座正下方，未动。

新契约：`terrain = 77`、**actor 总输入 527**（450+77）、expert／gate **157**、`critic` **125**；policy 45／history 450 不变。

⚠️ **兼容性**：2026-09-24 之前的所有 CMoE checkpoint（`20-38-55` 的 818 轮、`22-18-33` 的 16.7k 轮、`15-34-14_cmoe_A_fresh`）都是 187 几何，**不能**用新配置 `--resume` 或 `play`（`load_state_dict` 尺寸不匹配）。回放旧件有两条路：① 用各 run 目录里自动保存的 `params/CMoE_env_cfg.py`（启动时快照，仍是 187 几何）临时替换源文件；② 把上面两行改回 `(1.6, 1.0)` 并去掉 77 断言。部署端与导出的 `policy.pt`／`policy.onnx` 也必须与训练时几何一致（527 vs 637 不可混用）。
