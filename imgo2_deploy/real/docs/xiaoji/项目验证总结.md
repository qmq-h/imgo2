## 0. 一句话现状

## 1. 接手时的起点

- `GO_IMU_BUILD_RL=ON` 编译失败：`find_package(Torch)` 找不到。
  根因：用户传 `-DCMAKE_PREFIX_PATH="../library/inference_runtime/libtorch"`，而 CMake 的相对前缀按**源码目录**解析 → 指到了 `.../go_imu 20261015/library`（不存在）。仓库自带 libtorch 在 `.../go_imu/library/inference_runtime/libtorch`。
- 有 yaml-cpp 弃用告警（conda 的 yaml-cpp 0.9 被 PATH 选中；系统 0.7 也可用）。
- 真机上出现过三类运行期报错：IMU 陈旧（消息为空）、总线 `feedback timeout`、关节 `age=100ms` 陈旧。

### 3.4 真机 338 s 日志（`build/log/2026-10-19_22-15-26_19277/`）

- 67597 行 / 338.2 s；状态：InitialHold 0–36.6、Standing 36.6–40.6、StandHold 40.6–48.4、PPO 48.4–338.2。
- **失能原因**：`bus leg_fl motor 0: feedback timeout [id=0 waited=22914us budget=20000us bytesIn=16 badFrames=0 strayFrames=0]`（wall 22:21:04.796）→ 总线锁故障 → `unloadOnce` → FSM Fault → 卸力。
- **同一毫秒 3 条总线同时失败**（bus0/id0、bus1/id1、bus2/id2，各 waited 21.7–22.9 ms，**都是 16 字节**、`bad=0 stray=0` → 字节流错位，不是 CRC/串线）。
- **IMU 同时停**：`imu_age` 峰值 23 ms（全程最大）；控制环缺 **26.7 ms** 节拍（tick 连续无跳号）。
- **停顿事件统计**（用最年轻关节 age 判定整轮未完成）：5 ms 共 6024 次、10 ms 53 次、**15 ms 6 次、20 ms 1 次**（即故障那次）。≥15 ms 的事件在 105.5 / 139.1 / 199.5 / 221.1 / 242.0 / 269.5 / 338.1 s，间隔 **20–70 s（不规律）**，且**每次 IMU age 同步升高**。

### 3.5 通讯时延（usbmon + 日志）

| 量 | 实测 | 说明 |
|---|---|---|
| 485 线上时间（17B 命令 + 16B 应答 @4 Mbaud） | **83 µs** | 与波特率匹配，理论值 |
| USB OUT 传输（S→C） | **30 µs** | 命令发出极快 |
| **OUT 完成 → IN 完成（应答回来）** | **1.592 ms**，±0.045（13708 次，4 端点各 1.587–1.595） | **瓶颈所在** |
| 我们线程唤醒+解析 | **60 µs**（日志 `reply` 1.65 − usbmon 1.59） | 软件无浪费 |
| 命令周转（IN 完成→下一条 OUT 提交） | 108 µs（同轮内） | 轮间有 period 剩余的 sleep |

日志侧（67597 轮）：`total` 中位 **5020 µs**、`reply` **4943 µs**、`write` 33 µs、`flush` **4 µs**；每事务 `reply` **1648 µs** 占 99.3%。
每 (总线,电机) 的事务耗时中位 1.686–1.706 ms、std 0.056–0.071 ms（12 组几乎相同）。

**逻辑分析仪实测（用户，2026-10-19）**：命令帧发完 → 电机开始回帧 ≈ **10 µs**。
因此 1.59 ms 既不在 485 线上、也不在电机固件：**在适配器芯片/驱动的收包路径里**（芯片把 16 字节攒到定时器到期才上送 USB）。
**结论：5 ms = 3 × 1.59 ms 的固定等待 + 3 × 90 µs 软件开销；与波特率、电机固件都无关。**

## 4. 未解决的问题（按优先级）

### P0：15–25 ms 的系统级停顿（导致过卸力）

- **现象**：每 20–70 s 一次，关节反馈与 IMU **同时**停更 15–25 ms；超过 `io_timeout_us=20 ms` 时三总线同时超时 → Fault → 卸力。
- **已排除**：485 线束（4 条总线同时）、单台电机、CRC/噪声（`bad=0 stray=0`）、主机 URB 提交（30 µs）。
- **候选**（均未证实）：
  1. **内核脏页回写**：`vm.dirty_expire_centisecs=3000`（30 s），日志写 216 KB/s → 每 30 s 回写约 6.5 MB；与 20–70 s 的间隔吻合。
  2. USB 主机控制器/hub 级停顿：4 路 485 是**同一个 USB 设备**（Bus 03、Dev 2、4 对 CDC），IMU 也在 Bus 03。
  3. CPU 抢占/降频（控制环缺 26.7 ms 节拍；governor 为 `powersave`）。
  4. 电机电流/供电（与"负载越大越容易"一致，但难解释 IMU 同时停）。
- **下一步**：① **不带 `--log` 跑 5 分钟**，看 `--bus-stats` 的 `bus轮询 max` 是否还有 >10 ms 尖峰；② `dmesg -T` 对齐上面 7 个时刻；③ 把 `loopStats` 的 `gap/body` 每秒写进 `events.log`（尚未实现）。

### P1：低速/行进中的高频抖动（未定位）

- 用户观察：**把机器人提起再放下后抖动明显变小**；横移、接近零速、转向时更明显。
- 已排除：IMU 内部一致性、重力公式、yaw/±180、仿真↔实机 obs/action/gain 契约。
- 候选：
  1. **P0 的停顿**（有负载时更易触发一次 → 目标/反馈 hiccup）；
  2. **IMU 姿态滤波被落地冲击带偏**（抬起后收敛 → 放回时更准，与"抬起变小"吻合）；
  3. 足端打滑/接触（纯机械）。
- **下一步**：① 抬起 vs 落地各 60 s，比较 `bus轮询 max`/`gap` 的尖峰次数；② IMU 台架符号测试（见下）；③ 悬空静止时看 `quat` 的 roll/pitch 短时噪声。

### P2：IMU 物理轴对齐未验证

代码在 `RobotAdapter::toPolicy` 里明确 **不做任何 IMU 旋转**（`mount_quaternion` 只做长度/有限/零模校验）。需做 2 分钟台架测试：

| 动作 | 期望 |
|---|---|
| 车头朝下（前腿垫高） | `pitch > 0` 且 `gravity_x > 0` |
| 右侧朝下 | `roll > 0` 且 `gravity_y < 0` |
| 俯视逆时针转 | `gyro_z > 0` |
| 按 `a` | 向**左**平移 |
| 按 `q` | **逆时针**转 |

任何一条反了 → 需在 `toPolicy` 施加 `q_body = q_mount⁻¹ · q_imu`、`gyro_body = R(q_mount)ᵀ · gyro_imu`（约 10 行，尚未实现）。

### P3：1.59 ms 应答延迟——**已排除电机，锁定适配器/驱动**

- 逻辑分析仪实测：命令帧结束→电机开始应答 ≈ **10 µs**；线上总时间（收发帧）≈ 83 µs。
- 主机侧：OUT 传输 30 µs、我们线程唤醒 60 µs。
- ⇒ **1.59 ms 全部落在"适配器芯片把收到的字节攒起来再上送 USB"这一段**（含驱动收包）。
- **下一步**：① 查 CH344 / `usb_ch343` 驱动有没有"收包超时/latency"可调项（WCH 厂商工具或驱动源码）；② 换用转发更快的桥接（FTDI 系可把 `latency_timer` 设 1 ms，仍非 10 µs 级）；③ **流水线**（先发 3 条、间隔 200 µs，再按 ID 收 3 条）可把 1.59 ms 只付一次 → 一轮 5.0 ms 降到 **~2.2 ms**，这是当前最现实的提速手段。

### 已知但非本轮引入的问题

- `rl_relocation` 失败：`cmake --install` 不打包 libtorch 的 `.so`（约 465 MB 的取舍未定）。
- yaml-cpp 弃用告警：conda 0.9 被 PATH 优先（系统 0.7 也可用）；0.10 移除旧名后才会真正失败。
- `loop` / `fsm_check` 在并发或高负载下偶发时序断言失败（单独跑通过）。

## 7. 交接注意事项

1. **二进制读的是可执行文件旁边的 yaml**：`build/config/deployment.yaml` 与 `build/policy/ppo/config.yaml`。源码改了 yaml 后，要么重新链接（POST_BUILD 会拷），要么手动 `cp`。**本轮已核对两份一致**。
2. **没有 git**：任何"回滚/对比"只能靠本文件与文件时间戳。改动前建议先备份。
3. **跑测试**：`ctest --test-dir build -j1`；并发会偶发时序失败。
4. **别再改 `period` 而不改测试**：`tests/test_math_config.cpp` 钉住了 7 ms。
5. **`--log` 会自动开 `--bus-stats` + `--trace`**（stdout 每秒多两行），自动化脚本若严格解析 stdout 需注意。
6. **`--log` 有磁盘写**（约 200 KB/s）；排查时序问题时应做"带/不带 `--log`"的 A/B。
7. **所有 Fault/看门狗/`9`/Ctrl+C 都是力矩归零（会塌）**，任何真机测试必须吊住/托住。
