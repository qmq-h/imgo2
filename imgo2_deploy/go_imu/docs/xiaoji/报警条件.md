# 报警条件（按"发生阶段"分区：初始化 / 运行中 / 软拒绝）

> **v2 重排说明**：v1 按代码层次（单电机→总线→FSM）组织，排障时不好定位。
> 本版改为按**发生阶段**主分类，层次只作为"类别"；条件全部编号（`E*` 初始化 / `R*` 运行中 / `N*` 正常卸载 / `S*` 软拒绝），
> 排障时直接说编号即可。
>
> 代码基线：本目录当前工作副本（无 git）。数值以 `config/real_config.h`、`config/deployment.yaml`、
> `policy/ppo/config.yaml` 的实际内容为准；本文写出参数名，便于核对。

---

## 1. 五秒判断阶段（先看这四行）

| 你看到的现象 | 阶段 | 机器人当时状态 | 去查 |
|---|---|---|---|
| `deployment error: ...`、`start failed: ...`、`xxx failed: ...`，**退出码 1** | **初始化** | **从未出力**（安全） | §3 的 `E*` 表 |
| `Fault: ...` + `状态: Fault`，**退出码 2** | **运行中** | **已卸力**（会塌） | §4 的 `R*` 表 |
| 只有一句中文提示：`PPO锁定…` / `尚未就绪…` / `AMP未开放` / `轨迹拒绝: …` | **软拒绝** | 什么都没变，仍在当前状态 | §5 的 `S*` 表 |
| `... unloaded`（`no new target for N ms (watchdog 80 ms)`） | **运行中但非故障** | 已卸力，**可自动恢复** | §4 `R20` |

> 口诀：**英文报错且退出=初始化；Fault 且塌了=运行中；中文提示=软拒绝。**

## 2. 阶段边界：什么时候算"已使能"

```
main()
 ├─ 解析参数              ┐
 ├─ 读 deployment.yaml    │
 ├─ 读 policy 配置        ├── 阶段 A：初始化（只发 FOC 零指令，没有力矩）
 ├─ 构造各对象（含轨迹预检）│
 ├─ hardware.start()      │  ← 开串口、启动探测（零指令）、自动归零、等 IMU
 │                        ┘
 ├─ 第一轮 sendCommand(InitialHold, kp=60/kd=2, 目标=实测)   ← **使能从此开始**
 └─ while(...) { 读状态 / 更新 FSM / 下发 / 推理 }            ← 阶段 B：运行中
```

- **初始化阶段**：即使串口已打开，电机收到的也是 FOC 全零（`kp=kd=tau=0`）——**没有力矩**。
- **运行中阶段**：从第一轮 `sendCommand` 起，任何故障都会"锁存停机 + 卸力"，机器人会**失去支撑**。

## 4. 运行中错误（`R*`，已使能；后果都是**先卸载再报错**）

### 4.1 单电机 / 协议（`B1`，提交命令时）

| 编号 | 条件 | 消息原文 | 后果 |
|---|---|---|---|
| **R01** | 命令无法编码 | `invalid command encoding` | 该台拒发 |
| **R02** | 位置 + offset 溢出 | `invalid command or position+offset overflow` | **锁该电机故障** |
| **R03** | 提交时已有锁故障 | 首次故障原因 | 拒绝提交 |
| **R04** | 反馈角度非有限 | `feedback-offset overflow` | 本轮失败 |

### 4.2 单条总线（`B2`，每轮 `cycle()` 串行轮询 3 台；**任一台失败 → 整条总线锁故障 + 逐台零指令卸载**）

| 编号 | 条件 | 判据 / 阈值 | 消息原文 |
|---|---|---|---|
| **R10** | **应答超时** | `io_timeout_us = 20 ms` 内没有该 ID 的合法帧 | `feedback timeout [id=.. waited=..us budget=..us bytesIn=.. badFrames=.. strayFrames=..]` |
| **R11** | 串口读失败 / 一个字节都没来 | — | `I/O timeout` 等端口错误 |
| **R12** | **反馈不健康** | `valid && mode==Foc(1) && err==0 && temp≤80` 任一不满足 | `unhealthy feedback (mode/error/temperature)` |
| **R13** | **命令过期** | `command_timeout_ms = 100 ms` 内未刷新心跳 | `command expired` |
| **R14** | 整机停止被请求 | 外部 stop 标志 | `whole robot stop requested` |
| **R15** | 总线未打开 | — | `bus closed` |
| **R16** | 关机事务失败 | — | `shutdown motor <id>: <error>` |

**`R10` 方括号三个统计量怎么读**：`bytesIn=0` → 没应答/链路断；`badFrames>0` → 字节回来了但 CRC 不过（**噪声/EMI**）；`strayFrames>0` → 收到别的 ID（串线）。

### 4.3 多总线协调（`B3`）

| 编号 | 条件 | 判据 / 阈值 | 消息原文 | 性质 |
|---|---|---|---|---|
| **R20** | **上层失联看门狗** | 上层 `watchdog = 80 ms` 没提交新目标 | `<bus dev>: no new target for N ms (watchdog 80 ms): unloaded` | **卸载但不锁故障**，继续提交即**自动恢复** |
| **R21** | 目标长度不符 | 12 维 | `every target vector must have length N` | 拒绝本轮（不卸载） |
| **R22** | 目标含 NaN/Inf | Safety 判定 | `target rejected by Safety: every value must be finite` | 拒绝本轮（**整份作废**） |
| **R23** | 整机停止已锁存 | — | `whole robot stop latched` | 拒绝提交 |
| **R24** | 控制器未运行 | — | `controller is not running` | 拒绝提交 |

### 4.4 硬件聚合 / 健康门（`B4`，监管线程每 5 ms + 每次下发；失败即锁存停机 + 卸载）

| 编号 | 条件 | 判据 / 阈值 | 消息原文 |
|---|---|---|---|
| **R30** | **关节反馈陈旧**（最常见） | `age ≥ motor_stale_after_ms = 100 ms` | `joint N: invalid/unhealthy/stale motor feedback: age=..ms valid=.. mode=.. (need Foc=1) err=.. temp=.. limits: age<100ms temp<=80` |
| **R31** | 关节不健康（valid/mode/err/temp） | `mode=Foc(1)`、`err=0`、`temp≤80` | 同上（括号里的值指出是哪一项） |
| **R32** | **IMU 陈旧** | `age ≥ imu.stale_after_ms = 500 ms` | `IMU invalid/stale: age=..ms received=.. fields=.. error=(none)` |
| **R33** | **IMU 同帧缺字段** | `Has(Quaternion\|AngularVelocity)` 为假（如 `fields=gyro`） | 同上，`fields=` 指出缺哪个 |
| **R34** | IMU 从未收到帧 | `received==0` | 同上 |
| **R35** | `sendCommand` 内部失败 | — | `<总线原因>` |
| **R36** | 外部 `requestStop` | 键盘关闭 / 退出 / Fault 传播 | 对应 reason 原文 |

### 4.5 策略与推理（`B5`，PPO 期间）

| 编号 | 条件 | 判据 / 阈值 | 消息原文 | 后果 |
|---|---|---|---|---|
| **R40** | 输入快照过期 | 观测 `age ≥ result_timeout_ms = 100 ms` | `inference input snapshot expired` | 作为 `result.error` 上报 |
| **R41** | 推理异常 | 模型未加载/观测≠45/非有限输入/输出非张量/形状不符/非有限输出 | `<异常原文>` / `unknown inference failure` | 同上 |
| **R42** | 结果过期 | `now−generated ≥ 100 ms` 或 `now−observed ≥ 100 ms` | `policy result expired` | **Fault** |
| **R43** | 结果超时 | 进 PPO 后 100 ms 内无有效结果 | `policy result timeout` | **Fault** |

### 4.6 FSM / 应用（`B6`）

| 编号 | 条件 | 消息原文 | 后果 |
|---|---|---|---|
| **R50** | 硬件无效/故障（聚合） | 优先 `HardwareState.error`；否则 `hardware not started` / `joint count=N` / `IMU invalid/stale: ...` / `hardware faulted` | Fault → 卸载 → 退出 2 |
| **R51** | 关节 invalid 或 `q/dq` 非有限 | `invalid motor feedback` | 同上 |
| **R52** | IMU 观测非有限 | `nonfinite IMU feedback` | 同上 |

| **R55** | 状态机内部异常 | `<异常原文>` | 同上 |

## 5. 非故障卸载（`N*`）与软拒绝（`S*`）

### 5.1 正常卸载（不是错误，但会失去支撑）

| 编号 | 触发 | 行为 |
|---|---|---|
| **N01** | `9` 趴下且到位（0.05 rad / 0.5 rad/s 稳定 0.2 s） | 进入 `Passive`，`kp/kd/tau/dq` 归零 → **卸载** |
| **N02** | 上层失联看门狗（见 `R20`） | 卸载但**不锁故障**，可自动恢复 |
| **N03** | Ctrl+C / stdin EOF / 正常退出 | 退出前卸载 |

### 5.2 软拒绝（不卸载、不退出、不改状态）

| 编号 | 触发 | 消息 |
|---|---|---|
| **S01** | 按 `1` 但 `mapping_confirmed=false` | `PPO锁定：关节映射尚未确认` |
| **S02** | 按 `1` 但还在 `Standing`（轨迹没跑完） | `尚未就绪：站立轨迹未完成，完成并稳定后请重新输入1+回车` |

| **S06** | `clamp` 返回 `Clamped`（未超限，只是贴边） | 面板 `Limit: CLAMP`，值被夹住**仍会下发**（不是错误，但说明目标贴边） |

## 6. 同一判据在两阶段的不同表现（最容易混的地方）

| 判据 | 初始化阶段（`A*`） | 运行中阶段（`B*`） |
|---|---|---|
| IMU 帧完整性（quat+gyro 同帧） | `E36` 就绪超时 → 启动失败 | `R32/R33` 陈旧/缺字段 → Fault |
| 电机反馈健康（mode/err/temp） | `E32` 首轮探测失败 → 启动失败 | `R12` 不健康 / `R30/R31` 健康门 → 锁故障/Fault |
| 轨迹超限位/超速 | `E26` 构造期 throw（退出 1） | `S05` 按键时软拒绝（**不卸载**） |
| 端口打开 | `E30` 打不开即失败 | `R11` 运行中掉线 → I/O 错误 → 锁故障 |
| 命令有效期 | 启动探测是零指令、无活动目标 → **不会触发** | `R13` `command expired` |
| 配置合法性 | 仅在初始化（`E10–E19`） | — |
| `mapping_confirmed` | 不参与 | `S01` 只影响能否进 PPO（软门禁） |
| `Safety::clamp` | 启动探测不经过 `setTargets`，不会拒绝 | `R22`/`R56` 每轮都检查 |

## 7. 超时 / 看门狗参数对照（改之前务必一起看）

| 参数 | 默认值 | 监控对象 | 超时后果 | 恢复 | 阶段 |
|---|---|---|---|---|---|
| `start_timeout_` | **5000 ms** | 启动探测首轮 | 启动失败 | 重启 | 初始化 |
| `imu_ready_timeout_ms` | **2000 ms** | 启动时首批有效 IMU 帧 | 启动失败 | 重启 | 初始化 |
| `io_timeout_us` | **20 ms** | 单台电机一次"发+收" | 整条总线锁故障 | `clearFault` | 运行中 |
| `command_timeout_ms` | **100 ms** | 每台电机的活动命令心跳 | 锁故障 `command expired` | `clearFault` | 运行中 |
| `watchdog` | **80 ms** | 上层是否还在 `setTargets` | 卸载但**不锁故障** | **自动** | 运行中 |
| `motor_stale_after_ms` | **100 ms** | 关节反馈年龄 | Fault | 重启进程 | 运行中 |
| `imu.stale_after_ms` | **500 ms** | IMU 帧年龄 | Fault | 重启进程 | 运行中 |
| `result_timeout_ms` | **100 ms** | 推理结果 / 输入快照年龄 | 结果过期/超时 → Fault | 重启进程 | 运行中 |

**相互约束**：
- `watchdog < command_timeout_ms`（构造时强制，否则 `watchdog must be shorter than command timeout, ...`）
- 每条总线 3 台**串行** → 一轮最坏 `3 × io_timeout_us`，必须明显小于 `command_timeout_ms` 和 `motor_stale_after_ms`（否则故障会从"超时"变成"命令过期/反馈陈旧"）
- 实测健康值：单台事务 ~1.9 ms、整轮 ~5.8 ms（最坏 6.4 ms）；撞到 20 ms 预算需要慢 10 倍，属"事件"而非常态

## 8. 后果分类与恢复方式

| 后果 | 涉及编号 | 是否卸载 | 恢复 |
|---|---|---|---|
| **仅拒绝本次操作** | `R21` `R22` `R23` `R24` `S01–S06` | 否 | 修正目标/按键/等待，无需重启 |
| **卸载但可自动恢复** | `R20` `N02` | 是 | 上层继续 `setTargets` |
| **锁故障（单总线/单电机）** | `R01–R16` | 是（该总线） | 库层 `clearFault()`（需所有电机反馈新鲜健康）+ 重新提交；应用层等价于**重启进程** |
| **整机 Fault** | `R30–R36` `R42` `R43` `R50–R55` | 是（整车） | 进程退出（退出码 2）→ 重新启动（会重做自动归零） |
| **正常卸载** | `N01` `N03` | 是 | 按 `0` 重新站起 |
| **初始化失败** | `E01–E38` | 否（**从未使能**） | 改参数/配置/接线后重启 |

## 10. 排障流程（从现象出发）

1. **先定阶段**（§1 四行表）。
2. **初始化错误**：按 `E*` 的编号从"参数 → 配置 → 构造 → 启动"**从前往后**查——它们必经，前一级不过就不会到后一级。
3. **运行中错误**：先看是哪一类后果（§8）：
   - 只有 `unloaded` → `R20` 上层失联（查上层循环是否卡住/CPU 抢占）→ 自动恢复。
   - `joint N: ... age=100ms` → `R30`：查总线轮询耗时（`--bus-stats`），再看 USB/电源/调度。
   - `IMU invalid/stale: fields=缺字段` → `R33`：IMU 交错输出（代码兼容问题）；`age=500` → 数据流断（硬件/链路）。
   - `feedback timeout [..]` → `R10`：看三个统计量区分"没应答 / 噪声 / 串线"。
   - `command expired` → `R13`：总线一轮被拖太久（看是否撞上 `io_timeout`）。
   - `policy result ...` → `R42/R43`：查推理耗时与 CPU 负载。
4. **现场观测手段**：
   - `./rl_real_imgo2 --log`：**一次给全**（`robot.csv` 200 Hz / `policy.csv` 50 Hz / `events.log` / `meta.json`，
     并自动启用下两条的 `--bus-stats` 与 `--trace`，trace 落到同一目录）。
   - `./rl_real_imgo2 --bus-stats`：每秒输出每总线轮询 `last/max` 耗时 + `IMU age=last/max hz valid`
     + `线程最坏值(累计): gap/body/interval`（`gap` 大=线程被抢占，`body` 大=时间花在 I/O 里）。
   - `./rl_real_imgo2 --trace /tmp/t`：**逐事务时间线**。故障时写 `/tmp/t.fault.csv`、退出时写 `/tmp/t.exit.csv`，
     每行是一次"发+收"：`t_ms,bus,id,ok,waited_us,bytes,bad,stray`。判读：
     `ok=0 bytes=0`=没字节回来；`ok=0 bytes>0 bad>0`=回了坏帧（噪声）；`ok=0 bytes>0 bad=0`=回了但不是该 ID（串线）；
     **某段时间没有任何行**=总线线程没在跑（被冻结/抢占）；`waited_us` 明显大于 `io_timeout_us`=事务外阻塞。
   - `./go_monitor -t 20`：卸力状态下看累计超时 `TO=`、`坏帧=`、`最坏单轮=`（`-t` 默认 40 ms，比对部署要显式 `-t 20`）。
   - `dmesg -T | tail -50`：USB/串口层面事件（`reset`、`over-current`、`ch343`、`cdc_acm`）。

## 11. 一句话总结

**初始化错误（`E*`）只会在"从未出力"的窗口出现：看到 `deployment error:` / `start failed:` / 退出码 1 就是它，改完重启即可。
运行中错误（`R*`）一定伴随"先卸载再报错"：看到 `Fault:` / 退出码 2 就是它，四条主线——总线故障（`R10–R16`）、上层失联（`R20`）、健康门（`R30–R36`：关节 100 ms / IMU 500 ms / 温度 80℃）、策略回路（`R40–R43`）。
另外两类常被误当成故障：正常卸载（`N*`）和软拒绝（`S*`），它们既不卸力也不退出，别误判。**
